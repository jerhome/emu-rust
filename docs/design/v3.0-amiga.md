# Version 3.0 — Amiga, import de BIOS, dossier des ROMs : contrat et découpage

Décisions : **ADR 0017** (statut proposé — décisions utilisateur du 2026-11-21 intégrées ; précise 0005, 0013, 0014,
0015). Étude préalable : `docs/essais-puae.md`. Base réutilisée : `docs/design/v2.0-atari-st.md` (infrastructure
« ordinateur »). Ce document ne donne que le **delta** par rapport à la 2.0. Les signatures ci-dessous seront
**posées dans le code par l'`architecte` au lancement de la 3.0**, une fois la 2.0 intégrée (le code fera alors
foi) ; aucune n'est posée aujourd'hui.

Révision du 2026-11-21 (revue croisée des conceptions 3.0 à 6.0) : la 3.0 porte désormais les **règles communes**
dont dépendent les versions suivantes, écrites une seule fois au **§3.5** : ordre d'évaluation des médias,
extensions partagées et `folder_extensions`, `game_saves` / `reset_core_game_files`, couche « défauts calculés »,
contrôle de firmware unique avant lancement, format de `firmware.toml`, notices. Les designs 4.0, 5.0 et 6.0 y
renvoient et n'ajoutent que des données.

## 2. Fonctionnement

### 2.1 Lancement d'un jeu Amiga depuis la bibliothèque

```text
Game (amiga, media = [d1, d2]) ─ choose_core ─► puae
  modèle = options du jeu > [core_options.puae] > resolve_amiga_model(chemin, Disquette|DisqueDur, puae_model_fd/hd)
  check_required(system, required_firmware(puae, "Commodore - Amiga"), variante = modèle) ─► FirmwareCheck ─┐   (§3.5.5)
     Ok            ─► puae_kickstart = "auto"
     CoreFallback  ─► défaut calculé puae_kickstart = "aros" (repli déclaré) ; 1re fois pour ce jeu : dialogue
                      « Pas de Kickstart A500 : AROS intégré (compatibilité limitée) [Importer un Kickstart…] [Continuer] »
     WrongHash     ─► dialogue 1.0 : [Lancer quand même] [Utiliser AROS] [Importer…]
options : défauts core < cores.toml (puae_mapper_select = "---", puae_mapper_mouse_toggle = "---", …)
          < défauts calculés (puae_kickstart selon le contrôle ; jamais écrits) < config < jeu          (§3.5.4)
Emulator::load_content(core, ContentSpec::Media { set, rules: MediaRules { WorkingCopy, media_direct = [ipf, lha] } })
   ─► prepare_media (ordre §3.5.1) : d1, d2 copiés dans saves/puae/<jeu>.disks/ ; zip de disquettes extrait ; <jeu>.m3u généré
   ─► puae MultiDrive : d1 → DF0, d2 → DF1 ; menu Disquettes / Hôte + D agissent sur DF0
mode d'entrée initial = Clavier (souris capturée au premier clic) ; OSD « Ctrl droit : menu · Ctrl droit + J : joystick »
```

Entrée « Workbench / AROS » de la bibliothèque (système `amiga`) : `ContentSpec::NoGame` (A500 + Kickstart si présent,
sinon écran AROS « Waiting for bootable media »), mode *Clavier*.

### 2.2 Import d'un BIOS

```text
[Importer un BIOS…] ─► pick_file (rfd natif | navigateur egui) ─► identify_firmware(src, &catalogue)
   Known { targets: [kick34005.A500] } ─► pour chaque cible : target_state
        Absent | FreeInstalled ─► import_firmware(…, Refuse) ; Same ─► « déjà installé »
        Other { md5 }          ─► « Remplacer ? l'ancien deviendra kick34005.A500.user-<unix> » ─► BackupAndReplace
   AmigaForeverEncrypted       ─► import non vérifié sous le nom Amiga Forever + « copiez aussi rom.key »
   Unknown { md5 }             ─► refus expliqué ; [Importer quand même…] ─► choix du nom parmi expected_names() ─► verified = false
```

### 2.3 Ouvrir le dossier des ROMs

```text
[Ouvrir le dossier des ROMs] ─► roots = [<data>/roms] + library.roots (créé s'il manque)
   1 dossier : open_folder(dossier) ; plusieurs : menu
   open_folder : conteneur (EMU_RUST_CONTAINER=1) ─► ShowPath { /data/roms, EMU_HOST_ROMS_DIR? }
                 sinon opener::open(dossier) ─► Ok : Opened ; Err : ShowPath (chemin + [Copier])
```

### 3.5 Règles communes posées en 3.0 (réutilisées telles quelles par les 4.0, 5.0, 6.0 et 7.0)

Écrites ici **une seule fois** ; les ADR 0018, 0019, 0020 et leurs designs y renvoient au lieu de les redéfinir.

#### 3.5.1 Ordre d'évaluation d'une source de média (`prepare_media`)

Pour chaque source d'un `MediaSet` (fichier de l'utilisateur, entrée d'un `.m3u`), dans cet ordre :

1. **Extension directe** : l'extension est dans `media_direct` du core ⇒ transmise **en place** (chemin absolu),
   jamais copiée, jamais extraite — **même si c'est un zip** (dosbox_pure : `zip`, `dosz`) ;
2. **Zip inspecté** : sinon, si c'est un `.zip` — **que le core déclare ou non l'extension `zip`, quel que soit
   `block_extract`** — son répertoire central est lu sans extraction ; s'il contient au moins une image d'une
   extension acceptée par le core (hors `zip` / `7z`), le frontend l'**extrait** (limites 2.0) dans le dossier de
   travail (`working_copy`) ou dans un dossier temporaire privé (`direct`) ;
3. **Politique du core** : sinon, `media` s'applique — un fichier non zip est copié (`working_copy`) ou référencé en
   place (`direct`) ; un zip sans image acceptée est transmis tel quel si le core déclare `zip` (puae : il le traite
   comme un dossier, écritures perdues, documenté), refusé sinon (`InvalidMediaSet`, comportement 2.0).

Écart avec le code livré : `add_source` (`crates/emu-runtime/src/media.rs`) n'extrait un zip que si le core ne
déclare **pas** `zip` ; la tâche R3 remplace ce test par l'ordre ci-dessus. Comportement inchangé pour hatari (qui ne
déclare pas `zip`) : test de non-régression obligatoire. Un `MediaSet` d'une seule image directe équivaut à
`ContentSpec::File`.

Emplacement du `.m3u` généré (code 2.0, inchangé) : `<saves>/<core_id>/<jeu>.disks/<jeu>.m3u` en `working_copy`
(noms relatifs) ; **dossier temporaire privé** en `direct` (chemins absolus), jamais `<saves>/<core_id>/`.

Lignes `#` d'un `.m3u` de l'utilisateur relu pour produire le `.m3u` de travail : **liste blanche**, pas de
recopie aveugle. `#SAVEDISK:` et `#LABEL:` sont conservés à leur place ; le suffixe `|libellé` d'une entrée aussi ;
`#COMMAND:` n'est conservé que pour un core `m3u_launch = "command"` (5.0, cap32 : texte tapé dans la machine
émulée) et **jamais** pour `m3u_launch = "program"` (VICE : ce sont des arguments de ligne de commande du core) ;
toute autre ligne `#` est un commentaire, non recopié.

#### 3.5.2 Extensions partagées, `folder_extensions`, système d'un `.m3u`

`systems.toml` gagne `folder_extensions` (`Vec<String>`, défaut vide, sous-ensemble de `extensions`) : une extension
qui y figure n'est retenue pour ce système que **sous un dossier dont un composant vaut l'`id` du système** (casse
ignorée, règle des dossiers de la 1.0). Attribution d'un fichier d'extension E (hors `.m3u`) :

1. **Dossier** : sous un dossier portant l'`id` d'un système qui accepte E ⇒ ce système (une extension restreinte
   l'emporte donc sous son dossier) ;
2. sinon, parmi les systèmes qui acceptent E **sans restriction** : un seul ⇒ ce système (règle 1.0) ;
3. plusieurs (extension **partagée**, ex. `.ipf` : `atarist` et `amiga`) ⇒ **DAT** : le fichier est hashé comme
   d'habitude et cherché dans les DAT de ces systèmes ; trouvé dans un seul ⇒ ce système ;
4. sinon **non classé** : compté dans `ScanReport::unclassified`, listé par l'UI avec le conseil « rangez ce fichier
   dans `roms/<id>/` », jamais attribué par défaut au premier système du catalogue.

Une version ultérieure peut ajouter une **sonde de contenu** évaluée juste avant « non classé », y compris pour une
extension restreinte (6.0 : en-tête `SEGADISCSYSTEM` d'un CD hors dossier) ; elle ne change pas l'ordre ci-dessus.

`.m3u` (accepté par tous les systèmes à médias) : **le système d'un `.m3u` est celui de ses entrées** — chaque entrée
est attribuée par la règle ci-dessus ; toutes les entrées classées doivent donner le même système, sinon (entrées
illisibles, absentes ou de systèmes différents) le `.m3u` suit la règle du dossier, puis est non classé.

Effet sur la 2.0 : un `.ipf` hors de `roms/atarist/` et absent des DAT n'est plus rangé d'office en Atari ST dès que
le système `amiga` existe (test B3 ; une ligne déjà en base est réévaluée au scan suivant). Usages suivants, sans
nouveau code : 4.0 (`iso`, `cue`, `chd`, `img`… sous `dos/`), 5.0 (`sna`, `voc`, `tap` sous `cpc/`), 6.0 (CD).

#### 3.5.3 Fichiers de sauvegarde écrits par le core : `game_saves` et `reset_core_game_files`

`cores.toml` : `game_saves = ["{game}.save*.adf"]` — motifs de **noms de fichier** (jamais de séparateur), `{game}`
= nom de contenu transmis au core, au plus un `*`. `reset_core_game_files(saves_core_dir, content_name, patterns)`
ne regarde que `saves_core_dir` (non récursif), supprime les fichiers correspondants et les renvoie. « Réinitialiser
les disquettes / les sauvegardes du jeu » = `reset_working_copies` + `reset_core_game_files`. Données ajoutées par
les versions suivantes seulement : dosbox_pure (`{game}.pure.zip`), cap32 (`*.sav` dans le dossier du jeu), VICE
(`{game}.save*.d64`), genesis_plus_gx (`{game}.brm`).

#### 3.5.4 Couche « défauts calculés » des options de core

Ordre unique, pour tous les cores : **défauts du core < `cores.toml` (`options`) < défauts calculés < `config.toml`
(`[core_options.<core>]`) < options du jeu**. Les défauts calculés sont produits par une fonction pure de l'UI
(`computed_options`, §4) à partir de données de `cores.toml` ; ils ne sont **jamais écrits** (ni dans la config, ni
dans les options du jeu) et un réglage explicite de l'utilisateur l'emporte toujours. Sources : 3.0 — repli de
firmware (`required_firmware.fallback` : `puae_kickstart = "aros"` quand le Kickstart du modèle manque) ; 4.0 —
`layout_option` (disposition clavier d'après la langue du système) ; 5.0 — `options_by_extension`.
`effective_core_options` (2.0) gagne le paramètre `computed` entre `frontend` et `global`.

#### 3.5.5 Contrôle de firmware unique avant lancement

Un seul contrôle, posé par X0, appelé par l'UI avant tout lancement depuis la bibliothèque et par `--check-bios` :
`check_required(system_dir, required_firmware(core, système), variante, known)`.

- `required_firmware` est une table de données par (core, système) : `variant` dit d'où vient la variante
  (`"model"` : option de modèle résolue, Amiga ; `"region"` : région du jeu, Mega CD en 6.0, PlayStation en 7.0 avec
  `scph5500` / `5501` / `5502`), `files` associe variante → nom de fichier, `default` sert quand la variante est
  inconnue, `fallback` (optionnel) nomme l'option du core qui active une ROM intégrée.
- Résultat `FirmwareCheck { wanted, state, others_present }` avec le **`FirmwareState` existant** (aucune seconde
  énumération d'état) : `Ok` / `Free` / `Unverified` ⇒ lancement ; `Missing` **avec** `fallback` ⇒ `CoreFallback`
  (lancement, avertissement une fois par jeu) ; `Missing` sans repli ou `WrongHash` ⇒ dialogue (« Importer un
  BIOS… », « Lancer quand même », « Annuler » ; `others_present` permet « bios_CD_E.bin présent, mais ce jeu est
  USA »). Pas de table `required_firmware` : `Builtin` si le core a `builtin_firmware`, sinon contrôle `.info` de la
  1.0 inchangé (avertissement non bloquant).
- Les versions suivantes n'ajoutent que des **données** (`cores.toml`) et, côté UI, la source de la variante
  (5.0 : `builtin_firmware` de cap32 / VICE ; 6.0 : tables par région de genesis_plus_gx et picodrive).

#### 3.5.6 `firmware.toml` : format et attribution

Le fichier livré ne contient que des md5 (`"nom" = ["md5", …]`). Décision : ce format reste valide ; une entrée peut
aussi être une table `{ md5 = "…", size = 262144 }` (`size` facultative : rejet rapide à l'import, affichage). Le
**md5 reste la seule donnée de vérification** ; aucun sha1 n'est stocké (l'import en calcule un pour l'affichage
seulement). **Source unique : `libretro-database/dat/System.dat`** (CC-BY-SA-4.0, attribution de l'en-tête et de
`THIRD-PARTY-DATA.txt`, à mettre à jour quand des sections s'ajoutent). Les md5 qui n'existent que dans un `.info` ou
un README de core ne sont **pas recopiés** dans `firmware.toml` : le catalogue d'import les lit dans les `.info`
des cores installés, à l'exécution (aucune question de licence sur nos données).

#### 3.5.7 Notices et attributions

`packaging/THIRD-PARTY-DATA.txt` ne décrit que ce qui est **embarqué** dans le binaire ou les archives (données
dérivées de `System.dat`). Tout ce qui n'est pas embarqué — ROM intégrées aux cores (AROS, Amstrad, Commodore), DAT
téléchargés à l'exécution (No-Intro, TOSEC, Redump, clean-cpc-db, `DOS.dat`), licences des cores, SoundFont — est
cité dans le **README de release** et affiché dans l'**écran Cores** (notice `builtin_firmware`, licence du `.info`).

## 8. Risques

| Risque | Atténuation |
|---|---|
| Beaucoup de jeux ne marchent pas sous AROS | Dialogue explicite, import guidé du Kickstart, AROS seulement en repli |
| `rfd` échoue silencieusement sous Linux sans portail ni zenity (renvoie `None` comme une annulation) | Détection préalable (`picker_backend`) + lien « navigateur intégré » toujours présent dans le dialogue |
| `opener` sous Docker sur WSL2 détecte « WSL » (noyau Microsoft) et tenterait `explorer.exe` | Docker détecté par `EMU_RUST_CONTAINER` **avant** tout appel à `opener` |
| Alt + F4, Alt + Tab, Alt + Espace interceptés par Windows (Alt gauche = Amiga gauche) | Signalé dans le guide d'essai ; aucune liaison de la touche Windows ; clavier virtuel pour ces rares combinaisons ; `[computer.remap.amiga]` |
| Migration de schéma v3 → v4 sur la base de l'utilisateur | Test sur une base 2.0 réelle ; en cas d'échec : quarantaine 1.0 (`library.sqlite.corrupt-<unix>`), seuls favoris et historique perdus |
| `.ipf` ou `.m3u` non classés après la mise à jour | Compteur et liste dans le rapport de scan, conseil de dossier |
| Géométrie variable (lores / hires / entrelacé) | Déjà géré (`av_info_changed`) ; vérifié par Q5 sur le bureau AROS 720×574 |
| Nightly puae change l'AROS intégré ou les options | Version précédente conservée (ADR 0013), empreintes ré-enregistrées, puae2021 en alternative |
