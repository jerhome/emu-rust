# Version 7.2 — Sega CD 32X : contrat et découpage

Décisions : **ADR 0024** (accepté le 2026-11-21, amendé après revue indépendante). Étude :
`docs/essais-sega-cd-32x.md`. Branche `wip-7.2`, créée depuis `wip-7.1` **une fois la 7.1 livrée**. Petit chantier :
ce document ne donne que le **delta 7.1 → 7.2**. Base réutilisée sans la redéfinir : 6.0 (système `megacd`,
`disc_info`, Redump, `Game::region`, contrôle de firmware par région, `plan_disc_launch`, `mkcd.py`), 3.0 (dialogue
d'installation). `emu-libretro`, `emu-runtime`, `emu-app` : **aucun changement**. Schéma : **v6, inchangé**.

## 1. Fonctionnement

```text
Game (megacd) ─ cd32x_mark ─► No ───────────► choose_core            = 7.1 (genesis_plus_gx ou préférence)
                            └► ByName|Manual ► choose_cd32x_core ─► picodrive installé ─► contrôle du BIOS Mega CD (6.0) ─► jeu
                                                                 └► Install(picodrive) ─► dialogue d'installation
```

Marque = étiquette du titre / du fichier / d'un média (dérivée, `emu-library`) **ou** nom du fichier présent dans
`[library] cd32x` de `config.toml` (manuelle, `emu-ui`). Pastille « 32X » ; clic droit « Ce jeu est un CD 32X » ;
invitation dans la ligne d'aide. Cas de l'utilisateur : Night Trap 32X en deux `.chd` (jamais lus) ⇒ nom ou
marquage manuel (ADR 0024 §1, §6).

## 2. Contrat

Il n'y a **pas de tâche de contrat** : chaque agent de crate pose ses signatures **avec leur corps** (un `todo!()`
atteignable casserait les tests du workspace). `choose_core` n'est pas modifié.

### 2.1 `emu-library` (SB1) — `src/disc.rs`, `src/db.rs`, `src/scan.rs`, réexports dans `src/lib.rs`

```rust
/// `true` when `name` (a title or a file stem) carries a parenthesised Sega CD 32X tag: `Sega CD 32X`,
/// `Mega-CD 32X`, `Mega CD 32X`, `32X CD`, `CD 32X` or `32X` (ASCII case-insensitive, `-` read as a space,
/// inner spaces collapsed). Pure. Only meaningful for a game of system `megacd` (ADR 0024 §1).
pub fn cd32x_tag(name: &str) -> bool;

impl Game {
    /// Sega CD 32X game recognised by its names (ADR 0024 §1): system `megacd` and [`cd32x_tag`] on `title`,
    /// on the file stem of `path` or on the stem of any of `media`. No I/O.
    pub fn cd32x_by_name(&self) -> bool;
}
```

`scan.rs` : `crc_limit` applique au Mega CD la borne de 800 Mio déjà utilisée pour la 3DO (même condition : borne
par défaut non réduite par l'appelant). Rien d'autre ne change dans le scan, le schéma ni `systems.toml`.

### 2.2 `emu-assets` (SA1) — `src/cores/select.rs`, `src/cores/mod.rs`, `data/cores.toml`

```rust
impl CorePreferences {
    /// Cores imposed on the Sega CD 32X games of `system` (database name): `cd32x_cores` of its `cores.toml`
    /// entry; empty when the system has none. `with_overrides` never changes this list.
    pub fn cd32x_cores(&self, system: &str) -> &[CoreId];
}

/// Core of a Sega CD 32X game of `system` (ADR 0024 §3): first of [`CorePreferences::cd32x_cores`] that is
/// installed, else `Install(first)`; never another core. `None` when the system has no such list (the caller
/// then uses [`choose_core`]).
pub fn choose_cd32x_core(system: &str, installed: &[CoreId], prefs: &CorePreferences) -> Option<CoreChoice>;
```

Donnée : `cd32x_cores = ["picodrive"]` dans `[systems."Sega - Mega-CD - Sega CD"]`. Un id invalide est une erreur
de `parse` (test unitaire de `BUILTIN`).

### 2.3 `emu-ui` (SU1) — interne au crate (`pub(crate)` sauf `LibraryConfig`)

```rust
// config_library.rs
pub struct LibraryConfig {
    // …
    /// File names (with extension) of `megacd` games marked « CD 32X » by hand (ADR 0024 §2); compared in
    /// Unicode lower case on both sides.
    #[serde(skip_serializing_if = "Vec::is_empty")]
    pub cd32x: Vec<String>,
}

// library/cd32x.rs (nouveau, logique pure)
pub(crate) enum Cd32xMark { No, ByName, Manual }
/// `No` for any game outside `megacd`. `ByName` wins over `Manual`.
pub(crate) fn cd32x_mark(game: &Game, marked: &[String]) -> Cd32xMark;
/// Key of the manual list: `str::to_lowercase` of the file name of `game.path`; `None` without a UTF-8 name.
pub(crate) fn mark_key(game: &Game) -> Option<String>;
/// Adds or removes the key (entries equal after lower-casing are one entry); `true` when the list changed.
pub(crate) fn set_manual_mark(marked: &mut Vec<String>, game: &Game, on: bool) -> bool;
/// `megacd` games of `games` sharing the key of `game` (itself included): shown when > 1.
pub(crate) fn same_key_count(games: &[Game], game: &Game) -> usize;
/// The help line invites to mark: `megacd`, mark `No`, identification `Unknown` or `Name`.
pub(crate) fn invites_marking(game: &Game, marked: &[String]) -> bool;

// cores_ui/launch.rs : paramètre `cd32x` ajouté ; `true` ⇒ `choose_cd32x_core`, sinon `choose_core`
pub(crate) fn plan_launch(manager: &CoreManager, prefs: &CorePreferences, system: Option<&str>,
                          cd32x: bool, extension: Option<&str>) -> LaunchCheck;
```

Intégration (`library/{mod,home,text}.rs`) :

- `LaunchArgs` porte la marque ; la relance après installation de picodrive repasse par `plan_launch` avec elle.
- Pastille « 32X ». Clic droit sur la vignette + une touche : « Ce jeu est un CD 32X » / « Ce n'est pas un CD
  32X », seulement pour un jeu `megacd` non marqué par son nom.
- Message après marquage (ADR 0024 §4) : picodrive, sauvegardes `.brm` non reprises, nombre de jeux de même nom de
  fichier, autres disques à marquer.
- Écriture : `save_config` doit rendre son résultat ; en cas d'échec la marque est annulée en mémoire et l'échec
  affiché.
- Invitation : texte ajouté à la ligne d'aide quand `invites_marking` est vrai pour le jeu sélectionné.
- `text::install_question_cd32x(core, game)`. Le dialogue de BIOS manquant est celui de la 6.0, inchangé.

## 3. Données de test (aucune donnée commerciale)

- **Disque** : `tests/tools/mkcd.py megacd --name "Fake Trap (USA) (Sega CD 32X)"` (existant, sans modification de
  la sous-commande).
- **BIOS synthétique** : nouvelle sous-commande `mkcd.py bios-stub SORTIE` (131 072 octets : vecteurs 68000 +
  `13FC 0001 00A1 5101 60FE`, le reste à zéro — l'essai n° 2 de l'étude), couverte par `test_mkcd.py`. Le test
  l'écrit dans son **dossier système temporaire** sous le nom `bios_CD_U.bin` : jamais commité, jamais distribué,
  jamais dans `system/` d'un utilisateur.
- **DAT réduit** : quelques entrées Redump fictives écrites par les tests, comme en 6.0.
- Core réel : `tests/cores/picodrive_libretro.so` (`scripts/fetch-test-assets.sh --with-6.0`), **absent par
  défaut** : le test `#[ignore]` rend la main avec un message quand le fichier manque.

## 4. Tests et critères de fin

Sans core (tests ordinaires) :

1. **SB1** `cd32x_tag` : les six écritures, casse, tiret ; refus de `32X` hors parenthèses, de `[32X]`, de
   `(32X Edition)`, de `(Sega CD)`. `cd32x_by_name` : titre, fichier, un média ; faux hors `megacd`.
2. **SB1** `crc_limit` : 800 Mio pour `megacd` avec la borne par défaut, borne réduite respectée, PlayStation
   toujours `None`. `bin_kind` : en-tête `SEGADISCSYSTEM` + `SEGA 32X` à `0x100`, écrit en octets dans le test ⇒
   `SegaCdTrack`.
3. **SA1** `choose_cd32x_core` : picodrive installé ; absent ⇒ `Install(picodrive)` même si genesis_plus_gx est
   installé ; préférence utilisateur genesis_plus_gx sans effet ; système sans liste ⇒ `None`.
4. **SQ2** scan d'un dossier généré : `.cue` étiqueté, `.chd` étiqueté (fichier factice), `.cue` sans étiquette
   identifié par le DAT réduit, groupe `(Disc 1)` / `(Disc 2)` de `.chd` (un seul jeu), `.m3u` dont un seul disque
   est étiqueté ⇒ marque ; CD Mega CD ordinaire et cartouche `.32x` ⇒ pas de marque.
5. **SU1 / SQ2** interface — **c'est ce test qui prouve le routage** : jeu marqué ⇒ dialogue d'installation
   (picodrive absent) ou contrôle du BIOS Mega CD sur picodrive ; jeu non marqué inchangé. Marque manuelle, un test
   par point : ajout / retrait et relecture de `config.toml` ; clé conservée après déplacement du fichier ;
   entrée écrite à la main en majuscules ou avec des lettres accentuées reconnue ; collision de clé comptée et
   dite ; message mentionnant picodrive et les `.brm` ; échec d'écriture ⇒ marque annulée et erreur affichée ;
   `invites_marking` (`.chd` non marqué : oui ; marqué, identifié par CRC, autre système : non). Capture Xvfb de la
   pastille et de la ligne d'aide.

Avec le vrai core : **un seul** test `#[ignore]`, `#![cfg(unix)]` (`emu-runtime/tests/`) — disque étiqueté +
`bios-stub` ⇒ jeu chargé par picodrive, journal du core contenant `32X startup`. Il prouve l'allumage de la 32X par
picodrive dans le pipeline d'emu-rust, pas le routage ni un jeu.

Terminé quand : définition générale de `CLAUDE.md` (fmt, clippy `-D warnings` dont
`--target x86_64-pc-windows-gnu`, tests) ; les tests ci-dessus passent ; un `config.toml` et une base v6 de la 7.1
sont repris sans changement et restent lisibles par la 7.1 après une session 7.2 ; aucun fichier de l'utilisateur
modifié ; `docs/guide-essai-7.2.md` écrit. Ensuite : CI `success` lue, pré-release `v7.2.0-rc.1`, essai.

**Contenu du guide d'essai** (SU1) : ranger les fichiers sous `roms/megacd/` (un `.chd` ailleurs n'est ni classé ni
marquable) ; pour deux `.chd`, les nommer `… (Disc 1)` / `… (Disc 2)` pour n'avoir qu'un jeu, sinon marquer chaque
disque ; clic droit « Ce jeu est un CD 32X » quand la pastille manque (noms sans étiquette, `[32X]` de TOSEC) ;
**rescan complet** pour un `.cue` déjà présent avant la 7.2 ; titres non regroupés : Slam City, Supreme Warrior
(USA), Fahrenheit (marquer le disque 1, ou `.m3u`) ; BIOS de la région du disque (un `.chd` Europe avec le seul
BIOS USA donne « Missing BIOS », comme en 6.0) ; à essayer : vidéo, son, changement de disque, sauvegarde, état.
À relever : nom exact des fichiers, rapport de scan.

## 6. Interaction avec la 7.1 et points à re-valider

- Rangement (ADR 0023) : rien à changer ; un CD 32X est une unité `megacd`. La clé de la marque manuelle repose sur
  « le rangement ne renomme jamais » (ADR 0024, « Interaction avec la 7.1 »).
- À re-valider contre le code de `wip-7.2` par chaque agent : signature de `plan_launch` et de `LaunchArgs` après la
  7.1 ; `save_config` (aujourd'hui sans valeur de retour) ; existence d'une ligne d'aide affichée en permanence
  dans la bibliothèque et gestion du clic droit sur une vignette ; capture du journal du core dans un test
  `emu-runtime` (à défaut : lancer le binaire comme dans l'étude et lire sa sortie).
- Hors périmètre : glisser-déposer (7.2.1) ; sonde d'en-tête « SEGA 32X » ; numéro de série ; regroupement
  automatique de Fahrenheit, Slam City, Supreme Warrior ; système `megacd32x` ; options picodrive mises en avant.
