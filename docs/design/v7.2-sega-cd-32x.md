# Version 7.2 — Sega CD 32X : contrat et découpage

Décisions : **ADR 0024** (proposé, 2026-11-21). Étude : `docs/essais-sega-cd-32x.md`. Branche `wip-7.2`, créée
depuis `wip-7.1` **une fois la 7.1 livrée**. Petit chantier : ce document ne donne que le **delta 7.1 → 7.2**.
Base réutilisée sans la redéfinir : 6.0 (système `megacd`, `disc_info`, Redump, `Game::region`, contrôle de
firmware par région, `plan_disc_launch`, `mkcd.py`), 3.0 (dialogue d'installation, « Core utilisé »).
`emu-libretro`, `emu-runtime`, `emu-app` : **aucun changement**. Schéma de la bibliothèque : **v6, inchangé**.

## 1. Fonctionnement

```text
Game (megacd) ─ cd32x_mark ─► No ───────────► choose_core_tagged(tag = None)     = 7.1 (genesis_plus_gx, préférence)
                            └► ByName|Manual ► choose_core_tagged(tag = "cd32x") ─► picodrive installé ─► contrôle du BIOS
                                                                                 │                        Mega CD (6.0) ─► jeu
                                                                                 └► Install(picodrive) ─► dialogue d'installation
```

Marque = étiquette du titre / du fichier / d'un média (dérivée, `emu-library`) **ou** nom du fichier présent dans
`[library] cd32x` de `config.toml` (manuelle, `emu-ui`). Pastille « 32X » sur la vignette.

## 2. Contrat (signatures posées par SX0, corps `todo!()` sauf mention)

### 2.1 `emu-library` — `src/disc.rs`, `src/db.rs`, réexports dans `src/lib.rs`

```rust
/// `true` when `name` (a title or a file stem) carries a parenthesised Sega CD 32X tag: `Sega CD 32X`,
/// `Mega-CD 32X`, `Mega CD 32X`, `32X CD`, `CD 32X` or `32X` (ASCII case-insensitive, `-` read as a space,
/// inner spaces collapsed). Pure. Only meaningful for a game of system `megacd` (ADR 0024 §1).
pub fn cd32x_tag(name: &str) -> bool;

impl Game {
    /// Sega CD 32X game recognised by its names (ADR 0024 §1): system `megacd` and [`cd32x_tag`] on `title`,
    /// on the file stem of `path` or on the stem of any of `media`. No I/O.
    pub fn cd32x_by_name(&self) -> bool;
}
```

Aucun changement du scan, du schéma ni de `systems.toml`.

### 2.2 `emu-assets` — `src/cores/select.rs`, `src/cores/mod.rs`, `data/cores.toml`

```rust
/// Game tag of a Sega CD 32X disc (`[systems."…".tags.cd32x]`, ADR 0024 §3).
pub const GAME_TAG_CD32X: &str = "cd32x";

impl CorePreferences {
    /// Cores imposed on the games of `system` (database name) that carry `tag`; empty when there is no rule.
    /// `with_overrides` never changes this list.
    pub fn for_tag(&self, system: &str, tag: &str) -> &[CoreId];
}

/// [`choose_core`] for a tagged game: when `system` has a rule for `tag`, only its cores are candidates (first
/// installed, else `Install(first)`), with no fallback to the system list nor to the extension. `tag == None`
/// or no rule: exactly [`choose_core`].
pub fn choose_core_tagged(
    system: Option<&str>,
    tag: Option<&str>,
    extension: Option<&str>,
    installed: &[CoreId],
    infos: &BTreeMap<CoreId, CoreInfo>,
    prefs: &CorePreferences,
) -> CoreChoice;
```

`choose_core` garde sa signature (délègue avec `tag = None`). Données :

```toml
[systems."Sega - Mega-CD - Sega CD".tags.cd32x]
cores = ["picodrive"]

[cores.picodrive.featured_options]
"Sega - Mega-CD - Sega CD" = ["picodrive_region", "picodrive_drc", "picodrive_ramcart", "picodrive_aspect"]
```

Un id de core invalide ou une liste vide dans `tags` est une erreur de `parse` (test unitaire de `BUILTIN`).

### 2.3 `emu-ui` — interne au crate (`pub(crate)` sauf `LibraryConfig`)

```rust
// config_library.rs
pub struct LibraryConfig {
    // …
    /// File names (with extension, lower case) of `megacd` games marked « CD 32X » by hand (ADR 0024 §2).
    #[serde(skip_serializing_if = "Vec::is_empty")]
    pub cd32x: Vec<String>,
}

// library/cd32x.rs (nouveau, logique pure)
pub(crate) enum Cd32xMark { No, ByName, Manual }
/// `No` for any game outside `megacd`. `ByName` wins over `Manual`.
pub(crate) fn cd32x_mark(game: &Game, marked: &[String]) -> Cd32xMark;
/// Key of the manual list: lower-cased file name of `game.path`; `None` without a UTF-8 file name.
pub(crate) fn mark_key(game: &Game) -> Option<String>;
/// Adds or removes the key; `true` when the list changed (the caller then saves `config.toml`).
pub(crate) fn set_manual_mark(marked: &mut Vec<String>, game: &Game, on: bool) -> bool;

// cores_ui/launch.rs : paramètre `tag` ajouté, transmis à `choose_core_tagged`
pub(crate) fn plan_launch(manager: &CoreManager, prefs: &CorePreferences, system: Option<&str>,
                          tag: Option<&str>, extension: Option<&str>) -> LaunchCheck;
```

Intégration (`library/mod.rs`, `home.rs`, `text.rs`, `cores_ui/`) : `LaunchArgs` porte la marque ; pastille « 32X » ;
action « Ce jeu est un CD 32X » (ADR 0024 §4) ; `text::install_question_cd32x(core, game)` ; ligne « Les CD 32X
utilisent toujours picodrive » sous le Mega CD dans « Core utilisé ». Le dialogue de BIOS manquant est celui de la
6.0, sans changement. Relancer après installation de picodrive repasse par le même `plan_launch` (marque conservée).

## 3. Données de test (aucune donnée commerciale)

- **Disque** : `tests/tools/mkcd.py megacd` (existant) avec `--name "Fake Trap (USA) (Sega CD 32X)"`. Ajouts SQ1 :
  option `--console TEXTE` (champ console à `0x100`, défaut inchangé `SEGA MEGA DRIVE`) pour le test « reste
  `megacd` » ; sous-commande `bios-stub SORTIE [--no-aden]` : 131 072 octets, vecteurs 68000 + `13FC 0001 00A1 5101
  60FE` (écrit ADEN puis boucle ; `--no-aden` : boucle seule), le reste à zéro — c'est le fichier des essais n° 2 et

- **BIOS synthétique** : écrit par le test dans son **dossier système temporaire** sous le nom `bios_CD_U.bin`.
  Jamais commité, jamais distribué, jamais dans `system/` d'un utilisateur ; son md5 est inconnu d'emu-rust (le
  contrôle de firmware le signalerait : le test de fumée passe par le runtime, pas par ce contrôle).
- **DAT réduit** : quelques entrées Redump fictives écrites par les tests (une étiquetée, taille + CRC de la piste
  générée), comme en 6.0.
- Core réel : `tests/cores/picodrive_libretro.so` (déjà récupéré par `fetch-test-assets.sh --with-6.0`).

## 4. Tests et critères de fin

Sans core (tests ordinaires) :

1. `cd32x_tag` : les six écritures, casse, tiret ; refus de `32X` hors parenthèses, de `(32X Edition)`, de `(Sega CD)`.
2. Scan d'un dossier généré : `.cue` étiqueté, `.chd` étiqueté (fichier factice), `.cue` sans étiquette identifié
   par le DAT réduit (titre DAT étiqueté), groupe `(Disc 1)` / `(Disc 2)`, `.m3u` dont un seul disque est étiqueté
   ⇒ `cd32x_by_name` vrai ; CD Mega CD ordinaire et cartouche `.32x` ⇒ faux ; disque généré avec
   `--console "SEGA 32X"` ⇒ système `megacd`.
3. `choose_core_tagged` : picodrive installé ; picodrive absent ⇒ `Install(picodrive)` même si genesis_plus_gx est
   installé ; préférence utilisateur genesis_plus_gx ignorée pour la marque ; sans marque = `choose_core`.
4. UI : marque manuelle ajoutée / retirée, `config.toml` relu, clé conservée après déplacement du fichier ;
   `ByName` prime ; lancement d'un jeu marqué ⇒ dialogue d'installation (picodrive absent) ou contrôle du BIOS
   Mega CD sur picodrive (BIOS absent ⇒ dialogue 6.0) ; jeu non marqué inchangé. Capture Xvfb de la pastille.

Avec le vrai core (`#[ignore]`, `#![cfg(unix)]`) : disque étiqueté + `bios-stub` ⇒ jeu chargé par picodrive,
journal du core contenant `32X startup` ; avec `--no-aden` ⇒ pas de `32X startup` ; sans BIOS ⇒ refus `Missing BIOS`
et sortie propre.

Terminé quand : définition générale de `CLAUDE.md` (fmt, clippy `-D warnings` dont
`--target x86_64-pc-windows-gnu`, tests) ; les tests ci-dessus passent ; un `config.toml` et une base v6 de la 7.1
sont repris sans changement et restent lisibles par la 7.1 après une session 7.2 ; aucun fichier de l'utilisateur
modifié ; `docs/guide-essai-7.2.md` écrit (Night Trap 32X : vidéo, son, changement de disque, sauvegarde, état ;
marquage manuel ; Fahrenheit si possédé). Ensuite : CI `success` lue, pré-release `v7.2.0-rc.1`, essai utilisateur.

## 6. Interaction avec la 7.1 et points à re-valider par SX0

- Rangement (ADR 0023) : rien à changer ; un CD 32X est une unité `megacd`. La clé de la marque manuelle repose sur
  « le rangement ne renomme jamais » (ADR 0024, « Interaction avec la 7.1 »).
- À re-valider contre le code de `wip-7.2` : signature réelle de `plan_launch` et de `LaunchArgs` après la 7.1 ;
  forme de `PreferencesFile` (table `systems.<nom>` : accepte-t-elle une sous-table `tags` sans casser les versions
  qui liraient ce fichier — il est embarqué, donc sans objet hors tests) ; noms des options picodrive de
  `featured_options` contre le core réel (test d'options de la 7.0) ; capture du journal du core dans un test
  `emu-runtime` (à défaut : lancer le binaire comme dans l'étude et lire sa sortie).
- Hors périmètre : glisser-déposer (7.2.1) ; sonde d'en-tête « SEGA 32X » ; motif de série `T-1620xF` ; regroupement
  automatique de Fahrenheit ; système `megacd32x`.
