### 2.1 `emu-libretro` (`libretro-ffi`)

```rust
// src/hw.rs (created by 8.0 PF1, or by 9.0 GF1 if 9.0 comes first); re-exported from lib.rs
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct GlVersion { pub major: u32, pub minor: u32 }

/// What the frontend serves. `NONE`: 8.0 behaviour (every request remembered and refused).
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
#[non_exhaustive]
pub struct HwSupport {
    /// `RETRO_HW_CONTEXT_OPENGL` (compatibility profile) up to this version; `None` on macOS.
    pub opengl_compat: Option<GlVersion>,
    /// `RETRO_HW_CONTEXT_OPENGL_CORE` up to this version (macOS: 4.1).
    pub opengl_core: Option<GlVersion>,
}
impl HwSupport {
    pub const NONE: Self;
    pub fn opengl(compat: Option<GlVersion>, core: Option<GlVersion>) -> Self;
    pub fn serves(&self, request: &HwRenderRequest) -> bool;
    /// Answer to `GET_PREFERRED_HW_RENDER` (56); `None` declines.
    pub fn preferred(&self) -> Option<HwContextKind>;
}

/// 8.0 type, extended (fields added: `depth`, `stencil`, `bottom_left_origin`).
#[derive(Debug, Clone, PartialEq, Eq)]
#[non_exhaustive]
pub struct HwRenderRequest {
    pub context: HwContextKind, pub version_major: u32, pub version_minor: u32,
    pub depth: bool, pub stencil: bool, pub bottom_left_origin: bool,
}
/// libretro.h numbers: 1, 2, 3, 4, 5, 6, 7 (D3D11); everything else (0, 8 = D3D10, 9 = D3D12, 10 = D3D9, …) is
/// `Unknown(n)`. The 8.0 type is renamed `Direct3D` -> `Direct3D11` (ADR 0026 §3, m4).
#[non_exhaustive]
pub enum HwContextKind { OpenGl, OpenGlEs2, OpenGlCore, OpenGlEs3, OpenGlEsVersion, Vulkan, Direct3D11, Unknown(u32) }

#[derive(Debug, Clone, Default, PartialEq, Eq)]
pub enum HwRenderState { #[default] None, Refused(HwRenderRequest), Accepted(HwRenderRequest) }

/// Installed by `emu-runtime` from `Core::attach_hw` until `Core::shutdown`. Called on the core's thread only;
/// stored per thread (not `Send`). Later API (D3D11, Vulkan) adds methods with default bodies.
pub trait HwRenderHost {
    /// Name of the FBO the core draws into; stable for the whole session; never 0.
    fn current_framebuffer(&self) -> usize;
    /// Address of a GL function in the core's context, or null. Never dereferenced on our side; turned into
    /// `retro_proc_address_t` by emu-libretro only (`// SAFETY:`).
    fn proc_address(&self, name: &CStr) -> *const c_void;
    /// Makes the core's context current before an entry into the core; `false`: the entry is skipped
    /// (`LibretroError::HwContext`). At the end of a session, `false` means the core is never called again (no
    /// `context_destroy`, `retro_unload_game`, `retro_deinit`): the library stays loaded and is marked resident
    /// (ADR 0022). Rule: never call into the core with the frontend's context current; only exception: memory
    /// accessors (`retro_get_memory_data` / `_size`, SRAM), which do no GL.
    fn enter(&self) -> bool;
    /// Fence + `glFlush` after a frame (or `glFinish` without sync objects), then makes the frontend's context
    /// current again; called on every exit, panics included. The fence goes into the session's single
    /// `Option<GLsync>` slot (shared with the window): the previous one is taken out and deleted first.
    /// `false`: the frontend's context is no longer safe; the session ends like an abandon (core never called
    /// again, library left loaded and resident). The UI retries its context at once, skips drawing that frame on
    /// failure, retries next frame, then shows an error and closes.
    fn leave(&self) -> bool;
}

// CoreConfig is unchanged (no new field: m11).

pub trait FrontendHandler {
    /* … existing … */
    /// `video_refresh(RETRO_HW_FRAME_BUFFER_VALID, width, height, _)` with a host attached.
    fn hardware_frame(&mut self, width: u32, height: u32) {}
}

impl Core {
    /// Same as `load` with a capability; `load(p, c)` = `load_with_hw(p, c, HwSupport::NONE)`.
    pub fn load_with_hw(path: &Path, config: CoreConfig, hw: HwSupport) -> Result<Self, LibretroError>;
    /// `unload_game` if needed, then `retro_deinit` inside `enter`/`leave`, host dropped, library closed
    /// (ADR 0022). `enter` fails (or an earlier `leave` returned `false`): `retro_deinit` is not called, the
    /// library is leaked and marked resident (a private copy, if it was one, is kept). Idempotent; `Drop` calls it
    /// (`enter`/`leave` under `catch_unwind`).
    pub fn shutdown(&mut self);
    pub fn hw_render(&self) -> &HwRenderState;
    /// 8.0: last request seen (accepted or not).
    pub fn hw_render_request(&self) -> Option<&HwRenderRequest>;
    /// Every request in order, at most 16 (diagnostics, swanstation tries several).
    pub fn hw_render_attempts(&self) -> &[HwRenderRequest];
    /// Installs `host`, then calls `context_reset` inside `enter`/`leave`. `Err` when no request was accepted,
    /// when already attached, or when `enter` fails.
    pub fn attach_hw(&mut self, host: Box<dyn HwRenderHost>) -> Result<(), LibretroError>;
    pub fn hw_attached(&self) -> bool;
    /// 8.0: `Software | HwSentinel | Missing`; `HwSentinel` only without a host.
    pub fn take_frame_kind(&mut self) -> FrameKind;
}

```

Comportement attendu de `Core` (ADR 0026 §3, §4, amendement M1) : `run`, `serialize`, `unserialize`, `reset`,
`unload_game` et `shutdown` passent par `enter` / `leave` quand un hôte est installé.
`unload_game` : `enter` → `context_destroy` (si non nul et après un `context_reset` réussi) → `retro_unload_game`
→ `leave`. `shutdown` : `enter` → `retro_deinit` → `leave` → hôte détruit → bibliothèque fermée (ADR 0022).
`enter` en échec, ou `leave` faux plus tôt (abandon) : ni `context_destroy`, ni `retro_unload_game`, ni
`retro_deinit` ; bibliothèque laissée chargée et inscrite résidente (copie privée gardée si c'en était une, y compris
sous Windows : `copy.keep()`, `core.rs` vers la ligne 798). Accesseurs de mémoire permis hors `enter` (SRAM).
`SET_HW_RENDER` après `retro_load_game` : `false`, journalisé. `OPENGL` (1) : version ignorée ; `OPENGL_CORE` (3) :
version comparée (m1). `depth` / `stencil` : ADR 0026 §5 (m3). `bool` de la structure lus en `u8` (m5).
56 (seulement si la capacité n'est pas `NONE`) : valeur écrite même avec `false` ; compat + core ⇒
`OPENGL_CORE`, `true` ; core seul ⇒ `OPENGL_CORE`, `false` (m2). `NONE` (0) refusé sans journal d'erreur (m4).
44 : `true`. 41, 43, 73 : `false`.

`Rc<GlTarget>` partagé avec le contexte du core (ADR 0026 §4) ; contexte du core rendu courant sans surface quand

elle grandit (une image rognée assumée, m9) ; dans `leave` après une image matérielle : `glFenceSync` + `glFlush`,

`Option<GLsync>` par session, partagé entre l'hôte et la fenêtre, que chaque consommateur vide (`take`) avant de

contexte du core** (M2) ; temps de présentation pris juste avant `swap_buffers` [M, méthode vérifiée en GR2].
Repli `GlReadback` automatique si la création partagée échoue, et imposé si `HwLaunch::isolated` (journalisé).

## 3. Comportement

### 3.1 Lancement

1. `wants_hw` : HD active pour ce jeu (choix du système, exception du jeu) et profil `[cores.<id>.hw]` présent, ou
   `--hw-render=force`. **Sinon : `HwLaunch::NONE`**, comportement 7.x / 8.x exact (core choisi, options
   `Software` de swanstation inchangées ; dosbox_pure, swanstation choisi à la main : refus et repli logiciel
   inchangés) (B1).
2. Lancement direct et `wants_hw` : la fenêtre est créée **avant** `Core::load` (taille provisoire, ajustée à
   l'`AvInfo` ensuite) (M5). Mode bibliothèque : elle existe déjà.
3. `plan_hw_launch` (après `cores_ui::plan_launch`, §0.2) : core `hd_core`, options `renderer_values.opengl`,
   `scale_option` = choix, `pgxp_option` =
   `true` ou `false` (case PGXP), `options` du profil ; capacité `hw_support(hw_environment(), renderer,
   enabled)`. Indisponible ⇒ la HD n'est pas appliquée, message OSD « Haute résolution indisponible : (raison) »
   et lancement en logiciel (core choisi, `HwLaunch::NONE`).
4. L'autre core de la paire (`hd_core` et core choisi) a des sauvegardes plus récentes pour ce jeu
   (`other_core_newer`) ⇒ OSD « Haute résolution
   activée (ou coupée) : carte mémoire et sauvegardes d'état séparées de (autre core) » (Q-A, M6). Les réglages
   l'indiquent aussi sous la case.
5. `Emulator::load_content_hw` avec `HwPlan::hw`. `--hw-render=force` (tests, captures, essai Mac GE3) passe outre
   `macos = false` et
   l'absence de profil. Si `needs_gl()`, `attach_gl(&window)` **avant** le premier
   `run_frame` (`App::resumed` en lancement direct, `App::attach` en mode bibliothèque).
6. Échec d'attachement ⇒ écran d'erreur « Rendu matériel impossible : (détail) » avec « Relancer en rendu logiciel »
   (même jeu, `HwForce::Off` pour ce lancement).
7. Boucle : `run_frame` ; `video_updated` ⇒ `upload_frame` (logiciel) ou `show_hw_frame` (matériel) ; `draw_frame`,
   egui, `swap_buffers` inchangés. `--screenshot` et vignettes : `read_frame()`.
8. Fin : `App::teardown` / `App::detach` appellent `Emulator::release_gl()` **avant** de rendre ou détruire la
   fenêtre (m13) ; `App.emulator` reste un champ simple.

### 3.2 Interface

- Réglages → Vidéo (section nouvelle, B2) : « Rendu matériel » (activé ; sans effet tant qu'aucune haute
  résolution n'est choisie) ;
  « PlayStation : haute résolution (swanstation) » (désactivé), avec la note « carte mémoire et états séparés de
  pcsx_rearmed », « Résolution interne » ×1 à ×8 (×2) et « PGXP (géométrie stable) » (coché). Grisés avec la raison
  quand indisponibles (WSL, Docker, pilote logiciel, macOS tant que `macos = false`).
- Menu du jeu : « Haute résolution pour ce jeu » (oui / non / comme le système) ; « PGXP pour ce jeu » (oui / non /
  comme le système, Q-H) ; « Résolution interne » appliquée
  en cours de jeu si swanstation la prend, sinon « au prochain lancement » [M, à constater au lot GQ2].
- Panneau Stats : chemin de rendu (« logiciel », « OpenGL partagé », « OpenGL relu »), `GL_RENDERER`, résolution
  interne, temps core / GPU / présentation (moyenne sur 1 s), images lentes ; « Mesurer 60 s ».
- Mesure en cours : compte à rebours discret dans l'OSD ; à la fin, chemin du rapport et « Copier le rapport »
  (`copyable::copy_button_labelled`).

## 8. Plan d'essai réel (utilisateur, Windows natif, Iris Xe)

Préparation : exécutable Windows 9.0 de la CI ; fermer navigateur et gros programmes (fichier d'échange très
sollicité au
relevé du 2026-11-23) ; secteur branché, mode d'alimentation « meilleures performances » ; Windows natif, pas WSL.

1. Réglages → Vidéo : « Rendu matériel » activé ; « PlayStation : haute résolution » activé, ×2.
2. Lancer **GTA** (PS1). Vérifier : image nette, panneau Stats « OpenGL partagé » et « Intel(R) Iris(R) Xe ».
3. Aller à la scène de référence (réponse 5 : début de la première mission de **GTA PAL / Europe**, en voiture en
   ville), puis **trois « Mesurer 60 s »**, même scène, vsync activée, même taille de fenêtre : (a) haute résolution
   coupée (pcsx_rearmed, logiciel), (b) swanstation ×2, (c) swanstation ×4 ; (d) facultative, swanstation choisi
   comme core **sans** haute résolution (logiciel), pour séparer le coût du changement de core de celui de la HD
   (M6, question Q-G). Coller les rapports.
4. Sauvegarde d'état (emplacement 1), jouer 30 s, chargement ; quitter, relancer, charger l'état.
5. Plein écran / fenêtre plusieurs fois (Alt+Entrée), redimensionner : pas d'écran noir ni de plantage.
6. Menu : « Redémarrer le jeu » ; retour à la bibliothèque ; lancer un autre jeu PS1 ; relancer GTA.
7. Changer la résolution interne en jeu (×2 → ×4) : appliquée ou « au prochain lancement », comme annoncé.
8. Couper « Haute résolution pour ce jeu » dans le menu du jeu : relance en logiciel (pcsx_rearmed) avec le message
   « carte mémoire et états séparés » ; la carte de pcsx_rearmed est celle d'avant la HD (réponse Q-A).
9. Décocher « PGXP pour ce jeu » : appliqué au prochain lancement, géométrie qui « tremble » de nouveau.
10. Dix allers-retours bibliothèque → GTA ×2 → bibliothèque : relever la mémoire d'emu-rust (Gestionnaire des tâches,
    « Mémoire » et « Mémoire GPU partagée ») au 1er et au 10e (M2).
11. Un jeu DOS avec la Voodoo (dosbox_pure) : se lance et tourne comme en 7.x / 8.x (B1).
12. Sous WSLg (ou Docker) : réglage HD grisé avec la raison, GTA tourne en logiciel.
13. À relever : FPS ressentis, saccades, bruit du ventilateur, tout message d'erreur (journal joint).

Décision qui en découle (réponses 5 et 6) : si (b) est mauvais selon les seuils (moyenne < 97 % de la cadence,
soit 48,5 i/s en PAL, ou plus de 2 % d'images lentes, ou saccades visibles), DirectX 11 passe avant la 9.1. Les
seuils chiffrés décident ; le ressenti de l'utilisateur compte aussi un peu (cas limite : on en discute).

## 9. Risques

| Risque | Gravité | Parade |
|---|---|---|
| Partage de contextes refusé ou instable sur le pilote Intel Windows | haute | prototype GP0 / GE1 en tête ; repli `GlReadback` automatique ; ADR amendée si C devient la règle |
| `unsafe` FFI et GL nouveau (structure du core, trampolines, contexte courant implicite) | haute | invariants de l'ADR §11, garde RAII, `catch_unwind`, tests du cycle de vie, revue GV1 en deux temps |
| Vérification automatique faible sous Windows (pas de pilote GL sur la CI) | haute | CI Windows (`clippy`, tests msvc) sur la branche poussée, essais GE1 / GE2, rapport de mesure, journal détaillé |
| Régression d'un core livré qui demande déjà le rendu matériel (dosbox_pure Voodoo, swanstation en `Auto`) | haute | capacité `NONE` hors HD choisie (B1) ; tests du plan de lancement et réel `#[ignore]` |
| Fuite d'objets GL du core dans le groupe de partage (mode bibliothèque, mémoire partagée de l'Iris Xe) | moyenne | nettoyage de nos objets, `MOCK_HW_LEAK`, dix relancements au prototype et à l'essai, `isolated = true` par core (M2) |
| Barrière qui ne se débloque pas, ou contexte sans objets de synchronisation | moyenne | `glFlush` après `glFenceSync`, repli `glFinish`, test compat 3.0 (M4) |
| Noms et valeurs des options de swanstation [M] | moyenne | test réel qui vérifie le profil contre la liste du core (GQ2) ; profil dans `cores.toml`, corrigeable sans code |
| swanstation demande un type ou une version inattendus ; rendu en thread | moyenne | toutes les demandes journalisées ; `UseThread = false` forcé ; appels d'un autre thread neutres |
| Ordre `context_destroy` / `retro_unload_game`, `enter` en échec à la fin | moyenne | ordre vérifié dans RetroArch par la revue ; séquences de l'ADR §4 (M1) testées avec l'hôte factice ; `enter` en échec ou `leave` faux : abandon, le core n'est plus appelé, bibliothèque résidente (ADR 0022) |
| Détection WSL vraie dans le conteneur de Claude (noyau WSL2) | moyenne | capacité passée explicitement aux tests (`load_content_hw`) ; `--hw-render=force` pour les captures |
| Mémoire de l'Iris Xe partagée avec 16 Go déjà chargés ; ×8 très lourd | moyenne | ×2 par défaut ; contrôle `GL_MAX_TEXTURE_SIZE` ; message clair si l'allocation échoue |
| Empreintes de vrais cores instables d'une version de Mesa à l'autre | faible | tolérance, version de Mesa notée ; empreintes exactes réservées au core factice |
| Glissement de version de la 8.0 (types `HwRenderRequest`, `FrameKind`) | faible | la 9.0 les crée si elle passe avant ; noms identiques ; `#[non_exhaustive]` demandé à la 8.0 |
| macOS non essayable ici ; deux contextes sur la même `NSView` fragiles [M] | moyenne | contexte du core sans surface (M3) ; profil core ≤ 4.1 ; `macos = false` jusqu'à l'essai GE3 réussi |
