# Conception 9.0 — rendu matériel : socle OpenGL, PlayStation haute résolution, mesure

Date : 2026-11-25 (architecte). Décisions : **ADR 0026** (proposé). Étude : `docs/etude-9.0-rendu-materiel.md`.
Réponses de l'utilisateur (2026-11-22 et 2026-11-23, `docs/questions-ouvertes.md`, section 9.0) : elles font foi et
ne sont pas reposées ici. Marques [M] : de mémoire, à vérifier par le lot qui s'en sert. Rien n'a été compilé ni
exécuté pour ce document.

## 1. Objet

Livré par la 9.0, sur **Windows natif** (cible principale), **macOS Intel** (OpenGL core ≤ 4.1) et **Linux natif** :

- le **socle OpenGL** de l'ADR 0026 : demande `SET_HW_RENDER` servie, contexte du core partagé avec l'interface
  (repli par relecture), FBO, affichage, relecture à la demande, cycle de vie, sauvegardes d'état ;
- la **PlayStation en haute résolution avec swanstation** : réglage (désactivé par défaut, pcsx_rearmed reste le
  défaut), résolution interne ×2 à l'activation, réglable de ×1 à ×8 ;
- le **compteur étendu** (Stats) et **« Mesurer 60 s »** avec rapport à coller, utiles dès le rendu logiciel ;
- le **refus propre**, avec sa raison, sous WSL / WSLg, Docker, noVNC, sur pilote logiciel, ou si l'API n'est pas
  servie (macOS : grisé).

Hors 9.0 : nouveaux systèmes (9.1 et suivants, §10), DirectX 11, Vulkan, plein écran exclusif, récupération d'une
perte de contexte, thread d'émulation.

### 2.1 `emu-libretro` (`libretro-ffi`)

```rust
// src/hw.rs (created by 8.0 PF1, or by 9.0 GF1 if 9.0 comes first); re-exported from lib.rs
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct GlVersion { pub major: u32, pub minor: u32 }

/// What the frontend serves. `NONE`: 8.0 behaviour (every request remembered and refused).
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
#[non_exhaustive]
pub struct HwSupport {
    /// `RETRO_HW_CONTEXT_OPENGL` (compatibility profile) up to this version; `None` on macOS.
    pub opengl_compat: Option<GlVersion>,
    /// `RETRO_HW_CONTEXT_OPENGL_CORE` up to this version (macOS: 4.1).
    pub opengl_core: Option<GlVersion>,
}
impl HwSupport {
    pub const NONE: Self;
    pub fn opengl(compat: Option<GlVersion>, core: Option<GlVersion>) -> Self;
    pub fn serves(&self, request: &HwRenderRequest) -> bool;
    /// Answer to `GET_PREFERRED_HW_RENDER` (56); `None` declines.
    pub fn preferred(&self) -> Option<HwContextKind>;
}

/// 8.0 type, extended (fields added: `depth`, `stencil`, `bottom_left_origin`).
#[derive(Debug, Clone, PartialEq, Eq)]
#[non_exhaustive]
pub struct HwRenderRequest {
    pub context: HwContextKind, pub version_major: u32, pub version_minor: u32,
    pub depth: bool, pub stencil: bool, pub bottom_left_origin: bool,
}
#[non_exhaustive]
pub enum HwContextKind { OpenGl, OpenGlEs2, OpenGlCore, OpenGlEs3, OpenGlEsVersion, Vulkan, Direct3D, Unknown(u32) }

#[derive(Debug, Clone, Default, PartialEq, Eq)]
pub enum HwRenderState { #[default] None, Refused(HwRenderRequest), Accepted(HwRenderRequest) }

/// Installed by `emu-runtime` from `Core::attach_hw` until the `Core` is dropped. Called on the core's thread only;
/// stored per thread (not `Send`). Later API (D3D11, Vulkan) adds methods with default bodies.
pub trait HwRenderHost {
    /// Name of the FBO the core draws into; stable for the whole session; never 0.
    fn current_framebuffer(&self) -> usize;
    /// Address of a GL function in the core's context, or null. Never dereferenced on our side.
    fn proc_address(&self, name: &CStr) -> *const c_void;
    /// Makes the core's context current before an entry into the core; `false` skips the entry
    /// (`LibretroError::HwContext`).
    fn enter(&self) -> bool;
    /// Makes the frontend's context current again; called on every exit, panics included.
    fn leave(&self);
}

pub struct CoreConfig { /* … */ pub hw_support: HwSupport }

pub trait FrontendHandler {
    /* … existing … */
    /// `video_refresh(RETRO_HW_FRAME_BUFFER_VALID, width, height, _)` with a host attached.
    fn hardware_frame(&mut self, width: u32, height: u32) {}
}

impl Core {
    pub fn hw_render(&self) -> &HwRenderState;
    /// 8.0: last request seen (accepted or not).
    pub fn hw_render_request(&self) -> Option<&HwRenderRequest>;
    /// Every request in order, at most 16 (diagnostics, swanstation tries several).
    pub fn hw_render_attempts(&self) -> &[HwRenderRequest];
    /// Installs `host`, then calls `context_reset` inside `enter`/`leave`. `Err` when no request was accepted,
    /// when already attached, or when `enter` fails.
    pub fn attach_hw(&mut self, host: Box<dyn HwRenderHost>) -> Result<(), LibretroError>;
    pub fn hw_attached(&self) -> bool;
    /// 8.0: `Software | HwSentinel | Missing`; `HwSentinel` only without a host.
    pub fn take_frame_kind(&mut self) -> FrameKind;
}
// LibretroError (non_exhaustive): HwContext(String), HwNotAccepted
```

Comportement attendu de `Core` (ADR 0026 §3, §4) : `run`, `serialize`, `unserialize`, `reset` et `Drop` passent par
`enter` / `leave` quand un hôte est installé ; `Drop` : `enter`, `context_destroy` (si non nul et après un
`context_reset`), `retro_unload_game`, `retro_deinit`, `leave`, hôte détruit, puis bibliothèque fermée (ADR 0022).
`SET_HW_RENDER` après `retro_load_game` : `false`, journalisé. 44 : `true`. 41, 43, 73 : `false`.

## 3. Comportement

### 3.1 Lancement

1. `plan_launch` : HD active pour ce jeu (choix du système, exception du jeu) ⇒ core `hd_core`, options
   `renderer_values.opengl`, `scale_option` = choix, `options` du profil. Sinon : comportement 8.0 (core choisi,
   options `Software` de swanstation inchangées).
2. Capacité : `hw_support(hw_environment(), renderer, enabled)` ; `renderer` connu en mode bibliothèque, inconnu en
   lancement direct. Indisponible ⇒ la HD n'est pas appliquée, message OSD « Haute résolution indisponible :
   (raison) » et lancement en logiciel (pcsx_rearmed ou core choisi).
3. `Emulator::load_content_as` avec `hw_support`. Si `needs_gl()`, `attach_gl(&window)` dès que la fenêtre existe
   (`App::resumed` en lancement direct, `App::attach` en mode bibliothèque), **avant** le premier `run_frame`.
4. Échec d'attachement ⇒ écran d'erreur « Rendu matériel impossible : (détail) » avec « Relancer en rendu logiciel »
   (même jeu, `HwForce::Off` pour ce lancement).
5. Boucle : `run_frame` ; `video_updated` ⇒ `upload_frame` (logiciel) ou `show_hw_frame` (matériel) ; `draw_frame`,
   egui, `swap_buffers` inchangés. `--screenshot` et vignettes : `read_frame()`.
6. Fin : `App::teardown` / `App::detach` détruisent l'`Emulator` **avant** de rendre ou détruire la fenêtre.

### 3.2 Interface

- Réglages → Vidéo : « Rendu matériel » (activé) ; « PlayStation : haute résolution (swanstation) » (désactivé) et
  « Résolution interne » ×1 à ×8 (×2). Grisés avec la raison quand indisponibles (WSL, Docker, pilote logiciel,
  macOS si `macos = false`).
- Menu du jeu : « Haute résolution pour ce jeu » (oui / non / comme le système) ; « Résolution interne » appliquée
  en cours de jeu si swanstation la prend, sinon « au prochain lancement » [M, à constater au lot GQ2].
- Panneau Stats : chemin de rendu (« logiciel », « OpenGL partagé », « OpenGL relu »), `GL_RENDERER`, résolution
  interne, temps core / GPU / présentation (moyenne sur 1 s), images lentes ; « Mesurer 60 s ».
- Mesure en cours : compte à rebours discret dans l'OSD ; à la fin, chemin du rapport et « Copier le rapport ».

- vague 2 (après GX1) : GR2 ∥ GQ1 ∥ GF1 ∥ GA1 (quatre crates ou dossiers distincts ; trois sous-agents actifs en
  moyenne : GA1 ou GQ1 peut attendre) ; GB0 + GE1 en arrière-plan ;
- vague 3 : GR1 (après GR2, même crate) ∥ GU1 (après GR2) ∥ GV1a (après GF1) ;
- vague 4 : GU2 (après GU1, GR1, GA1) ∥ GV1b (après GR1) ; puis GU3 éventuel, GQ2, GX2, GE2.

**Chemin critique** : GX1 → GR2 → GR1 → GU2 → GQ2 → GE2 (GF1 en parallèle de GR2 / GR1 ; GR1 peut commencer
sur les signatures de GX1 et intègre GF1 à sa fin). GE1 n'est **pas** bloquant.

## 9. Risques

| Risque | Gravité | Parade |
|---|---|---|
| Partage de contextes refusé ou instable sur le pilote Intel Windows | haute | prototype GP0 / GE1 en tête ; repli `GlReadback` automatique ; ADR amendée si C devient la règle |
| `unsafe` FFI et GL nouveau (structure du core, trampolines, contexte courant implicite) | haute | invariants de l'ADR §11, garde RAII, `catch_unwind`, tests du cycle de vie, revue GV1 en deux temps |
| Vérification automatique faible sous Windows (pas de pilote GL sur la CI) | haute | `clippy` cible Windows, essais GE1 / GE2, rapport de mesure, journal détaillé |
| Noms et valeurs des options de swanstation [M] | moyenne | test réel qui vérifie le profil contre la liste du core (GQ2) ; profil dans `cores.toml`, corrigeable sans code |
| swanstation demande un type ou une version inattendus ; rendu en thread | moyenne | toutes les demandes journalisées ; `UseThread = false` forcé ; appels d'un autre thread neutres |
| Ordre `context_destroy` / `retro_unload_game` [M] | moyenne | vérifié dans RetroArch au lot GF1 ; contexte vivant jusqu'à `retro_deinit` de toute façon |
| Détection WSL vraie dans le conteneur de Claude (noyau WSL2) | moyenne | capacité passée explicitement aux tests ; `--hw-render=force` pour les captures |
| Mémoire de l'Iris Xe partagée avec 16 Go déjà chargés ; ×8 très lourd | moyenne | ×2 par défaut ; contrôle `GL_MAX_TEXTURE_SIZE` ; message clair si l'allocation échoue |
| Empreintes de vrais cores instables d'une version de Mesa à l'autre | faible | tolérance, version de Mesa notée ; empreintes exactes réservées au core factice |
| Glissement de version de la 8.0 (types `HwRenderRequest`, `FrameKind`) | faible | la 9.0 les crée si elle passe avant ; noms identiques ; `#[non_exhaustive]` demandé à la 8.0 |
| macOS non essayable ici | moyenne | profil core ≤ 4.1 ; `macos = true` à confirmer par l'utilisateur sur son Mac, sinon grisé |
