# Version 4.0 — PC-DOS (dosbox_pure) : contrat et découpage

Décisions : **ADR 0018** (statut proposé ; précise 0005, 0013, 0014, 0016). Étude préalable : `docs/essais-dosbox.md`.
Base réutilisée : `docs/design/v2.0-atari-st.md` (infrastructure « ordinateur ») et `docs/design/v3.0-amiga.md`
(`MediaRules`, `DatSource::Libretro`, import de BIOS, sélecteur de fichier, dossier des ROMs). Ce document ne donne
que le **delta** par rapport à la 3.0. Les signatures seront **posées dans le code par l'`architecte` au lancement de
la 4.0** (tâche DX0), une fois la 3.0 intégrée ; aucune n'est posée aujourd'hui (le code fera alors foi).

## 1. Périmètre

| Dans la 4.0 | Plus tard / jamais |
|---|---|
| PC-DOS avec `dosbox_pure` (seul core proposé), Linux / Windows / macOS x86_64 / Docker | `dosbox_core`, `dosbox_svn` (`--core <chemin>` seulement) |
| Contenus : zip / dosz, dossier, exe / com / bat, iso / cue / chd / ins, img / ima / vhd / jrc, m3u / m3u8 | `.conf` comme contenu (refusé) ; `dosbox.conf` interne : option `dosbox_pure_conf` par jeu |
| Fichiers de l'utilisateur jamais modifiés : `.pure.zip` du core, instantané zip des dossiers, copie de travail des images inscriptibles | Partage de sauvegardes entre contenus (`.SAVENAME`, fonction du core, non exposée) |
| Choix de l'exécutable par le menu de démarrage du core (mémorisé par le core), « Changer de programme », lancement d'un `.exe` précis | Sélecteur d'exécutable propre au frontend (ISO / FAT à analyser) |
| Options par jeu, section « Réglages DOS » (`featured_options`) | Préréglages par titre (base de données) |
| MIDI : SoundFont libre GeneralUser GS (facultatif, téléchargé sur action), MT-32 / CM-32L importés | SC-55 (ROM commerciales, import non vérifié possible), sortie MIDI vers l'hôte (`GET_MIDI_INTERFACE`) |
| `GET_VFS_INTERFACE` v3 (opt-in par core) | — |
| Clavier PC (disposition DOS calculée), clavier virtuel `pc.toml`, mode Joystick 2.0 = flèches | Couche « pavé numérique » sur les lettres (question §9.6) |
| Manette : axes analogiques (`RETRO_DEVICE_ANALOG`) | Lecture de `SET_CONTROLLER_INFO` (type de manette DOS choisi dans le core) |
| Bibliothèque : système `dos`, jeux-dossiers, DAT `dat/DOS.dat` par CRC des entrées | TOSEC PC, eXoDOS (écartés, ADR 0018 §9) |
| — | Installation de Windows 3.x / 9x (fonction du core, non testée, OS commercial fourni par l'utilisateur) ; Voodoo matériel (phase 7) ; réseau / modem |

## 2. Fonctionnement

### 2.1 Lancement d'un jeu DOS depuis la bibliothèque

```text
Game (dos) ─ choose_core ─► dosbox_pure (vfs = true ⇒ CoreConfig::provide_vfs)
options : défauts core < cores.toml (dosbox_pure_midi = "disabled") < keyboard_layout calculé (locale)
          < [core_options.dosbox_pure] < game-options/dosbox_pure/<jeu>.toml
selon Game.content / extension :
  zip, dosz, iso, cue, chd, ins ─► ContentSpec::File(chemin)                 (transmis tel quel, block_extract = 1)
  dossier ─► snapshot_status(dir, <cache>/dosbox_pure/<jeu>.zip)
               Current ─► ContentSpec::Folder { dir, name, start: options.dos.start }
               Stale | Missing ─► job « Préparation du jeu… » (snapshot_folder, progression, annulation) ─► idem
  img, ima, vhd, jrc ─► ContentSpec::Media { set, rules: MediaRules { WorkingCopy, direct = [zip, dosz, iso, cue, chd, ins] } }
  m3u, m3u8, groupe multi-disques ─► ContentSpec::Media (même règles : CD référencés en absolu, disquettes copiées)
Emulator::load_content ─► core : C: = contenu ; modifications ─► saves/dosbox_pure/<nom>.pure.zip
1er lancement (pas de <nom>.pure.zip) ─► OSD « Menu DOS : ↑ ↓ Entrée · → : lancer automatiquement la prochaine fois »
mode d'entrée initial = Clavier ; souris capturée au premier clic (2.0)
```

`<nom>` = nom du fichier transmis au core sans extension (`Emulator::core_content_name`) : nom du zip de
l'utilisateur, ou nom du jeu pour un instantané.

### 2.2 Changer de programme de démarrage

```text
menu (touche hôte) ─► « Changer de programme de démarrage »
   ─► Emulator::reset_with_keys(&[RetroKey::LSHIFT])   // le core lit Shift dans retro_reset ⇒ menu forcé
   ─► menu du core ; l'utilisateur choisit (→ = nouveau démarrage auto, mémorisé dans AUTOBOOT.DBP du .pure.zip)
fiche du jeu (dossier) ─► « Lancer un autre programme… » ─► root_executables(dir) ─► choix ─► [dos] start = "SETUP.EXE"
   (« pour cette fois » ou « par défaut ») ─► ContentSpec::Folder { start: Some("SETUP.EXE") } ─► <instantané>.zip#SETUP.EXE
```

`AUTOBOOT.DBP` (choix fait dans le core) l'emporte sur `start` : « par défaut » n'est proposé que si le jeu n'a pas
encore de démarrage auto (sinon message « choisi dans le menu DOS : utilisez Changer de programme »).

### 2.3 Réinitialiser les modifications

```text
menu ─► « Réinitialiser les modifications du jeu… » (confirmation : sauvegardes du jeu, SETUP, programme de démarrage,
        correspondances manette perdus) ─► partie arrêtée ─► reset_core_game_files(saves/dosbox_pure, <nom>,
        ["{game}.pure.zip", "{game}-*.sav"]) + reset_working_copies(…) ─► relance
```

### 2.4 MIDI

```text
Réglages DOS ▸ MIDI = [Aucun ▾ | GeneralUser GS | MT-32 | CM-32L | fichiers .sf2 trouvés]
   valeur absente de la liste du core ─► « Installer GeneralUser GS (32 Mo, licence libre) ? » ─► job FreeBiosManager::install
                                      ─► « Importer des ROM MT-32… » ─► import de BIOS (3.0), noms MT32_*.ROM / CM32L_*.ROM
   après installation / import ─► invalidate_system_caches(system, ["DOSBoxPureMidiCache.txt"]) ─► « Redémarrer le jeu »
   « pour tous les jeux DOS » ─► [core_options.dosbox_pure] dosbox_pure_midi = "GeneralUser-GS.sf2"
```

Les valeurs de `dosbox_pure_midi` sont des chemins relatifs au dossier système (`GeneralUser-GS.sf2`,
`MT32_CONTROL.ROM`), lus dans les options que le core déclare (il les liste par la VFS au chargement).

## 3. Interfaces entre crates (delta 3.0 → 4.0)

### 3.1 `emu-libretro`

```rust
pub struct CoreConfig { …, pub provide_vfs: bool }   // défaut false : 45 | EXPERIMENTAL → false (comportement 3.0)
// vfs.rs (nouveau, privé) : `retro_vfs_interface` v3 sur std::fs
//   get_path, open, close, size, tell, seek, read, write, flush, remove, rename, truncate, stat, mkdir,
//   opendir, readdir, dirent_get_name, dirent_is_dir, closedir  (19 fonctions `unsafe extern "C"`)
```

Règles : réponse à `GET_VFS_INTERFACE` seulement si `provide_vfs` ; `required_interface_version` > 3 ⇒ `false`,
sinon on écrit la version **3** et le pointeur d'une table `static`. Les fonctions **n'utilisent aucun état
thread-local ni `with_env`** (le core peut les appeler depuis son thread d'émulation) : poignées
`Box<VfsFile { file: File, path: CString }>` et `Box<VfsDir { iter: ReadDir, current: Option<(CString, bool)> }>`,
libérées par `close` / `closedir` ; chemins UTF-8 (refus sinon, `NULL` / `-1`) ; aucun `panic` ne traverse la
frontière (`catch_unwind` ⇒ valeur d'erreur) ; modes d'accès et `stat` (`IS_VALID`, `IS_DIRECTORY`,
`IS_CHARACTER_SPECIAL`) selon `libretro.h` ; `mkdir` : 0, -2 si existe, -1 sinon ; `dirent_get_name` valide jusqu'au
`readdir` suivant ; `opendir(include_hidden = false)` saute les noms commençant par `.`. Aucun privilège nouveau : le
core a déjà accès au système de fichiers par `fopen`.

### 3.2 `emu-runtime`

```rust
pub enum ContentSpec { …, Folder { dir: PathBuf, name: String, start: Option<String> } }
pub struct EmulatorOptions { …, pub cache_dir: PathBuf }     // <data>/cache ; instantanés dans <cache>/<core_id>/
pub struct SnapshotLimits { pub max_bytes: u64, pub max_files: u32, pub max_depth: u32 }   // 4 Gio, 65 535, 16
impl SnapshotLimits { pub const DEFAULT: Self; }
pub enum SnapshotStatus { Current, Stale, Missing }
pub struct SnapshotReport { pub files: u32, pub bytes: u64, pub rebuilt: bool }
pub fn snapshot_path(cache_core_dir: &Path, name: &str) -> PathBuf;              // <name assaini, sans #>.zip
pub fn snapshot_status(dir: &Path, snapshot: &Path) -> Result<SnapshotStatus, RuntimeError>;
pub fn snapshot_folder(dir: &Path, snapshot: &Path, limits: &SnapshotLimits,
                       progress: &mut dyn FnMut(u64, u64), cancel: &AtomicBool) -> Result<SnapshotReport, RuntimeError>;
pub fn reset_core_game_files(saves_core_dir: &Path, content_name: &str, patterns: &[String]) -> Result<Vec<PathBuf>, RuntimeError>;
impl Emulator { pub fn reset_with_keys(&mut self, held: &[RetroKey]); pub fn core_content_name(&self) -> Option<&str>; }
pub enum AnalogStick { Left, Right }
impl PadState { pub fn set_analog(&mut self, stick: AnalogStick, x: i16, y: i16); pub fn analog(&self, stick: AnalogStick) -> (i16, i16) }
RuntimeError += SnapshotTooLarge { limit: u64 }, SnapshotCancelled, UnrepresentableName(PathBuf), InvalidStart(String)
```

Règles :
- **Instantané** : zip **stocké** (crate `zip` déjà présent, Zip64 si besoin), écrit dans `<snapshot>.tmp-*` puis
  renommé avec le manifeste `<snapshot>.manifest` (SHA-256 de la liste triée `chemin relatif \0 taille \0 mtime`) ;
  noms d'entrée = chemins relatifs avec `/`, sans `..`, sans composant vide ni caractère de contrôle (sinon
  `UnrepresentableName`) ; liens symboliques ignorés (ni suivis ni copiés), profondeur et taille bornées **pendant**
  le parcours ; `cancel` vérifié entre deux fichiers (temporaire supprimé) ; le dossier source n'est **jamais ouvert en
  écriture**. `Folder` dont l'instantané n'est pas `Current` : `load_content` le construit (sans progression).
- `start` : non vide, ≤ 12 caractères 8.3, ASCII imprimable sans `/ \ # :` ni espace, extension `exe` / `com` / `bat`,
  présent à la racine de `dir` (casse ignorée) ; sinon `InvalidStart`. Chemin transmis : `<snapshot>.zip#START.EXE`
  (non vérifié comme fichier ; `GameSource::Path`).
- `MediaRules` (3.0) : une extension de `direct_extensions` est testée **avant** l'inspection des zips (un zip direct
  n'est jamais extrait, même s'il contient des images). Un `MediaSet` d'une seule image directe = `File`.
- `reset_with_keys` : les touches sont vues enfoncées par `input_state(KEYBOARD)` **pendant `retro_reset` seulement**
  (état du clavier restauré après) ; aucun événement `send_key_event`.
- `reset_core_game_files` : motifs de `cores.toml` avec `{game}` et au plus un `*` dans le **nom de fichier** (jamais
  de séparateur), appliqués au seul dossier `saves_core_dir` ; renvoie les fichiers supprimés.
- Analogique : `input_state(ANALOG, index 0/1, id X/Y)` = valeurs de `PadState` (port du pad) ; `INDEX_ANALOG_BUTTON`
  = ±0x7FFF dérivé du bouton numérique ; clavier seul ⇒ 0 (les directions numériques suffisent au core).

Règles de scan (système `dos`) :
- Seulement sous un dossier dont un composant vaut `dos` (casse ignorée, règle des dossiers de la 1.0), sauf
  `dosz` / `ima` / `jrc` / `m3u8` (propres au DOS) et les zips dont une entrée est `.exe` / `.com` / `.bat` (règle zip
  de la 1.0).
- Un sous-dossier (pas la racine `dos` elle-même) dont la racine contient ≥ 1 `.exe` / `.com` / `.bat` est **un jeu**
  (`GameContent::Folder`, chemin = dossier, titre = nom du dossier) ; ses fichiers ne sont pas listés à part ; un
  dossier sans exécutable à sa racine est parcouru normalement (images, zips).
- Exécutables directement dans la racine `dos` : ignorés, comptés dans `ignored_loose_executables`.
- Zip : **aucune décompression** ; seuls le répertoire central (noms, CRC32, tailles) et la limite d'entrées de la
  1.0 sont appliqués ; pas de refus au-delà de 1 Gio pour `dos` (le contenu n'est pas lu).
- Groupes : règles 2.0 + `(Disc N)`, `(Disc N of M)`, `(CD N)`.
- Identification : `DosFile` = entrées du zip (répertoire central) ou fichiers `exe com bat ima img` de la racine du
  dossier (≤ 64, ≤ 16 Mio, CRC calculé), ou l'image seule (`ima` / `img`). Une ligne du DAT compte si CRC32, taille et
  nom (casse ignorée) concordent ; titre avec le plus de lignes concordantes ⇒ `Unique`, égalité ⇒ `Ambiguous`
  (non identifié, repli sur le nom). ISO / CHD / CUE : nom seulement. Métadonnées `genre`, `releaseyear`,
  `developer` du DAT importées si le schéma les accepte (sinon ignorées).

Écrans et menus :

  modifications du jeu… », « Disquettes / CD » (2.0, libellé selon les images), « Options de ce jeu » avec
  **Réglages DOS** en tête (`featured_options`, puis la liste complète).

  (progression, Annuler) pour l'instantané ; avertissement si deux jeux DOS ont le même `<nom>` de contenu (même
  `.pure.zip`).

  (3.0) propose MT-32. **Réglages** : « Vider le cache DOS (N Mo) » (supprime `<cache>/dosbox_pure/`, partie arrêtée).

- `effective_core_options` (2.0) reçoit `dosbox_pure_keyboard_layout = dos_keyboard_layout(locale)` comme défaut
  frontend calculé, sous la config et le jeu.
- Manette (si phase 6 intégrée) : les sticks remplissent `PadState::set_analog` (zone morte de la phase 6).

CLI (`emu-app`) : `--rom <dossier>` (jeu-dossier, instantané avec progression texte) ; `--rom <dossier>/START.EXE`
(⇒ `Folder { start: "START.EXE" }`) ; `--rom x.conf` refusé (message) ; `--clear-dos-cache` ; `--install-bios
generaluser-gs` (2.0, `kind` affiché par `--list-bios`). Codes de sortie inchangés.

## 7. Découpage

Règle (1.0) : une seule instance d'agent par fichier ; un agent par crate ; chaque agent finit avec le workspace vert.
Préalables : **3.0 intégrée** (V3 fait) ; pour DG1 seulement : phase 6 (manette) intégrée (T3).

1. **DX0** seul (court) ;
2. **DF1** ‖ **DR1** ‖ **DA1** (puis **DB1**, **DU1**, **DQ1**, **DP1** dès qu'une place se libère : ils ne bloquent

### Critères de « terminé » (4.0)

- Définition générale de `CLAUDE.md` (fmt, clippy `-D warnings`, tests, aucun réseau réel hors `#[ignore]`, revue
  de tout l'`unsafe` VFS et du téléchargement du SoundFont).
- Headless, **sans aucun logiciel commercial** : `hello.zip`, menu du core navigué au clavier, jeu-dossier, disquette
  et ISO générés, Floppy Bird et FreeDOS reconnus par empreinte ; `.pure.zip` créé ; MIDI audible avec GeneralUser GS
  (`#[ignore]`) et liste MIDI peuplée par la VFS.
- **Aucun fichier de l'utilisateur modifié** : hash avant / après pour zip, dossier, disquette, ISO après une session
  qui écrit.
- Un `config.toml` 3.0 est relu sans changement ; ST, Amiga et consoles se comportent comme en 3.0 (puae ne reçoit
  toujours pas de VFS).
- Essai utilisateur : un point-and-click DOS à la souris capturée (zip), un jeu au clavier 60 % (flèches par Fn ou
  mode Joystick), un jeu-dossier, choix d'exécutable mémorisé puis changé, sauvegarde de partie retrouvée au
  lancement suivant, MIDI GeneralUser GS (et MT-32 si l'utilisateur possède les ROM), Windows et macOS.

## 8. Risques

| Risque | Atténuation |
|---|---|
| `dosbox_pure` nightly en « preview » (1.0-preview8) | Version précédente conservée (ADR 0013), empreintes ré-enregistrables ; aucun ticket en amont rédigé par un LLM (politique du projet) |
| 70,09 images/s (VGA) sur un écran 60 Hz avec vsync : saccades ou sous-alimentation audio | Synchro audio (ADR 0010) mesurée par DQ2 ; repli par jeu `dosbox_pure_force60fps = 60` (option du core) ; question §9.10 |
| Rapport d'aspect 640×400 / 320×200 affiché étiré | DQ2 vérifie l'`aspect_ratio` transmis ; `dosbox_pure_aspect_correction` par jeu |
| Menu du core peu pratique au clavier 60 % (flèches par Fn) | Souris acceptée par le menu (à confirmer en DQ2), mode Joystick (ZQSD = flèches), « Lancer un autre programme… » du frontend |
| Instantanés : place disque doublée pour les jeux-dossiers | Cache supprimable, taille affichée, limite 4 Gio, question §9.3 |
| Deux zips de même nom (dossiers différents) partagent le même `.pure.zip` | Avertissement de la bibliothèque ; renommer l'un des fichiers |
| VFS : code `unsafe` appelé depuis le thread du core | Aucun état global ni thread-local, `catch_unwind`, revue opus, test multi-thread du core factice ; opt-in par core |
| Programmes DJGPP 32 bits sans `CWSDPMI.EXE` dans le contenu (« no DPMI ») | Documenté dans le guide (fichier à ajouter au jeu par l'utilisateur) |
| Performances sur le Mac Intel | Cycles `auto` (recompilation dynamique x86_64) ; `dosbox_pure_cycles` par jeu |

## 9. Questions pour l'utilisateur (défaut appliqué sans attendre ; recommandation entre parenthèses)

1. **Core** : `dosbox_pure` seul (zip natif, savestates, menu de démarrage, modifications séparées), `dosbox_core` /
   `dosbox_svn` seulement à la main ? (*oui*.)
2. **Choix de l'exécutable** : le menu de démarrage de dosbox_pure (une fois, → pour le mémoriser ; « Changer de
   programme » dans le menu Ctrl droit), plutôt qu'une liste propre à emu-rust ? (*menu du core* ; emu-rust ajoute
   seulement « Lancer un autre programme… » pour les jeux-dossiers.)
3. **Tes jeux DOS** : plutôt en **zip** (aucune copie) ou en **dossiers décompressés** (copie « instantané » dans le
   cache, place disque doublée, pour ne jamais écrire dans tes dossiers) ? CD en ISO / CUE / CHD ? (*instantané
   accepté* ; sinon dis-le : une exception « écrire dans mes dossiers » serait une décision explicite.)
4. **SoundFont GeneralUser GS** (32 Mo, licence libre, téléchargé seulement sur ton action) pour la musique MIDI ?
   (*oui, proposé quand tu choisis MIDI*.)
5. **MT-32 / CM-32L** : possèdes-tu ces ROM (beaucoup de jeux Sierra / LucasArts en profitent) ? Elles s'importeraient
   par « Importer un BIOS… ». (*question d'information*.)
6. **Pavé numérique sur le Razer 60 %** : faut-il une couche « Hôte + N : U I O / J K L / M , ; = 7 8 9 / 4 5 6 /
   1 2 3 » pour les simulateurs, ou le clavier virtuel suffit-il ? (*clavier virtuel en 4.0* ; couche si l'essai le
   demande.)
7. **Disposition clavier DOS** = langue du système (AZERTY ⇒ `fr`), réglable par jeu ? (*oui*.)
8. **Mode d'entrée par défaut** d'un jeu DOS = *Clavier* (comme le ST, décision 2.0), *Joystick* (ZQSD = flèches) par
   Ctrl droit + J ? (*Clavier*.)
9. **Windows 3.x / 95** (installation d'un OS fourni par toi, fonction du core) : hors garantie de la 4.0 ? (*oui, non
   testé*.)
10. **70 images/s** : laisser la cadence native (VGA 70 Hz) ou forcer 60 images/s si l'essai montre des saccades ?
    (*native, 60 par jeu si besoin*.)
