# Version 4.0 — PC-DOS (dosbox_pure) : contrat et découpage

Décisions : **ADR 0018** (statut **accepté** le 2026-11-21, après re-validation contre le code : §10 ; précise 0005,
0013, 0014, 0016). Étude préalable : `docs/essais-dosbox.md`. Base réutilisée : `docs/design/v2.0-atari-st.md` (infrastructure
« ordinateur ») et `docs/design/v3.0-amiga.md` (`MediaRules`, `DatSource::Libretro`, import de BIOS, sélecteur de
fichier, dossier des ROMs, et les **règles communes du §3.5** : ordre d'évaluation des médias, `folder_extensions`,
`game_saves` / `reset_core_game_files`, défauts calculés, contrôle de firmware, notices). Ce document ne donne que le
**delta** par rapport à la 3.0. Les signatures seront **posées dans le code par l'`architecte` au lancement de la
4.0** (tâche DX0), au point **M3** du plan d'harmonie (`docs/design/integration-largeur.md` : crates bas de la 3.0
fusionnés, §3.5 gelé) ; aucune n'est posée aujourd'hui (le code fera alors foi). **Re-validation du 2026-11-21 contre
le code réel (3.0 : X0, R3, B3, A3, F3 ; 2.1 : identité de jeu, Mega CD express) : §10 — en cas de divergence avec
un passage antérieur, le §10 prime.**

Révision du 2026-11-21 (revue croisée) : `reset_core_game_files` / `game_saves` et `folder_extensions` sont **avancés
en 3.0** (la 4.0 n'apporte que des données) ; `layout_option` et `featured_options` par (core, système) sont **posés
ici** ; les règles CD de la bibliothèque (`cue_references`, masquage, pas de hash) sont **avancées de la 6.0 à la
4.0** ; `reset_with_keys` exige `Core::reset_with(handler)` ; `[computer] dos_keyboard_layout` est supprimé.

## 1. Périmètre

| Dans la 4.0 | Plus tard / jamais |
|---|---|
| PC-DOS avec `dosbox_pure` (seul core proposé), Linux / Windows / macOS x86_64 / Docker | `dosbox_core`, `dosbox_svn` (`--core <chemin>` seulement) |
| Contenus : zip / dosz, dossier, exe / com / bat, iso / cue / chd / ins, img / ima / vhd / jrc, m3u / m3u8 | `.conf` comme contenu (refusé) ; `dosbox.conf` interne : option `dosbox_pure_conf` par jeu |
| Fichiers de l'utilisateur jamais modifiés : `.pure.zip` du core, instantané zip des dossiers, copie de travail des images inscriptibles | Partage de sauvegardes entre contenus (`.SAVENAME`, fonction du core, non exposée) |
| Choix de l'exécutable par le menu de démarrage du core (mémorisé par le core), « Changer de programme », lancement d'un `.exe` précis | Sélecteur d'exécutable propre au frontend (ISO / FAT à analyser) |
| Options par jeu, section « Réglages DOS » (`featured_options`) | Préréglages par titre (base de données) |
| MIDI : SoundFont libre GeneralUser GS (facultatif, téléchargé sur action ; **autorisée**, ADR 0005 amendée), MT-32 / CM-32L importés | SC-55 (ROM commerciales sans hash de référence : hors import guidé, dépôt manuel dans `system/`, non vérifié, sans garantie), sortie MIDI vers l'hôte (`GET_MIDI_INTERFACE`) |
| `GET_VFS_INTERFACE` v3 (opt-in par core) | — |
| Clavier PC (disposition DOS calculée par `layout_option`), clavier virtuel `pc.toml` (+ `[remap]` : `<` ⇒ `OEM_102`), mode Joystick 2.0 = flèches | Couche « pavé numérique » sur les lettres (question §9.6) |
| Manette (livrée en 2.1) : axes analogiques (`RETRO_DEVICE_ANALOG`) pour les cores `analog = true` | Lecture de `SET_CONTROLLER_INFO` (type de manette DOS choisi dans le core) |
| Bibliothèque : système `dos`, jeux-dossiers, DAT `dat/DOS.dat` par CRC des entrées ; **règles CD génériques** (`.cue` masquant ses pistes, images CD jamais hashées) ; schéma v5 | TOSEC PC, eXoDOS (écartés, ADR 0018 §9) ; identification Redump des CD (6.0) |
| — | Installation de Windows 3.x / 9x (fonction du core, non testée, OS commercial fourni par l'utilisateur) ; Voodoo matériel (phase 7) ; réseau / modem |

## 2. Fonctionnement

### 2.1 Lancement d'un jeu DOS depuis la bibliothèque

```text
Game (dos) ─ choose_core ─► dosbox_pure (vfs = true ⇒ CoreConfig::provide_vfs)
options : défauts core < cores.toml (dosbox_pure_midi = "disabled") < défauts calculés (layout_option : langue ⇒
          dosbox_pure_keyboard_layout) < [core_options.dosbox_pure] < game-options/dosbox_pure/<jeu>.toml   (3.0 §3.5.4)
selon Game.content / extension :
  zip, dosz, iso, cue, chd, ins ─► ContentSpec::File(chemin)                 (transmis tel quel, block_extract = 1)
  dossier ─► snapshot_status(dir, <cache>/dosbox_pure/<jeu>.zip)
               Current ─► ContentSpec::Folder { dir, name, start: options.dos.start }
               Stale | Missing ─► job « Préparation du jeu… » (snapshot_folder, progression, annulation) ─► idem
  img, ima, vhd, jrc ─► ContentSpec::Media { set, rules: MediaRules { WorkingCopy, media_direct = [zip, dosz, iso, cue, chd, ins] } }
  m3u, m3u8, groupe multi-disques ─► ContentSpec::Media (même règles : CD référencés en absolu, disquettes copiées)
Emulator::load_content ─► core : C: = contenu ; modifications ─► saves/dosbox_pure/<nom>.pure.zip
1er lancement (pas de <nom>.pure.zip) ─► OSD « Menu DOS : ↑ ↓ Entrée · → : lancer automatiquement la prochaine fois »
mode d'entrée initial = Clavier ; souris capturée au premier clic (2.0)
```

`<nom>` = nom du fichier transmis au core sans extension (`Emulator::content_name()`, posé par la 2.1) : nom du zip
de l'utilisateur, ou `save_name` du jeu (identité 2.1) pour un instantané. Le `.pure.zip` est écrit dans
`identity.core_save_dir` : `saves/dosbox_pure/` pour un nom nu, `saves/dosbox_pure/<save_name>/` pour un homonyme.

### 2.2 Changer de programme de démarrage

```text
menu (touche hôte) ─► « Changer de programme de démarrage »
   ─► Emulator::reset_with_keys(&[RetroKey::LSHIFT])   // ─► Core::reset_with(handler) : le core lit Shift dans retro_reset ⇒ menu forcé
   ─► menu du core ; l'utilisateur choisit (→ = nouveau démarrage auto, mémorisé dans AUTOBOOT.DBP du .pure.zip)
fiche du jeu (dossier) ─► « Lancer un autre programme… » ─► root_executables(dir) ─► choix ─► [dos] start = "SETUP.EXE"
   (« pour cette fois » ou « par défaut ») ─► ContentSpec::Folder { start: Some("SETUP.EXE") } ─► <instantané>.zip#SETUP.EXE
```

`AUTOBOOT.DBP` (choix fait dans le core) l'emporte sur `start` : « par défaut » n'est proposé que si le jeu n'a pas
encore de démarrage auto (sinon message « choisi dans le menu DOS : utilisez Changer de programme »).

### 2.3 Réinitialiser les modifications

```text
menu ─► « Réinitialiser les modifications du jeu… » (confirmation : sauvegardes du jeu, SETUP, programme de démarrage,
        correspondances manette perdus) ─► partie arrêtée ─► reset_core_game_files(identity.core_save_dir, content_name,
        game_save_patterns(dosbox_pure)) + reset_work_dir(…) ─► relance      (mécanisme 3.0, §3.5.3 ; identité 2.1)
```

### 2.4 MIDI

```text
Réglages DOS ▸ MIDI = [Aucun ▾ | GeneralUser GS | MT-32 | CM-32L | fichiers .sf2 trouvés]
   valeur absente de la liste du core ─► « Installer GeneralUser GS (32 Mo, licence libre) ? » ─► job FreeBiosManager::install
                                      ─► « Importer des ROM MT-32… » ─► import de BIOS (3.0), noms MT32_*.ROM / CM32L_*.ROM
   après installation / import ─► invalidate_system_caches(system, ["DOSBoxPureMidiCache.txt"]) ─► « Redémarrer le jeu »
   « pour tous les jeux DOS » ─► [core_options.dosbox_pure] dosbox_pure_midi = "GeneralUser-GS.sf2"
```

Les valeurs de `dosbox_pure_midi` sont des chemins relatifs au dossier système (`GeneralUser-GS.sf2`,
`MT32_CONTROL.ROM`), lus dans les options que le core déclare (il les liste par la VFS au chargement).

## 3. Interfaces entre crates (delta 3.0 → 4.0)

### 3.1 `emu-libretro`

```rust
pub struct CoreConfig { …, pub provide_vfs: bool }   // défaut false : 45 | EXPERIMENTAL → false (comportement 3.0)
impl Core { pub fn reset_with(&mut self, handler: &mut dyn FrontendHandler); }   // retro_reset avec gestionnaire installé
// vfs.rs (nouveau, privé) : `retro_vfs_interface` v3 sur std::fs
//   get_path, open, close, size, tell, seek, read, write, flush, remove, rename, truncate, stat, mkdir,
//   opendir, readdir, dirent_get_name, dirent_is_dir, closedir  (19 fonctions `unsafe extern "C"`)
```

Règles : réponse à `GET_VFS_INTERFACE` seulement si `provide_vfs` ; `required_interface_version` > 3 ⇒ `false`,
sinon on écrit la version **3** et le pointeur d'une table `static`. Les fonctions **n'utilisent aucun état
thread-local ni `with_env`** (le core peut les appeler depuis son thread d'émulation) : poignées
`Box<VfsFile { file: File, path: CString }>` et `Box<VfsDir { iter: ReadDir, current: Option<(CString, bool)> }>`,
libérées par `close` / `closedir` ; chemins UTF-8 (refus sinon, `NULL` / `-1`) ; aucun `panic` ne traverse la
frontière (`catch_unwind` ⇒ valeur d'erreur) ; modes d'accès et `stat` (`IS_VALID`, `IS_DIRECTORY`,
`IS_CHARACTER_SPECIAL`) selon `libretro.h` ; `mkdir` : 0, -2 si existe, -1 sinon ; `dirent_get_name` valide jusqu'au
`readdir` suivant ; `opendir(include_hidden = false)` saute les noms commençant par `.`. Aucun privilège nouveau : le
core a déjà accès au système de fichiers par `fopen`.

`Core::reset_with` : le code livré ne peut pas servir `reset_with_keys`. `Core::reset`
(`crates/emu-libretro/src/core.rs`) appelle `retro_reset` **sans** gestionnaire installé, et `with_handler`
(`crates/emu-libretro/src/callbacks.rs`) rend la valeur neutre « hors de `Core::run` » : pendant `retro_reset`,
`input_state(KEYBOARD, LSHIFT)` vaudrait toujours 0. `reset_with` installe le gestionnaire pour la durée de
`retro_reset`, exactement comme `Core::run` (même garde de réentrance, même traitement d'un `panic` du gestionnaire,
gestionnaire retiré à la sortie quel que soit le chemin) ; sans jeu chargé : sans effet ; `Core::reset` est
inchangé. Les callbacks vidéo / audio reçus pendant `retro_reset` suivent le chemin normal du gestionnaire.

### 3.2 `emu-runtime`

```rust
pub enum ContentSpec { …, Folder { dir: PathBuf, name: String, start: Option<String> } }
pub struct EmulatorOptions { …, pub cache_dir: PathBuf }     // <data>/cache ; instantanés dans <cache>/<core_id>/
pub struct SnapshotLimits { pub max_bytes: u64, pub max_files: u32, pub max_depth: u32 }   // 4 Gio, 65 535, 16
impl SnapshotLimits { pub const DEFAULT: Self; }
pub enum SnapshotStatus { Current, Stale, Missing }
pub struct SnapshotReport { pub files: u32, pub bytes: u64, pub rebuilt: bool }
pub fn snapshot_path(cache_core_dir: &Path, name: &str) -> PathBuf;              // <name assaini, sans #>.zip ; name = identity.save_name
pub fn snapshot_status(dir: &Path, snapshot: &Path) -> Result<SnapshotStatus, RuntimeError>;
pub fn snapshot_folder(dir: &Path, snapshot: &Path, limits: &SnapshotLimits,
                       progress: &mut dyn FnMut(u64, u64), cancel: &AtomicBool) -> Result<SnapshotReport, RuntimeError>;
impl Emulator { pub fn reset_with_keys(&mut self, held: &[RetroKey]); }   // `content_name()` existe (2.1) : pas de `core_content_name`
pub enum AnalogStick { Left, Right }
impl PadState { pub fn set_analog(&mut self, stick: AnalogStick, x: i16, y: i16); pub fn analog(&self, stick: AnalogStick) -> (i16, i16) }
RuntimeError += SnapshotTooLarge { limit: u64 }, SnapshotCancelled, UnrepresentableName(PathBuf), InvalidStart(String)
```

Règles :
- **Instantané** : zip **stocké** (crate `zip` déjà présent, Zip64 si besoin), écrit dans `<snapshot>.tmp-*` puis
  renommé avec le manifeste `<snapshot>.manifest` (SHA-256 de la liste triée `chemin relatif \0 taille \0 mtime`) ;
  noms d'entrée = chemins relatifs avec `/`, sans `..`, sans composant vide ni caractère de contrôle (sinon
  `UnrepresentableName`) ; liens symboliques ignorés (ni suivis ni copiés), profondeur et taille bornées **pendant**
  le parcours ; `cancel` vérifié entre deux fichiers (temporaire supprimé) ; le dossier source n'est **jamais ouvert en
  écriture**. `Folder` dont l'instantané n'est pas `Current` : `load_content` le construit (sans progression).
- `start` : non vide, ≤ 12 caractères 8.3, ASCII imprimable sans `/ \ # :` ni espace, extension `exe` / `com` / `bat`,
  présent à la racine de `dir` (casse ignorée) ; sinon `InvalidStart`. Chemin transmis : `<snapshot>.zip#START.EXE`
  (non vérifié comme fichier ; `GameSource::Path`).
- `MediaRules` : ordre d'évaluation du design 3.0 §3.5.1, **inchangé** (extension de `media_direct` avant
  l'inspection des zips : un zip DOS n'est jamais extrait, même s'il contient des images ; un `MediaSet` d'une seule
  image directe = `File`).
- `reset_with_keys` : appelle `Core::reset_with` (§3.1) avec un gestionnaire dont l'état clavier contient les
  touches demandées ; elles sont vues enfoncées par `input_state(KEYBOARD)` **pendant `retro_reset` seulement**
  (état du clavier restauré après) ; aucun événement `send_key_event`.
- `reset_core_game_files` : **posé en 3.0** (design 3.0 §3.5.3), utilisé tel quel avec les motifs de dosbox_pure.
- Analogique : `input_state(ANALOG, index 0/1, id X/Y)` = valeurs de `PadState` (port du pad) ; `INDEX_ANALOG_BUTTON`
  = ±0x7FFF dérivé du bouton numérique ; clavier seul ⇒ 0 (les directions numériques suffisent au core). Les axes ne
  sont remplis que pour un core `analog = true` (ADR 0016 amendée : la conversion stick ⇒ D-pad est alors coupée).

Règles : `Raw` = le fichier téléchargé **est** la variante (taille + SHA-256 de l'archive et de la variante égaux,
`entry` vide — accepté **seulement** pour `format = "raw"` : le code livré refuse une variante sans entrée) ; mêmes
temporaire / renommage / manifeste que la 2.0 ; `FreeBiosState` inchangé.
**Limites par type** : le code livré borne toute archive à `MAX_BIOS_ARCHIVE_BYTES` = 16 Mio et toute image
installée à `MAX_BIOS_IMAGE_BYTES` = **4 Mio** (`crates/emu-assets/src/bios.rs`) : le SoundFont (32 319 396 o) serait
refusé au chargement du catalogue. `kind = "bios"` garde ces deux valeurs ; `kind = "soundfont"` a
`MAX_SOUNDFONT_BYTES` (64 Mio) pour l'archive et pour le fichier ; la taille épinglée de l'entrée reste la borne
effective du téléchargement (lecture en flux, jamais plus que `size` + 1 octets). Une ressource `SoundFont`
n'apparaît jamais dans `check_firmware` ni dans le contrôle `required_firmware` (ce n'est pas un BIOS).
`layout_option` : correspondance par langue exacte puis par langue sans région, sinon `fallback`.
`featured_options` : table par système ; système inconnu ⇒ liste vide. `invalidate_system_caches` : noms simples
(pas de séparateur), seulement à la racine de `system/`.

Règles de scan (système `dos`) :
- **Règles CD génériques (tous systèmes, avant l'attribution d'un système) — déjà livrées par la 2.1 (Mega CD
  express, `emu-library/src/disc.rs` et `scan.rs`), que DB1 généralise sans les réécrire** : tout `.cue` rencontré est lu
  (`cue_references` : lignes `FILE`, fichier ≤ 64 Kio, au plus 99 références, noms absolus ou contenant `..`, `/`, `\` ignorés) et les
  fichiers qu'il référence dans son dossier sont **masqués** : ils ne deviennent un jeu d'aucun système (sans cela
  `jeu.bin` d'un CD DOS est listé en Mega Drive, dont `bin` est une extension) ; compteur `hidden_tracks`. Les
  fichiers d'extension `DISC_EXTENSIONS` et les pistes masquées ne sont **jamais hashés** (centaines de Mo) :
  identification par le nom en 4.0. Un `.cue` hors de tout dossier de système est non classé (3.0 §3.5.2) mais ses
  pistes restent masquées. La 6.0 réutilise ces règles et n'ajoute que Redump, la série et `disc = true`. La sonde
  d'en-tête `SEGADISCSYSTEM` (`disc_info`, 2.1) reste évaluée juste avant « non classé » : §10 n° 7.
- Extensions restreintes au dossier `dos` : `folder_extensions` (champ posé en 3.0) ; `dosz` / `ima` / `jrc` / `m3u8`
  (propres au DOS) sont acceptées partout, et les zips dont une entrée est `.exe` / `.com` / `.bat` suivent la règle
  zip de la 1.0.
- Un sous-dossier (pas la racine `dos` elle-même) dont la racine contient ≥ 1 `.exe` / `.com` / `.bat` est **un jeu**
  (`GameContent::Folder`, chemin = dossier, titre = nom du dossier) ; ses fichiers ne sont pas listés à part ; un
  dossier sans exécutable à sa racine est parcouru normalement (images, zips).
- Exécutables directement dans la racine `dos` : ignorés, comptés dans `ignored_loose_executables`.
- Zip sous un dossier `dos`, ou contenant une entrée `.exe` / `.com` / `.bat` : jeu DOS, **jamais** le refus « Les CD ne se
  lisent pas dans un zip » de la 2.1 (un zip DOS contient souvent son `.iso` / `.cue`, monté par le core) ; ce refus ne
  vaut plus que pour les autres zips (§10 n° 8).
- Zip : **aucune décompression** ; seuls le répertoire central (noms, CRC32, tailles) et la limite d'entrées de la
  1.0 sont appliqués ; pas de refus au-delà de 1 Gio pour `dos` (le contenu n'est pas lu).
- Groupes : règles 2.0 + `(Disc N)`, `(Disc N of M)`, `(CD N)`.
- Identification : `DosFile` = entrées du zip (répertoire central) ou fichiers `exe com bat ima img` de la racine du
  dossier (≤ 64, ≤ 16 Mio, CRC calculé), ou l'image seule (`ima` / `img`). Une ligne du DAT compte si CRC32, taille et
  nom (casse ignorée) concordent ; titre avec le plus de lignes concordantes ⇒ `Unique`, égalité ⇒ `Ambiguous`
  (non identifié, repli sur le nom). ISO / CHD / CUE : nom seulement. Métadonnées `genre`, `releaseyear`,
  `developer` du DAT : ignorées en 4.0 (§10 n° 9).
