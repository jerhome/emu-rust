# Version 7.0 — PlayStation et 3DO (rendu logiciel) : contrat et découpage

Décisions : **ADR 0021** (accepté le 2026-11-21 ; faits vérifiés sur le réseau et par exécution des quatre cores
nightly : son tableau « Contexte » fait foi). Feu vert de l'utilisateur : 2026-11-21. Branche `wip-7.0`, créée depuis
`wip-6.0` (ddc6064 = `v6.0.0-rc.1`) : **tout jusqu'à la 6.0 est livré**, il n'y a plus de travail en largeur.
Base réutilisée sans la redéfinir : 2.0 (`MediaSet`, interface disque), 2.1 (identité de jeu, manette DS4), 3.0
(`MediaRules` / `media_direct`, « Importer un BIOS… », sélecteur « Core utilisé », **règles communes §3.5**), 4.0
(`featured_options`, `analog`, règles CD de la bibliothèque), 6.0 (`DiscRegion`, `DiscFormat`, `disc_info`,
`disc_serial`, `probe_bin`, `Game::region`, `DatSource::Redump`, `SystemInfo::disc`, `firmware_system_for`,
`region_variant`, `firmware_gate`, `plan_disc_launch`, `core_error`, menu « CD », `mkcd.py`), ADR 0022. Ce document
ne donne que le **delta 6.0 → 7.0**. Les signatures sont posées dans le code par la tâche **PX0**.

## 2. Fonctionnement

### 2.1 Lancement

```text
Game (psx) ─ choose_core ─► pcsx_rearmed | swanstation | mednafen_psx      (préférence « Core utilisé », 3.0)
   ─ check_core_firmware(…, système du jeu, variante = région) ─► firmware_gate (6.0, inchangé)
        Ok / Unverified             ─► lancement
        CoreFallback (fichier absent) ─► lancement + avertissement une fois par jeu :
              « scph5502.bin (Europe) absent : le core utilise son BIOS de remplacement, compatibilité réduite. »
              [Importer un BIOS…] [Continuer]      (si un autre fichier de la table est présent : « … le core
              utilisera scph5501.bin. »)
        WrongHash / Unreadable      ─► dialogue générique 6.0 (« Lancer quand même », jamais bloquant)
   ─ carte mémoire : <saves>/<core>/<jeu>.srm absent ─► adopt_family_save (copie de la carte d'un autre core)
   ─ 1 disque  : ContentSpec::File(cue | chd | iso | pbp | bin | m3u)                      (en place)
   ─ N disques : ContentSpec::Media { set, rules: Direct, media_direct } ─► <jeu>.m3u privé ─► disks() (menu « CD »)
   ─ après load_game : set_port_device(0 et 1, identifiant du mode de manette) ; sticks envoyés si mode dualshock
Game (3do) ─ opera ─ check_core_firmware (panafz10.bin ; absent ⇒ CoreFallback : opera_bios = opera-boot-internal,
              même avertissement : « BIOS libre Opera Boot ») ─► ContentSpec::File(cue | chd | iso | bin)
options : défauts cores.toml < défauts calculés (repli de BIOS) < config < jeu ─► core_variables
```

### 2.2 Région et BIOS PlayStation

Région, dans l'ordre : (1) **secteur 4** du disque (texte de licence : `Amer  ica` ⇒ USA, `Euro pe` ⇒ Europe,
`Inc.` ⇒ Japon) ; (2) préfixe de la **série** de `SYSTEM.CNF` (3e lettre : `E` ⇒ Europe, `U` ⇒ USA, `P` ou autre
connue `SLPS` / `SLPM` / `SCPS` / `SIPS` / `PAPX` ⇒ Japon) ; (3) champ `region` du DAT Redump si le jeu est
identifié (`.chd`, `.pbp`) ; (4) étiquette du nom (`region_from_name`) ; (5) inconnue. Calculée au scan
(`game.region`), repli au lancement par `region_variant` (6.0). Région inconnue ⇒ `default = "usa"` et
`variant_known = false` ; avec `fallback = "core"` le résultat n'est jamais bloquant.

Les cores choisissent eux-mêmes parmi les fichiers présents (ADR 0021) : le contrôle sert à **dire** quel fichier
manque et à proposer l'import, pas à forcer un fichier. Aucune option de BIOS n'est posée par le frontend.

### 2.3 Cartes mémoire

- Emplacement 1 = `SAVE_RAM` (128 Kio) pour les trois cores : `<saves>/<core>/<save_name>.srm` écrit par le frontend
  (ADR 0011, identité 2.1 : homonymes séparés). Un jeu à plusieurs CD est **un** jeu (`.m3u`) : une seule carte.
- Emplacement 2 : désactivé par défaut frontend (`pcsx_rearmed_memcard2 = "none"`,
  `beetle_psx_enable_memcard1 = "disabled"` ; swanstation : `None` est déjà son défaut) ; réglable (options mises en
  avant). Activé, le core écrit `pcsx-card2.mcd` (partagée) ou `<jeu>.1.mcr`.
- **Changement de core** : au lancement, si `<saves>/<core>/<save_name>.srm` n'existe pas et qu'un autre core de la
  même `save_family` en a un, il est copié (le plus récent ; jamais d'écrasement ; les originaux restent). Message
  OSD « Carte mémoire reprise de swanstation ». Ensuite chaque core a sa copie : pas de synchronisation.
- 3DO : NVRAM `opera/per_game/<jeu>.<v>.srm` sous `core_save_dir` (défaut du core, conservé). « Réinitialiser les
  sauvegardes du jeu » l'efface grâce au motif à sous-dossier (§3.2). `opera/shared/` n'est jamais effacé.
- États : inchangés (2.1). Tailles constatées : 4,4 Mo (pcsx_rearmed), 11,5 Mo (swanstation), 16 Mo (beetle),
  6,6 Mo (opera).

### 2.4 Manette

Deux modes par core PlayStation (`pad_devices`) : **`digital`** (pad d'origine ; le stick gauche de la DS4 vaut la
croix, conversion 2.1) et **`dualshock`** (sticks transmis en `RETRO_DEVICE_ANALOG`, pas de conversion, L3 / R3).
Mode effectif : jeu (`game-options/<core>/<jeu>.toml`, `[input] pad_device`) > config (`[input.pad_device]
<core> = "…"`) > `default` de `cores.toml` (`digital`). Changé dans le menu en jeu (« Manette : Numérique /
DualShock »), appliqué **à chaud** aux ports 0 et 1 (`set_port_device`), mémorisé pour le jeu. Au clavier le mode
n'a pas d'effet visible (pas de stick). Le raccourci du core « L1 + R1 + Select » (bascule analogique) reste actif.


Sondes (toutes les entrées sont non fiables ; aucune lecture au-delà de la taille du fichier, rien ne panique) :

| Format | Détection | Région | Série |
|---|---|---|---|
| `Opera` | `01 5A 5A 5A 5A 5A 01` à 0 (2048) ou 0x10 (secteur brut) : dans les 0x220 octets déjà lus en 6.0 | aucune (`None`) | aucune |

Règles du scan (delta) :
- **Attribution** (3.0 §3.5.2, ordre inchangé) : dossier `psx/` ou `3do/` d'abord ; hors dossier, la sonde d'en-tête
  (étendue à `Psx` et `Opera`) attribue un `.cue` / `.iso` ; un `.chd` hors dossier est attribué par son nom Redump
  **seulement s'il ne figure que dans un seul des DAT** `megacd` / `psx` / `3do` ; sinon non classé, avec le conseil
  « rangez ce fichier dans `roms/psx/` ». `.pbp` : `psx` partout. `.m3u` : système de ses entrées (inchangé).
- **`.bin`** : `probe_bin` — `PsxTrack` / `OperaTrack` référencée par un `.cue` ⇒ masquée (4.0) ; **non
  référencée ⇒ un jeu** du système (lancé tel quel) ; `SegaCdTrack` orpheline : toujours ignorée (2.1) ; sinon
  règles 6.0 (32X, Mega Drive). Sous `psx/` ou `3do/`, un `.bin` non reconnu n'est pas un jeu Mega Drive : ignoré,
  compté au rapport.
- **Identification** : ordre par format — `Psx` : série (`dat_entry.serial`, comparaison normalisée 6.0 étendue :
  `SLES_000.32` = `SLES-00032`), puis nom ; **jamais de CRC**. `Opera` : taille + CRC32 de la piste 01, seulement si
  la taille figure au DAT, borne **800 Mio** pour ce format (512 Mio inchangés pour `SegaCd`), interruptible, mis en
  cache ; puis nom. `.chd` / `.pbp` : nom.
- **Région** : §2.2 pour `psx` ; `3do` : DAT puis nom. Complétée pour une ligne `disc = true` dont elle est NULL (6.0).
- `group_discs = false` : `(Disc N)` n'est pas regroupé ; chaque disque est un jeu, le suffixe reste dans le nom.
- Fichiers ignorés sans message : `.sbi` (protection LibCrypt : le core le lit à côté de l'image), `.ccd`, `.sub`.
- **Aucune migration** : `SCHEMA_VERSION` reste 6.

  clé statique `analog` (inchangée pour dosbox_pure).
- **Mode de manette** (§2.4) : `EmulatorOptions::port_devices` au lancement ; entrée « Manette » en tête des réglages
  mis en avant d'un core à `pad_devices` ; changement à chaud (`set_port_device` ports 0 et 1 + `set_analog`),
  écrit dans `[input] pad_device` du jeu ; réglage global dans l'écran des réglages de manette. Identifiant refusé
  par le core ⇒ mode numérique + message OSD. CLI : `--pad-device digital|dualshock`.
- **Firmware** : aucun code propre à la PlayStation. `fallback_option` rend `None` pour `FirmwareFallback::Core`.
  Texte de l'avertissement `CoreFallback` généralisé : libellé `builtin_firmware`, nom et région du fichier voulu,
  `others_present` (§2.1) ; « une fois par jeu » = mécanisme AROS (3.0). Dialogue et import inchangés.
- **Carte mémoire** : `adopt_family_save` appelé avant le chargement quand le core a une `save_family` ; OSD.
- **Lancement** : `plan_disc_launch` inchangé pour N disques ; ajoute le refus `ForeignDisc` quand `disc_info` du
  premier fichier désigne un **autre** format connu que celui du système du jeu (un disque PlayStation rangé dans
  `3do/` : opera resterait sur son écran de démarrage, sans erreur). En-tête illisible ⇒ pas de refus.
- **Sélecteur « Core utilisé »** (3.0) : trois cores pour la PlayStation ; choisir un core non installé propose son
  installation (à vérifier par PU2 ; à ajouter sinon). Libellés : « PCSX-ReARMed (rapide, défaut) », « SwanStation
  (rendu logiciel) », « Beetle PSX (précis, plus lent) » — textes de `cores_ui/text.rs`.
- **Menu « CD »** (6.0) et **PS + L3 = disque suivant** étendus à tout système `disc = true` à plusieurs images
  (aujourd'hui : ordinateurs seulement). `.pbp` multi-disque : les images viennent du core (`disks()`).
- Réglages par jeu : sections « PlayStation » et « 3DO » (`featured_options`). Écran Cores : colonne BIOS =
  « recommandé » (PlayStation, 3DO), libellé du remplaçant intégré.
- CLI : `--check-bios` / `--list-bios` couvrent les nouveaux noms ; `--rom x.exe` (PS-EXE) accepté avec `--core`.
- Docs : `docs/guide-essai-7.0.md` (GTA, Road Rash ; `roms/psx/`, `roms/3do/` ; BIOS recommandés ; mode DualShock ;
  cores alternatifs ; limites) ; `docs/bios-utilisateur.md` (PlayStation / 3DO : « recommandé », plus « requis »).

## 7. Risques

| Risque | Atténuation |
|---|---|
| BIOS de remplacement (HLE, OpenBIOS, Opera Boot) incompatible avec un jeu du commerce (GTA, Road Rash) | BIOS de l'utilisateur préféré dès qu'il est présent ; avertissement unique qui propose l'import ; essai PE1 avec et sans |
| Opera Boot très récent (août 2026) ; aucun disque 3DO libre pour le tester | `panafz10.bin` par défaut s'il est là ; `EMU_TEST_3DO_DISC` local ; essai utilisateur ; `opera_bios` mis en avant |
| pcsx_rearmed (recompilateur lightrec) trop lent ou refusé sur le Mac Intel / sous Docker | `pcsx_rearmed_drc` mis en avant ; beetle_psx (interpréteur par défaut) et swanstation en un clic ; à mesurer par PQ3 et PE1 |
| swanstation sans rendu matériel déçoit (pas de mise à l'échelle) | Libellé « rendu logiciel » dans le sélecteur ; rendu matériel = version ultérieure |
| Identifiants de périphérique différents par core, ou changés par un nightly | `pad_devices` par core ; identifiant vérifié contre `controller_types` au lancement ; repli numérique + OSD ; test réel par core |
| Mode numérique par défaut : stick inerte attendu en analogique (ou l'inverse) | Réglage en tête des réglages du jeu, à chaud, mémorisé ; question §9 n° 3 |
| Sonde ISO 9660 sur un disque hostile (LBA énormes, boucles) | Lectures bornées (8 × 2048), tout décalage vérifié contre la taille, racine limitée à 4 secteurs ; revue PV1 |
| Scan lent : CRC de pistes 3DO de plusieurs centaines de Mo | Seulement si la taille figure au DAT ; cache taille + date ; interruptible ; jamais pour la PlayStation |
| `.chd` hors dossier au titre commun à plusieurs machines (Road Rash) | Non classé + conseil de dossier ; guide : « rangez vos CD dans `roms/psx/`, `roms/3do/`, `roms/megacd/` » |
| `.chd` / `.pbp` : région et série inconnues | Nom Redump puis étiquette ; région inconnue non bloquante (`fallback = "core"`) |
| Effacement par motif à sous-dossier (`opera/per_game/`) : surface de suppression élargie | Dossiers littéraux, deux niveaux, liens refusés ; tests ; revue PV1 |
| Deux cartes mémoire qui divergent après un changement de core | Copie une seule fois, annoncée par OSD ; documenté ; question §9 n° 5 |
| Jeux PAL protégés (LibCrypt) sans `.sbi` | Le core lit le `.sbi` voisin de l'image ; mention dans le guide |
| 3DO à plusieurs CD : NVRAM par jeu ⇒ le disque 2 ne voit pas la sauvegarde du disque 1 | `opera_nvram_storage = shared` mis en avant et documenté ; question §9 n° 8 |
| Licence d'opera (non commerciale) et d'OpenBIOS (non sourcée ici) | Usage personnel (ADR 0001) ; rien n'est redistribué ; PV1 établit la licence d'OpenBIOS et ajuste la notice |
| Régression Mega CD / DOS par l'extension des sondes et du scan | Sondes Sega CD évaluées en premier, inchangées ; tests `megacd_scan.rs` et DOS rejoués |

## 9. Questions pour l'utilisateur (défaut appliqué sans attendre ; recommandation entre parenthèses)

Tranché par l'utilisateur : périmètre, pcsx_rearmed par défaut, swanstation et beetle_psx sélectionnables, opera,
BIOS jamais téléchargés, jeux d'essai.

1. **Sans BIOS PlayStation** : les trois cores savent démarrer avec un BIOS de remplacement intégré. Lancer avec un
   avertissement unique, ou refuser tant que ton BIOS n'est pas importé ? (*lancer + avertir* ; ton BIOS est utilisé
   dès qu'il est là.)
2. **3DO** : opera embarque désormais un boot ROM libre (Opera Boot). Utiliser ton `panafz10.bin` quand il est
   présent, Opera Boot sinon ? (*oui* ; Opera Boot est très récent.)
3. **Manette PlayStation par défaut** : pad numérique (le stick gauche fait la croix : pratique pour GTA) ou
   DualShock analogique (le stick ne fait rien dans les jeux numériques) ? (*numérique*, DualShock en un réglage,
   mémorisé par jeu.)
4. **Seconde carte mémoire** : désactivée par défaut ? (*oui* ; une carte par jeu suffit, 15 blocs.)
5. **Changer de core** : reprendre automatiquement la carte mémoire du jeu (copie, une fois) ? (*oui*.)
6. **Tes CD** : `.cue/.bin`, `.chd` ou `.pbp` ? Les `.chd` / `.pbp` ne sont reconnus que par leur nom, et les CD
   doivent être rangés dans `roms/psx/` et `roms/3do/` dès que leur titre existe sur plusieurs machines.
   (*question d'information* ; faut-il accepter aussi `ps1/` et `playstation/` comme noms de dossier ? *non*.)
7. **swanstation en rendu logiciel seulement** (ni haute résolution ni PGXP avant le rendu matériel) : acceptable ?
   (*oui*.)
8. **3DO à plusieurs CD** : un jeu par disque, sauvegarde par disque sauf réglage « NVRAM partagée ». En as-tu ?
   (*laisser ainsi*.)
9. **Vibration** de la manette : plus tard ? (*oui*.)
10. **Touches PlayStation au clavier** : disposition SNES + L2 = P, R2 = M ? (*oui*.)
11. **Premier scan 3DO** : calculer le CRC des pistes (jusqu'à 800 Mo chacune, une seule fois) pour reconnaître les
    jeux, ou se contenter du nom ? (*CRC*, interruptible.)
12. **Ordre de livraison** : PlayStation et 3DO ensemble, 3DO en `rc.2` seulement si elle bloque ? (*ensemble*.)
