# Version 7.1 — Finition de l'interface : contrat et découpage

Décisions : **ADR 0023** (proposé le 2026-11-21). Spécification : `docs/specs/v7.1-v8.0-utilisateur.md` §7.1 (fait
autorité ; d'autres points peuvent suivre : ils s'ajouteront ici). Branche `wip-7.1`, créée depuis `wip-7.0`
(bdf1ccf = `v7.0.0-rc.1`). Base réutilisée sans la redéfinir : identité de jeu 2.1 (`save_name`, registre), règles
de classement 3.0 §3.5.2 (`folder_extensions`), `group_media` (2.0), jeux-dossiers DOS (4.0), `disc_info` /
`cue_references` / `probe_bin` (6.0, 7.0), contrôle de firmware unique et `CoreFallback` (3.0, 7.0), « Importer un
BIOS… » et `open_folder` (3.0), sélecteur de fichiers egui (`file_picker`). Ce document ne donne que le **delta
7.0 → 7.1**. Les signatures sont posées dans le code par la tâche **FX0**, une fois l'ADR acceptée.

## 2. Fonctionnement

### 2.1 Démarrage (console et journal)

```text
main ─ LogBuffer::global() + couche de capture + sortie stderr (comme aujourd'hui)     ← avant toute autre chose
     ─ cli::parse
        sous-commande / --help / --version ─► ensure_console(ParentOnly) ─► sortie dans le terminal appelant
        mode fenêtre (bibliothèque, jeu)    ─► prepare (racine, config)
              ─► ensure_console(if config.interface.console { ParentOrNew } else { ParentOnly })
              ─► LogBuffer::attach_file(<data>/logs/emu-rust.log)   (rotation .1, borne 2 Mio, crochet de panique)
              ─► emu_ui::run / run_library
        erreur fatale avant la fenêtre ─► journal + stderr + fatal_dialog (Windows sans console : MessageBoxW)
```

`ensure_console` ne fait rien hors Windows et rien quand les sorties standard sont déjà valides (redirection). Sous
Linux / macOS le réglage n'existe pas (ADR 0023 §3).

### 2.2 Rangement

```text
Réglages ─ « Créer les dossiers des systèmes » ─► create_system_folders(roms)                 (rien n'est déplacé)
         ─ « Ranger les ROMs… » ─► tâche de fond : Library::plan_tidy ─► TidyPlan
               écran d'aperçu : unités groupées par système de destination ;
                   Sûre (cochée) | Suggérée (décochée, raison) | Ambiguë (liste de systèmes) | Bloquée (raison) | Inconnue
                   total : N fichiers, X Mo, D dossiers créés ; [Ranger] [Annuler]
               [Ranger] ─► tâche de fond : Library::apply_tidy(plan, sélection)   (journal ─ déplacement ─ base, par unité)
                        ─► emu_runtime::relocate_identities(saves, moved)
                        ─► scan incrémental
                        ─► rapport : déplacés / laissés (raison) / échecs ; [Annuler ce rangement] [Ouvrir roms/]
         ─ « Annuler le dernier rangement » (si last_tidy() est annulable) ─► Library::undo_tidy ─► relocate_identities
               (paires inversées) ─► scan incrémental ─► rapport
ouverture de la bibliothèque ─► Library::recover_tidy (journal inachevé) ─► relocate_identities ─► scan au démarrage
```

Le plan porte l'empreinte de l'état analysé (chemin, taille, date de chaque fichier d'une unité) : `apply_tidy`
revérifie chaque unité juste avant de la traiter ; une unité qui a changé depuis l'aperçu est laissée (« modifiée
depuis l'aperçu »). Le plan n'est jamais persisté.

### 2.3 Fichiers d'origine

```text
écran Cores, ligne d'un core installé ─ firmware_enhancements(core, système) ─► pour chaque fichier :
      « scph5502.bin (Europe) — absent. BIOS d'origine : meilleure compatibilité. [Importer un BIOS…] »
lancement d'un jeu ─ firmware_gate (7.0, inchangé) ─ CoreFallback ─► clé "<core>/<fichier>" dans firmware_hints_seen ?
      non ─► dialogue 7.0 (non bloquant) puis clé ajoutée        oui ─► lancement direct
      (un jeu déjà averti en 7.0 — indicateur de game-options — ne déclenche rien et sa clé est ajoutée)
bibliothèque ─ core installé avec optional_firmware absent et clé non vue ─► bandeau d'information refermable
```

Règles : `windows-sys` (features `Win32_System_Console`, `Win32_UI_WindowsAndMessaging`, `Win32_Foundation`) en

`AttachConsole` / `AllocConsole`, `println!` / `eprintln!` doivent écrire dans la console (à prouver par un test
Windows, sinon réouverture de `CONOUT$`). `relocate_identities` : à vérifier contre le code que le `.m3u` privé des
jeux multi-CD (chemins absolus) est bien régénéré à chaque lancement ; sinon il est traité ici aussi.

Règles (ADR 0023 §4, qui fait foi) :

- **Classement** : `plan_tidy` réutilise le classeur du scan (`scan.rs`) avec la règle de dossier neutralisée et
  renvoie **tous** les candidats ; il ne duplique aucune sonde. Hachage borné par `max_file_size` (défaut du scan) ;
  les empreintes déjà en base (ligne inchangée : chemin, taille, date) sont reprises, pas recalculées.
- **Unités** : fichier seul ; groupe `group_media` ; `.cue` + `cue_references` + `.sbi` ; `.m3u` + disques (+ leurs
  pistes) ; jeu-dossier DOS (règle `folder_games` appliquée hors `roms/dos/`, statut `Suggested(DosFolder)`). Un
  fichier appartient à une seule unité (une piste référencée par deux `.cue` ⇒ les deux unités `Blocked`).
- **Destination** : `<id>/<nom>` ; CD à plusieurs fichiers : `<id>/<radical du .cue ou du .m3u>/…` en conservant
  les sous-chemins relatifs référencés ; jeu-dossier : `dos/<dossier>/`.
- **Journal** : `journal-<unix>.txt` dans `journal_dir` ; en-tête `emu-rust tidy 1`, racine `roms` absolue (pour
  information), puis par opération `B <unité>` · `M <n> <de> <vers>` (intention) · `m <n>` (fait) · `D+ <dossier>`
  / `D- <dossier>` (créé / retiré) · `C <unité>` (unité validée en base) ; `E` (fin) ; `U` (annulé). Chemins
  relatifs à `roms_root`, octets échappés (`%XX`) ; `sync_all` après chaque intention. Borne de lecture : 16 Mio.
- **Déplacement** : `symlink_metadata(destination)` doit répondre « absent » ; `rename` ; sur
  `ErrorKind::CrossesDevices` : copie `.emu-rust-part` + `sync_all` + taille et CRC32 + `rename` + suppression de
  la source. Jamais de lien suivi ; mode et dates du fichier conservés autant que la plate-forme le permet.
- **Scan** (filet) : dans la transaction finale, une ligne « disparue » et un fichier « nouveau » de mêmes système,
  taille et (CRC32, SHA1) — ou, sans empreinte, mêmes nom de fichier, taille et date — sont fusionnés : la ligne
  garde son `id` et reçoit le nouveau chemin. Ambiguïté (deux candidats) ⇒ pas de fusion. `ScanReport` gagne
  `pub moved: u64`.
- `relocate` ne crée ni ne supprime de ligne ; chemin de destination déjà en base ⇒ erreur, transaction annulée.
- Aucun `unsafe`. Schéma inchangé (v6) : `SCHEMA_VERSION` ne bouge pas.

## 6. Découpage

Un agent par crate ; codes `F…` (finition). `FX0` pose le contrat (signatures, `todo!()`, clés de config, `pub use`)
pour que le workspace compile ; les tâches d'une même vague sont **parallèles** (crates disjoints).

FB1 + FR1 + FU1 d'abord (chemin critique : FB1 → FU2), puis FA1 + FP1 + FQ1. `emu-ui` n'a jamais deux tâches à la
fois (FU1 puis FU2). FI0 ne bloque que la régénération finale des icônes (FP1, quelques minutes).

### Critères de « terminé » (7.1)

1. Vérification complète du `CLAUDE.md` + `clippy --target x86_64-pc-windows-gnu` ; aucun test réseau.
2. Windows : aucun terminal au lancement par double-clic ; `--version` et `cores list` lisibles depuis PowerShell ;
   `console = true` ⇒ console au démarrage suivant (essai utilisateur).
3. Rangement : l'aller-retour ranger / annuler laisse l'arbre et la base identiques ; aucun test ne montre un
   fichier écrasé, supprimé ou renommé ; favoris, `.srm`, états et options retrouvés après rangement (test réel).
4. Pied de page, Journal, aperçu, rapport, écran Cores : captures Xvfb jointes au guide d'essai.
5. Icône identique sur les trois plates-formes (exe, `.app`, `.desktop`, fenêtre) à partir du seul SVG.
6. `reviewer` : `unsafe` de `console.rs` et `tidy.rs` validés ; rien de téléchargé de nouveau.

## 7. Risques

| Risque | Parade |
|---|---|
| Perte ou mélange de fichiers de l'utilisateur | jamais d'écrasement ni de suppression ; journal avant action ; annulation ; revue dédiée ; tests d'injection de pannes |
| `println!` muet après `AttachConsole` | test Windows en CI ; repli : réouverture de `CONOUT$` dans `console.rs` |
| `rc.exe` absent (compilation croisée) | `build.rs` sans ressource, avertissement, jamais d'échec |
| Rendu SVG différent selon l'outil | fichiers générés commités ; la CI ne compare que l'empreinte du SVG |
| États sauvegardés qui mémorisent le chemin du média | mesuré par FQ2 ; documenté ; l'annulation remet les chemins |
| Analyse lente (gros CD, hachage) | empreintes reprises de la base ; mêmes bornes que le scan ; annulable |
| Jeu-dossier DOS pris à tort (dossier Windows quelconque) | statut « Suggérée », décoché d'office |
