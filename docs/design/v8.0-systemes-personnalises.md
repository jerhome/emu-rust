# Conception 8.0 — systèmes personnalisés (cartouches et fichier unique, rendu logiciel)

Date : 2026-11-25 (architecte). Décisions : **ADR 0025** (proposé), qui fait foi ; étude
`docs/essais-systemes-personnalises.md` (§10 : réponses de l'utilisateur) ; essais `docs/plan-essais-8x-9x.md`.
Branche : `wip-8.0`, créée depuis la tête de la dernière version livrée (`wip-7.2`, ou `wip-7.2.1` si le
glisser-déposer est livré avant), par fusion vers l'aval seulement (`docs/design/integration-largeur.md` §1).
Paliers suivants : 8.1 CD, 8.2 ordinateurs, 8.3 arcade, 9.0 rendu matériel.

## 1. Fonctionnement (parcours de l'utilisateur)

1. Écran Cores → « Vérifier les mises à jour » (existant) → « Ajouter un système non testé… ».
2. Liste filtrée (émulateurs non expérimentaux ; « Tout afficher ») ; recherche par machine ; cores grisés avec
   leur palier (« prévu en 8.1 / 8.3 / 9.0 »).
3. Fiche : machine(s) à cocher (la première cochée), licence, BIOS annoncés, avertissements (expérimental, clavier
   en 8.2, pas d'états sauvegardés). « Ajouter ».
4. Si le core n'est pas dans `cores.toml` et pas encore accepté : avertissement « contenu non vérifié ».
5. Installation (gestionnaire existant) → sonde en processus enfant → définitions écrites → catalogue publié →
   `roms/<id>/` créé → scan incrémental → message « Déposez vos jeux dans `roms/<id>/` » + « Ouvrir le dossier ».
6. Premier lancement d'un jeu : avertissement « non testé » (sauf « Ça marche chez moi »), essai à blanc
   (quelques secondes, barre d'attente annulable), puis la partie. Témoin de lancement, SRAM toutes les 60 s.
7. Réglages → Systèmes personnalisés : nom, extensions, cores, « Chercher la base d'identification », numéros
   ScreenScraper / IGDB, BIOS ignorés, « Recalculer depuis le core », « Supprimer » ; systèmes en erreur ; bascule
   vers un système officiel (bandeau).

## 2. Contrat (interfaces publiques entre crates)

Signatures cibles ; le lot **PX0** les pose avec des corps `todo!()` (ou un comportement neutre quand un appelant
existant passe par là) et `cargo check --workspace` vert. Noms de fichiers indicatifs, à re-valider contre le code
de `wip-8.0` (§8). Tout type public nouveau d'une énumération est `#[non_exhaustive]`.

Règles internes (pas d'API nouvelle) : scan, rangement, import des DAT capturent `catalog()` une fois au départ ;
`attribute` prend le catalogue en paramètre ; une extension d'un système personnalisé est toujours « folder-only » ;
le classement du rangement applique ADR 0025 §12 (candidat personnalisé seulement si l'extension n'appartient à
aucun autre système ; statut Suggérée, raison « système non testé »).

## 3. Données de test (aucune donnée commerciale)

- `.info` synthétiques écrits à la main dans les tests (`emu-assets`) : un core cartouche, un multi-machines
  (3 `database`), un rendu matériel avec `required_hw_api` à trois API, un CD seul, un arcade (`zip` seul), un sans
  `database`, des valeurs parasites (`/`, `.`, `V32`) ; les cas réels relevés par l'étude §2.3 (swanstation,
  puae, mednafen_psx) recopiés en extraits.
- Définitions : fichiers valides, invalides (une par variante de `DefinitionError`), `format = 2`,
  `render = "hardware"`, id = officiel avec et sans même `database`, doublons ; catalogue officiel synthétique
  pour la bascule.
- Core factice (`tests/mock-core/mock_core.c`, `qa-systems`), comportements nouveaux **chacun derrière sa
  variable d'environnement**, comportement par défaut inchangé : `MOCK_HW_RENDER=<ctx>,<maj>,<min>` (demande puis
  échec de `load_game`), `MOCK_HW_FRAME=1` (sentinelle à la 10e image), `MOCK_CRASH_AT_FRAME=<n>` (`abort()`),
  `MOCK_HANG_AT_FRAME=<n>` (boucle), `MOCK_DESCRIPTORS=1` (8 descripteurs, dont un texte de 300 caractères et des
  caractères de contrôle), `MOCK_EXTENSIONS=<liste>`.
- Réel (`#[ignore]`, `platform-build` épingle les SHA-256 dans `scripts/fetch-test-assets.sh`) : deux cores libres
  à rendu logiciel d'un système non officiel (proposés : `stella` pour l'Atari 2600, `mednafen_pce_fast` pour la
  PC Engine ; licences à noter) et pour chacun un homebrew de licence libre explicite (à choisir par
  `platform-build`, licence citée) ; un core à rendu matériel pour le refus (proposé : `flycast`, **sans** contenu).

deux crates différents (comme SB1 ‖ SA1 en 7.2). Un seul worktree (`wip-8.0`) : `cargo` se sérialise sur

**Vagues** : (1) **PX0** ; (2) **PB1** ‖ **PA1** ‖ **PF1** ‖ **PQ1** ‖ **PP1** (crates et fichiers disjoints) ;
(3) **PB2** ‖ **PR1** ‖ **PV0** ; (4) **PU1** (dès PR1, en parallèle de la fin de PB2 : fichiers disjoints) ;
(5) **PU2** ; (6) **PU3** ‖ début de **PQ2** (tests de bibliothèque et du runtime) ; (7) fin de **PQ2** ;
(8) **PV1** → **PP2** → `v8.0.0-rc.1` → **PE1**.

**Chemin critique** : PX0 → PB1 → PB2 → PU2 → PU3 → PQ2 → PV1 → PP2 (9 étapes avec le tag). La branche
PF1 → PR1 → PU1 doit finir avant PU2 ; elle a une étape de marge.

**Parallélisables sans conflit** : PB1 / PA1 / PF1 / PQ1 / PP1 (vague 2) ; PB2 / PR1 / PV0 ; PU1 / fin de PB2.
**En série obligatoire** : tout ce qui touche `emu-ui` (PU1 → PU2 → PU3 : `app.rs`, `lib.rs`, `config.rs`) ;
PB1 → PB2 (même crate).

## 7. Risques

| Risque | Effet | Parade |
|---|---|---|
| Catalogue changé pendant une opération longue | jeux classés sous deux catalogues | instantané capturé au départ ; publication refusée pendant scan / rangement / DAT (PB1, PU2) |
| Régression des 17 systèmes officiels | jeux mal classés, bibliothèque cassée | PB1 seul et sans changement de comportement ; test de non-régression du scan (PB2) ; attentes des tests existants intouchables |
| Id personnalisé = nom de dossier courant dans une racine externe (`games`) | fichiers attribués à tort | ids issus de la table ; signalement du dossier existant à l'ajout ; règle « folder-only » limitée aux extensions du système |
| Un core plante en cours de partie | application fermée | témoin, SRAM 60 s, message au redémarrage ; isolation complète hors 8.0 (ADR 0022) |
| Essai à blanc trompeur (jeu qui exige une touche, plantage tardif) | faux sentiment de sécurité | texte : « l'essai vérifie le démarrage seulement » |
| Enfant d'essai sous macOS (icône du Dock) ou Windows (antivirus) | gêne, essai lent | aucune initialisation de fenêtre dans l'enfant ; délai de 30 s ; essai réel n° 7 |
| `.info` faux (extensions, BIOS requis) | jeux non vus, avertissements inutiles | sonde (le core corrige), « Recalculer », « Ne plus avertir » |
| Core à rendu matériel mal déclaré | écran noir au lieu d'un refus | sentinelle détectée ⇒ `HardwareRenderRequired` |
| Rotation (`SET_ROTATION` non géré) | jeux Lynx verticaux mal orientés | California Games est horizontal (**non vérifié**) ; rotation à prévoir avant d'autres portables |
| BIOS en arborescence (bluemsx) | MSX non démarrable sans copie manuelle | guide d'essai ; repli `fmsx` ; question 8.0-6 |
| Fuite des instantanés | mémoire | quelques Kio par modification ; avertissement au-delà de 1 000 |
| Charge des lots `emu-ui` en série | délai | PU1 sorti de `app.rs` ; tests de bibliothèque de PQ2 avancés |
| Disque (~24 Go libres) | builds en échec | un seul worktree, tests ciblés, `incremental` purgé entre vagues |

## 8. Points à re-valider contre le code de `wip-8.0`

- Chaque agent relit les signatures qu'il remplit (`plan_launch`, `LaunchArgs`, `save_config` après 7.1 / 7.2).
- `CoreManager` garde-t-il tous les `.info` de `info.zip` ou seulement ceux des cores installés ? (PA1 : sinon
  garder `info.zip` en cache et l'analyser à la demande, borne existante de 16 Mio.)
- Clé de `[cores.preferred]` : id de système (commentaire de `config_library.rs`) ou nom de base (commentaire de
  `select.rs`) ; la bascule (ADR 0025 §10) suit la clé réellement utilisée.
- `ScanOptions` construit ailleurs par littéral complet ? (PB2 : `..Default::default()` partout.)
- `Emulator` utilisable sans sortie audio et sans rythme pour `dry_run` (PR1).
- 7.2.1 (glisser-déposer) livré avant la 8.0 ou non : dans les deux cas, ADR 0025 §12 s'impose à sa conception.
