# 7.7 — Archives `.7z` comme les `.zip` (conception)

Décision utilisateur du 2026-11-24 (prévue en 7.5, renumérotée **7.7** le 2026-11-25 à la fusion Mac + PC ; branche
`wip-7.7`, ex-`feat/7.5-7z`). Projet d'ADR : `docs/adr/0027-archives-7z.md` (ex-0023). Rien n'a pu être vérifié hors
ligne (pas de réseau, pas de build) : les points marqués **[V]** sont à vérifier par `reviewer` / `library-assets`.

## 1. Crate

`sevenz-rust2` (Apache-2.0, pur Rust, fork maintenu de `sevenz-rust`). **[V]** : licence exacte et licences des
dépendances (`cargo deny`/`cargo tree`) ; features : garder LZMA, LZMA2, BCJ/delta, PPMd (`ppmd-rust` : vérifier
qu'il est pur Rust, sinon le retirer), Deflate ; **désactiver** chiffrement AES (`aes256`), et tout codec à
dépendance C (zstd, brotli, bzip2 à écarter sauf preuve de pur Rust) ; version récente, dernière release, issues
ouvertes sur panics en entrée corrompue ; absence d'`unsafe` dans le chemin de lecture (sinon : fuzz minimal).
Repli si rejet : `lzma-rs` + parseur d'en-tête maison (hors budget, pas prévu).
Déclaration : `[workspace.dependencies] sevenz-rust2 = { version, default-features = false, features = [...] }`.
Une archive chiffrée (en-tête ou données) est **refusée** avec un message clair, jamais de mot de passe.

## 2. Scan (`emu-library`)

Le 7z stocke un CRC32 par fichier dans l'en-tête, lisible **sans décompresser** (l'en-tête seul est lu ; il est
lui-même LZMA-compressé mais petit). Stratégie à deux niveaux, ADR 0014/0005 :

- Lister entrées (nom, taille, CRC32, dossier/lien/anti-item) : identification par **CRC32 + taille** contre le
  DAT/libretro-database (qui indexe déjà CRC32 ; sinon retomber sur SHA1).
- SHA1 seulement si l'identification CRC32+taille échoue ou si le DAT n'a que SHA1 : décompression d'une seule
  entrée, bornée (`max` existant, annulation par `cancel`), jamais pour toute l'archive solide si évitable.
- CRC absent (entrée sans CRC) : décompression bornée de cette entrée ; archive solide : une seule passe
  séquentielle, entrées inutiles jetées (le solide impose de décoder le bloc jusqu'à l'entrée).
- Bornes : nombre d'entrées (comme zip), taille déclarée par entrée et totale, taille de bloc solide
  (rejeter au-delà de ~512 Mo décompressés au scan), dictionnaire LZMA déclaré (rejeter > 64 Mo : mémoire).
- Refus : CD (cue/bin) dans une archive, comme `CD_IN_ZIP` ; mêmes règles que `analyze_zip`
  (`zip_disk_order`, 32X, `zip_disks`). Refactor : extraire un trait/enum `ArchiveReader` (listing commun
  `ArchiveEntryInfo { name, size, crc32: Option<u32>, is_file }`) pour que `analyze_zip` devienne
  `analyze_archive` sans dupliquer la logique. Table `media`/`zip_media_agrees` : étendre à `.7z`.
- Le scan ne remplit PAS de cache d'extraction (coût disque inutile).

## 3. Lancement (`emu-runtime`)

Même chemin que le zip : `media::zip_images` → `archive_images` (listing par en-tête, filtré par
`zip_entry_accepted` ; liens/dossiers/`..`/chemins absolus/noms à NUL ignorés), `workcopy` extrait vers la copie de
travail (`<work>/<hash>/`), nom de fichier = basename assaini, jamais le chemin de l'archive (zip-slip impossible).

- Archive solide : décoder séquentiellement **une seule fois** pour toutes les entrées voulues (multi-disques :
  une passe, pas N). Le CRC32 stocké est revérifié à l'écriture ; échec = erreur, copie supprimée.
- Bornes : `Limits` existant (taille par entrée, totale, `MAX_COPY_BYTES` 2 Go, ratio de compression max ~ 200:1
  vérifié en cours de flux, pas sur la taille déclarée), mémoire du dictionnaire, annulation coopérative.
- Cache : la copie de travail est déjà persistante (sauvegardes, disquettes ; `MAX_WORK_DIRS` = 64) ; pas de
  second cache. Ajouter : plafond total (défaut **2 Go**, décision utilisateur ; réglable, §9.4) et éviction LRU des dossiers sans écritures
  utilisateur, nettoyage au démarrage des extractions inachevées (`.partial`). Disque presque plein sur le Mac :
  vérifier l'espace libre avant extraction (taille déclarée + marge 10 %), erreur claire sinon.
- Progression : `Progress { done_bytes, total_bytes, entry }` via callback `FnMut` (déjà le modèle `Limits`/
  `cancel`), affichée par l'UI (barre + bouton Annuler) car un solide LZMA2 de 200 Mo dure ~20-40 s sur le Mac ;
  l'extraction tourne hors du thread UI.

## 4. Multi-disques, CD, m3u

- Disquettes (Amiga, CPC, C64, Atari ST…) : même logique que zip (`zip_disk_order`, ≤ 32 images).
- m3u dans le 7z : ignoré comme pour zip ; m3u externe référençant un `.7z` : supporté via le même résolveur.
- CD (cue+bin, iso) dans un 7z : refusé avec le message « décompressez ou convertissez en CHD » (comme zip). Sa
  prise en charge (extraction complète en copie de travail, cue réécrit) est une extension hors 7.7 —
  **remplacé** par la décision de l'utilisateur (fin du document) : extraction proposée, détaillée au §9.3.

## 5. Cores qui lisent le 7z eux-mêmes

puae, VICE (`block_extract = true`) : ADR 0017/0019 ont choisi « le frontend extrait, le core reçoit des images »
pour garder les écritures. Même règle : une archive `.7z` contenant des images acceptées est extraite par le
frontend (ordre d'évaluation du design 3.0 §3.5.1) ; sans image acceptée, transmise telle quelle si le core la lit
(`accepts_ext`) — comportement actuel conservé. Mettre à jour les lignes « `.7z` … direct » des tables 0017/0019
(pas de nouvelle ADR : renvoi vers 0027). Les cores à `block_extract = false` ne voient plus jamais un `.7z`.

## 6. Autres usages du zip

- `emu-assets/cores/archive.rs` : les cores du buildbot sont en `.zip` ; le 7z n'y est PAS ajouté (surface
  d'attaque réseau inutile). Les BIOS libres idem.
- `emu-ui/launch_firmware.rs` : `zip_entry_extensions` → lire aussi les entrées d'un `.7z` (listing d'en-tête).
  API : un seul `emu_library::archive::list_extensions(path)` pour éviter 3 implémentations.
- Placement : la lecture d'archive vit dans `emu-library` (listing + CRC) ; `emu-runtime` ne peut pas en dépendre
  (graphe) → l'extraction a sa propre dépendance `sevenz-rust2` dans `emu-runtime` (déjà le cas de `zip`) ;
  `emu-ui` appelle `emu-library`. Pas de nouveau crate, pas de changement de graphe.

## 9. Effet de la fusion (architecte, 2026-11-25)

La 7.7 part de la base fusionnée (7.5 finition PC, 7.6 rangement). Contrats de référence : ADR 0023 (rangement,
§4), ADR 0024 (CD 32X, amendement de fusion), `docs/design/v7.5-finition-pc.md` (fait foi pour `GameNeeds`,
Journal, `copyable`, `firmware_advice`, `config.toml`), `docs/design/v7.3-refonte.md` (thème). Décisions
d'architecture tranchées ici ; questions produit : `docs/questions-ouvertes.md`, section 7.7.

### 9.1 Rangement des ROMs (7.6, ADR 0023 §4)

- **Unité** : un `.7z` est un « fichier seul » (ligne `.zip` de §4.2), déplacé tel quel vers `roms/<id>/<nom>`.
  Le rangement ne décompresse jamais (§4.1) : rien ne change pour lui, sauf le listing.
- **Système de destination** (§4.3 étape 3, « contenu de l'archive ») : extensions des entrées lues par
  `emu_library::archive::list_extensions` (en-tête seul, §6), la même fonction que le scan et `launch_firmware` ;
  pas de second lecteur dans `tidy`. Un `.7z` chiffré ou illisible : unité **inconnue**, laissée en place.
- **CD archivé** : la sonde d'en-tête (étape 1) demanderait une décompression ; elle n'est pas faite. Le système
  vient des extensions et du nom ; un `.cue` / `.iso` / `.bin` dans l'archive rend l'unité **ambiguë**
  (megacd, psx, 3do) sauf DAT ou nom qui tranche ; jamais « Sûre » par extension seule.
- **Collisions** (§4.4) : taille et CRC32 du fichier `.7z` entier, comme un zip. Aucune règle nouvelle.
- **Copies extraites** : la copie de travail est indexée par l'identité de la source (`ManifestEntry`) ; l'étape (5)
  `relocate_identities` la réécrit pour un `.7z` comme pour un zip, à l'aller et à l'annulation. Le cache
  extrait et les sauvegardes suivent donc le jeu rangé ou ramené. **Aucune ligne de journal nouvelle**, format en
  version 1 ; l'éviction LRU n'est jamais écrite au journal de rangement (elle ne touche pas `roms/`).
- **Exclusion** : une extraction (lancement ou CD proposé) est une tâche de fond au même titre qu'un scan ; le
  rangement est refusé pendant une extraction, et un lancement qui doit extraire est refusé pendant un rangement
  (message « rangement en cours »). Une extraction inachevée (`.partial`) est nettoyée au démarrage **après** la
  reprise d'un journal de rangement (ordre : reprise du journal, puis nettoyage, puis scan).
- **Unités** de taille : les bornes et le plafond sont en octets dans le code, affichés en Mo / Go décimaux comme
  le reste de l'interface (« ≈ 680 Mo ») ; la borne de scan de 512 Mo décompressés reste alignée sur la borne CRC
  Mega CD de **512 Mio** (D8) : même constante `MAX_SCAN_DECODE = 512 * 1024 * 1024`.

### 9.2 Schéma v7

Aucune migration : la base reste en **v7** (colonne `needs_32x` de la 7.4 comprise). `media` et
`zip_media_agrees` acceptent un chemin `.7z` sans colonne nouvelle (le nom `zip_media_agrees` est gardé). Un
`Game` littéral écrit en 7.7 (tests, `tidy`) renseigne `needs_32x` (conflit 2 de la fusion). Une base 7.7 reste
lisible par la 7.4 à la 7.6.

### 9.3 CD 32X (socle Mac) et CD archivés

- **Scan** : un CD dans un zip ou un `.7z` n'est plus refusé (`ZIPPED_DISC` disparaît) : il devient un jeu du
  système deviné, marqué « archivé » par son extension de chemin (pas de colonne). Pas de sonde, pas de CRC de
  piste (le scan ne remplit pas de cache). `needs_32x` = `name_needs_32x` (formes normalisées de la 7.5,
  `(32X)` nu refusé, D9) ou marque manuelle `[library] cd32x`.
- **Lancement** : `LaunchRefusal::ArchivedDisc` est remplacé par une demande `ArchivedDiscOffer { bytes }` (taille
  déclarée de l'archive) que l'UI montre ; après accord, extraction complète dans la copie de travail, `.cue`
  réécrit pour pointer les pistes extraites, puis **sonde `32X Initial Program`** (`disc_needs_32x`) sur la piste
  de données extraite, **avant** `choose_game_core`. `GameNeeds::needs_32x` = colonne ou marque manuelle ou
  sonde ; le résultat de la sonde est écrit dans `game.needs_32x` (nouvelle fonction de `emu-library`,
  `Library::set_needs_32x(game_id, bool)`, à poser par T2). Picodrive absent : message 7.5 inchangé (« picodrive
  requis, jamais de repli sur genesis_plus_gx »).
- La sonde de disque (`SEGADISCSYSTEM`, `disc_info`) et l'identification Redump par piste 01 sont aussi passées
  sur la copie extraite ; elles ne changent jamais le système d'un jeu déjà rangé (règle `known_game`).

### 9.4 Contrat 7.5 (Journal, messages copiables, fichiers d'origine, config)

- **`firmware_advice`** (contrat 7.5 §8) : inchangée ; elle dépend du core, du système et de la variante, pas du
  conteneur. Si la variante dépend des extensions du contenu (`launch_firmware`), elle lit le `.7z` par
  `list_extensions`.
- **Erreurs d'extraction** : un type `ArchiveError` (`emu-runtime`, `#[non_exhaustive]`) — `Encrypted`,
  `TooLarge`, `RatioExceeded`, `DictionaryTooLarge`, `CrcMismatch`, `DiskFull { needed, free }`, `Corrupt`,
  `Cancelled` — converti par `emu-ui` en `UserMessage { what, fix }` (7.3) rendu par `theme::error_box` avec
  `copyable::copy_button` (texte = message + chemin de l'archive). Chaque erreur est aussi écrite au Journal
  (`tracing::error!`, cible `emu_runtime::archive`), donc comptée dans le bouton du pied de page.
  `Cancelled` : `info`, aucun message d'erreur.
- **Réglages** : clé `[library] archive_cache_mb` (défaut 2000, minimum 500) ; absente = défaut ; test
  d'aller-retour avec un `config.toml` 7.4, 7.1.0-rc.1 PC et 7.5 (contrat 7.5 §4).
- **Manuel** (`docs/manuel.md`, embarqué) : paragraphe « Archives `.7z` et CD archivés » (T4).

### 9.5 Thème 7.3

Barre de progression (`ui.add(egui::ProgressBar)` avec les couleurs de `theme::`), bouton « Annuler », dialogue
« Extraire ce CD (≈ N Mo, première fois lente) » : helpers `theme::section_title`, `theme::hint`,
`theme::error_box` ; aucun `Color32::from_rgb` hors `theme.rs`. Captures Xvfb du dialogue et de la barre (T5).

## Décisions de l'utilisateur (2026-11-24, priment sur ce qui précède)

- **CD (cue + pistes) dans un `.zip` ou un `.7z`** (mise en œuvre : §9.3) : ne plus refuser sèchement. Proposer : « Extraire ce CD (≈ N Mo dans le cache, première fois lente) » en exposant le risque (place disque, temps), **ou** annuler avec l'explication « extrayez-le vous-même puis faites le ménage ». Concerne aussi le zip (refus actuel `ZIPPED_DISC` au scan, `LaunchRefusal::ArchivedDisc` au lancement).
- **Cache d'extraction** : **2 Go** par défaut, réglable dans les Réglages, éviction LRU.
- **puae / VICE (Amiga, CPC, C64)** : **emu-rust extrait** l'archive (chemin unique, écritures conservées).
