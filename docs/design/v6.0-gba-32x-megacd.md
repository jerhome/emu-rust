# Version 6.0 — Game Boy Advance, 32X et Mega CD : contrat et découpage

Décisions : **ADR 0020** (statut **accepté** le 2026-11-21, avec ses deux amendements du même jour ; re-validation contre le code : §10). Étude préalable :
`docs/essais-gba-32x-megacd.md`. Périmètre fixé par l'utilisateur le 2026-11-20 : **GBA + 32X + Mega CD**, rendu
logiciel. Suite décidée le même jour : **7.0 = PlayStation + 3DO (rendu logiciel)** ; Saturn, Dreamcast et rendu
matériel (OpenGL, DirectX **et Vulkan**) plus tard — la mention « PS1, Saturn, 3DO non prévus » des premières
versions de ce document est caduque.
Base réutilisée : 1.0 (cores, bibliothèque, jaquettes), 2.0 (`MediaSet`, interface disque, regroupement multi-disques,
options par jeu), 3.0 (`MediaRules` / `media_direct`, « Importer un BIOS… », `DatSource::Libretro`, et les **règles
communes du design 3.0 §3.5** : ordre d'évaluation des médias, **contrôle de firmware unique par variante**,
`game_saves` / `reset_core_game_files`, notices), 4.0 (`featured_options` par (core, système), `(Disc N)`, **règles
CD de la bibliothèque** : `cue_references`, masquage des pistes, images CD jamais hashées). Ce document ne donne que
le **delta** par rapport à la 5.0. Les signatures seront **posées dans le code par l'`architecte` au lancement de la
6.0** (tâche GX0), quand les crates bas de la 5.0 sont fusionnés (plan d'harmonie, `docs/design/integration-largeur.md`).

**Mega CD : reprise et extension du socle livré en 2.1** (« Mega CD express », `docs/design/v2.1-megacd-express.md`,
`v2.1.0-rc.1`). Existent déjà dans le code et **ne sont pas reposés** : système `megacd` (`id`, `database` persistés),
table `[systems."Sega - Mega-CD - Sega CD"]` et `[cores.genesis_plus_gx] options` (RAM par jeu) de `cores.toml`,
`emu-library/src/disc.rs` (`DiscRegion` + `key`, `DiscFormat::SegaCd`, `DiscInfo`, `disc_info`, `region_from_name`,
`cue_references`, `DISC_EXTENSIONS`), masquage des pistes, images CD jamais hashées, piste orpheline ignorée, refus
des CD en zip, dialogue « BIOS Mega CD manquant » (`emu-ui/src/library/megacd.rs`), `tests/tools/mkcd.py`, disque
libre 240p Test Suite. La 6.0 **complète** : Redump et numéro de série, `game.region` (v6), contrôle de firmware
unique par région à la place de `megacd.rs`, erreur du core, multi-CD, `game_saves`, réglages mis en avant.
**Re-validation du 2026-11-21 contre le code réel : §10 — en cas de divergence avec un passage antérieur, le §10
prime.** La 7.0 n'est pas abordée sans le feu vert de l'utilisateur (§8 : pour mémoire seulement).

Ce que la 6.0 pose (`DiscRegion`, `disc_serial`, tables de BIOS par région, Redump) est **générique** : la 7.0 le
réutilise pour la PlayStation (`scph5500` / `5501` / `5502`) et la 3DO sans le modifier.

## 2. Fonctionnement

### 2.1 Lancement

```text
Game (gba)    ─ choose_core ─► mgba            ─ prepare_launch (gba_bios.bin : info seulement) ─► ContentSpec::File(rom|zip)
Game (32x)    ─ choose_core ─► picodrive       ─ (aucun BIOS)                                    ─► ContentSpec::File(rom|zip)
Game (megacd) ─ choose_core ─► genesis_plus_gx ─ check_core_firmware(…, variante = Game::region) ─┐   (contrôle unique, 3.0 §3.5.5 ;
                                                   remplace megacd::bios_verdict de la 2.1 ; région inconnue : §2.2)
     Missing / WrongHash ─► dialogue « BIOS Mega CD manquant : bios_CD_U.bin (Sega CD, USA) »
                            [Importer un BIOS…] [Lancer quand même] [Annuler]
     Ok / Unverified ─► 1 disque  : ContentSpec::File(cue|chd|iso|m3u)    (transmis en place)
                     ─► N disques : ContentSpec::Media { set, rules: MediaRules { Direct, media_direct = [cue, chd, iso] } }
                              ─► <jeu>.m3u généré dans un dossier temporaire privé (chemins absolus ; politique Direct,
                                 3.0 §3.5.1 — jamais dans <saves>/genesis_plus_gx/) ─► disks() (menu Disquettes / CD)
                              ─► (7.0.1, §12) genesis_plus_gx / picodrive : PAS de .m3u ; disque 1 chargé en place,
                                 disques 2..N ajoutés par l'interface disque après retro_load_game
     zip ─► refus avant chargement : « Les CD ne se lisent pas dans un zip : décompressez-le ou convertissez-le en CHD. »
options : défauts cores.toml (genesis_plus_gx_system_bram = "per game") < défauts calculés < config < jeu ─► core_variables
```

`retro_load_game` refusé : `LibretroError::LoadGameFailed { path, core_error }` ⇒ l'UI affiche `core_error` (« Unable
to open CD BIOS: …/bios_CD_U.bin ») au lieu du conseil générique, qui ne s'affiche plus que si `core_error` est vide.

### 2.2 Région et BIOS du Mega CD

Région du jeu, dans l'ordre (règle de la 2.1, constatée sur le core : ADR 0020, amendement du 2026-11-21) :
(1) **en-tête du disque** — `disc_info` : octet 0x20B du secteur 0, `0x64` Europe, `0xA1` Japon, toute autre valeur
USA : c'est exactement le choix du core ; (2) en-tête illisible (`.chd`, fichier absent) : champ `region` du DAT
Redump si le jeu est identifié ; (3) sinon étiquette du nom (`region_from_name`) ; (4) sinon **inconnue**
(`Game::region = None`). La 6.0 la calcule **au scan** et la stocke (`game.region`, v6) au lieu de la sonder à chaque
lancement. BIOS voulu = celui de la région. Si le BIOS de la région manque mais qu'un autre est présent, le dialogue
le dit (« bios_CD_E.bin présent, mais ce jeu est USA ») sans proposer de forcer la région.

**Région inconnue** (un `.chd` sans étiquette) : comportement de la 2.1 conservé — le lancement n'est pas bloqué dès
qu'**un** des fichiers de la table est présent (le core choisira). `check_required` rend alors l'état du fichier
`default` (`usa`) et `others_present` : l'UI ne montre le dialogue que si le fichier voulu est absent **et**
`others_present` est vide (fonction pure `firmware_gate`, §3.5). Sans cette règle un `.chd` européen sans étiquette,
jouable en 2.1 avec le seul `bios_CD_E.bin`, serait refusé en 6.0.

## 3. Interfaces entre crates (delta 5.0 → 6.0)

### 3.1 `emu-libretro`

```rust
pub enum LibretroError { …, LoadGameFailed { path: PathBuf, core_error: Option<String> } }   // remplace LoadGameFailed(PathBuf)
```

Règles : pendant `retro_load_game` seulement, la **dernière** ligne de niveau `RETRO_LOG_ERROR` reçue par
l'interface de log (ADR 0009) est mémorisée ; tronquée à 512 caractères, caractères de contrôle retirés, chemins
laissés tels quels (journal local). Commandes 62 `SET_AUDIO_BUFFER_STATUS_CALLBACK`, 63 `SET_MINIMUM_AUDIO_LATENCY`,
66 `GET_GAME_INFO_EXT` : réponse `false` explicite au niveau `debug`, sans « unhandled » (demandées par mgba /
picodrive, consultatives). 14 `SET_HW_RENDER` reste refusé (aucun core de la 6.0 ne le demande).

### 3.2 `emu-runtime`

Aucune API nouvelle. Vérifications seulement : `MediaRules` avec `Direct` + `media_direct = [cue, chd, iso]`
génère, **dans le dossier temporaire privé** de la politique `Direct`, un `.m3u` de chemins absolus sans rien copier ; audio à 65 536 Hz (mgba) rééchantillonné sans sous-alimentation
(déjà constaté) ; `reset_core_game_files` (3.0) applique les motifs `game_saves` de genesis_plus_gx.

### 3.3 `emu-assets`

**Aucune API nouvelle pour les BIOS** : `RequiredFirmware`, `FirmwareVariant::Region`, `check_required` et
`FirmwareCheck` (avec le `FirmwareState` existant et `others_present`) sont posés en 3.0 (design 3.0 §3.5.5). Il n'y
a **pas** d'énumération `RequirementState` (doublon supprimé) ni de `DiscRegion` dans `emu-assets` : la variante est
une clé de chaîne (`"europe"`, `"usa"`, `"japan"`) que l'UI tire de `Game::region` (`emu-library`, §3.4). La 6.0
ajoute des **données** et une URL :

```rust
// dat.rs
pub const DAT_REDUMP_BASE_URL: &str = "https://raw.githubusercontent.com/libretro/libretro-database/master/metadat/redump/";
```

Le code livré ne connaît que `metadat/no-intro/` et `metadat/tosec/` (`crates/emu-assets/src/dat.rs`) : sans cette
constante le DAT Redump n'est pas téléchargeable. Même hôte, mêmes règles (HTTPS, ETag, taille bornée, écriture
atomique) ; code réseau ⇒ revue GV1.

Rappel des règles du contrôle (3.0) : variante inconnue ⇒ `default` ; le fichier voulu est hashé (md5) et comparé à
`firmware.toml` ; présent sans hash connu ⇒ `Unverified` (pas de blocage) ; lecture bornée (`MAX_FIRMWARE_BYTES`).

### 3.4 `emu-library`

```rust

pub struct SystemInfo { …, pub disc: bool }                  // systems.toml `disc = true` : règles CD propres au système
// disc.rs — EXISTENT depuis la 2.1, inchangés : DiscRegion { Europe, Usa, Japan } + key() ("europe" | "usa" | "japan" =
//   clé de variante du contrôle de firmware), DiscFormat { SegaCd }, DiscInfo { format, region }, disc_info(path),
//   region_from_name(stem), cue_references(cue), DISC_EXTENSIONS. La 6.0 ajoute À CÔTÉ :
pub fn disc_serial(path: &Path, format: DiscFormat) -> Result<Option<String>, LibraryError>;   // cue (piste 01) ou iso ; lecture bornée
```

Règles du scan :

- `.bin` : `probe_bin` — `SEGA 32X` à 0x100 ⇒ `32x` (**nouveau**) ; `SEGADISCSYSTEM` à 0 ou 0x10 ⇒ piste CD, jamais une
  ROM MD, orpheline ⇒ ignorée avec un message au rapport (**déjà livré en 2.1** par `disc_info`) ; sinon règle 1.0.
- `Game::region` : rempli au scan (§2.2). Les lignes `megacd` d'une base v5 ont `region = NULL` et ne sont pas
  ré-analysées tant que taille et date n'ont pas changé : le scan **complète la région d'une ligne de système
  `disc = true` dont elle est NULL** (une sonde de moins de 4 Kio), même « inchangée ». Tant que ce scan n'a pas eu
  lieu, l'UI retombe sur la sonde au lancement (`disc_info`), comme en 2.1.
- Masquage des pistes d'un `.cue`, des entrées d'un `.m3u` et absence de hash des images CD : **règles génériques de
  la 4.0**, inchangées. `disc = true` ajoute pour le système : le jeu porte le nom du `.cue` / `.chd` / `.iso` /
  `.m3u`, identification Redump ci-dessous, libellé « CD » dans l'UI. Regroupement `(Disc N)` / `(CD N)` (4.0).
- Attribution (design 3.0 §3.5.2) : **en place depuis la 4.0** (DB1 : `folder_extensions` sur `megacd` et sonde
  `disc_info` avant « non classé » ; design 4.0 §10 n° 7). La 6.0 ajoute seulement : un `.chd` hors dossier dont le nom
  correspond à une entrée Redump du système est attribué à `megacd` (règle 3 du §3.5.2, par le nom faute de hash).
- Zip de CD : refusé au scan avec le message du §2.1 (**livré en 2.1**, restreint aux zips non DOS par la 4.0) ; inchangé.
- Identification Redump : index `taille de la piste 01 → entrées` ; CRC32 calculé **seulement** si la taille figure
  dans l'index (premier fichier du `.cue`, ou `.iso` entier) ; sinon `disc_serial` (en-tête de type MD à 0x100 du
  secteur 0 : série à 0x180, à confirmer sur le DAT : forme `T-93175`) comparé au champ `serial` ; `.chd` : nom de
  fichier puis rien (lecture CHD reportée). Résultat mis en cache (taille + date) comme les hash 1.0.

### 3.5 `emu-ui` / `emu-app` (agent `ui`)

```rust
pub enum PadStyle { …, Gba }      // from_core_id("mgba") = Gba ; from_extension("gba") = Gba, ("32x") = MegaDrive
impl KeyMap { pub fn gba_default() -> Self }   // A=K, B=J, L=O, R=L, Start=Entrée, Select=Maj droite (= SNES sans X/Y), flèches + ZQSD
pub fn plan_disc_launch(game: &Game, core: &CoreId, prefs: &CorePreferences) -> Result<ContentSpec, LaunchRefusal>;
pub enum LaunchRefusal { ArchivedDisc, … }
// library/firmware_gate.rs (remplace library/megacd.rs de la 2.1 ; pur, testé)
pub(crate) enum FirmwareGate { Launch, WarnOnce, Ask }      // Ask = dialogue générique de firmware requis
pub(crate) fn firmware_gate(check: &FirmwareCheck, variant_known: bool) -> FirmwareGate;   // région inconnue + autre fichier présent ⇒ Launch (§2.2)
```

- Contrôle de firmware unique de la 3.0 (`check_core_firmware`, qui enveloppe `check_required` et `Builtin`), ici avec
  `variant = "region"` : l'UI passe `Game::region.map(DiscRegion::key)` ; dialogue du §2.1 ; « Importer un BIOS… »
  ouvre l'import 3.0 présélectionné sur le nom voulu, puis relance le contrôle. **Reprise du socle 2.1** :
  `library/megacd.rs` (`bios_verdict`, `region_of`, `BIOS_NAMES`) est supprimé, ses tests portés sur `firmware_gate` +
  `check_required` (mêmes cas : présent, absent, autre région, mauvais hash = `Different` ⇒ « Lancer quand même »,
  région inconnue) ; `Dialog::MegaCdBios` devient le dialogue générique (il garde le chemin du dossier `system/`,
  « Copier le chemin » et « Réessayer ») ; `megacd_gate` disparaît de `launch` ; `LaunchRequest::failure_hint` est
  supprimé au profit de `core_error` ; `NO_AUTO_DAT` est supprimé de `library/worker.rs` (Redump téléchargé par la
  boucle par source de la 3.0, qui gagne le bras `DatSource::Redump` ⇒ `DAT_REDUMP_BASE_URL`). Aucun code de contrôle
  propre au Mega CD ne subsiste.
- Erreur de chargement : `core_error` affiché tel quel (OSD + boîte d'erreur), conseil générique sinon.
- Menu **Disquettes / CD** : libellé « CD » pour un système `disc = true`.
- Réglages par jeu : `featured_options(core, système du jeu)` (4.0, données du §3.3) — section « Mega CD » pour un
  jeu `megacd` lancé avec genesis_plus_gx, **rien de tel pour un jeu Mega Drive, Master System ou Game Gear du même
  core** ; « GBA » (mgba) ; « 32X » (picodrive).
- Gestionnaire de cores : colonne « BIOS » du Mega CD = « requis » ; GBA = « facultatif ».
- CLI : `--check-bios` couvre les BIOS requis par système.
- `docs/bios-utilisateur.md` : sections « Mega CD » (requis) et « Game Boy Advance » (facultatif) déjà écrites
  (2026-11-21) ; PlayStation et 3DO y figurent pour la 7.0, la Saturn « plus tard ». GU2 vérifie seulement les noms.
- Manette : mapping `PadStyle::Gba` dans `crates/emu-ui/src/gamepad/mapping.rs` (tâche GU1 ; colonne GBA d'ADR 0016).

## 8. Suite : 7.0 (PlayStation, 3DO) et rendu matériel

**Pour mémoire seulement** (décision de l'utilisateur du 2026-11-21) : la 7.0 **n'est pas abordée** sans son feu vert ;

Décisions de l'utilisateur (2026-11-20, `docs/questions-ouvertes.md`) :

- **7.0 = PlayStation + 3DO, rendu logiciel.** ADR et design dédiés au lancement de la 7.0. Réutilisés sans
  changement : CD de la 4.0 / 6.0 (`media_direct`, `.m3u`, masquage, Redump, `disc_serial` avec de nouvelles sondes),

- **Saturn, Dreamcast, rendu matériel : plus tard.** Quand le rendu matériel sera abordé : **OpenGL, DirectX
  (contexte libretro D3D11 sous Windows) et Vulkan**. Vulkan ne sera pas essayé par l'utilisateur : les **tests
  automatiques sous lavapipe valident les étapes** ; essai réel facultatif par un camarade (à lui rappeler).

Vulkan natif, ce qui rend ces tests logiciels indispensables.

## 12. Correctif 7.0.1 — multi-CD par l'interface disque (ADR 0020, amendement du 2026-11-23)

Cause : `genesis_plus_gx` et `picodrive` préfixent chaque ligne d'un `.m3u` par son dossier ; le `.m3u` de chemins
absolus du §2.1 leur est illisible. Branche `wip-7.0` (base 7.0.1), correctif minimal.

### 12.2 Comportement du runtime avec `MultiDisc::DiskControl`

- `prepare_media` : `policy` doit être `Direct` et `set.playlist` `None`, sinon `InvalidMediaSet` (l'UI n'envoie
  jamais l'un ou l'autre : un `.m3u` utilisateur part en `ContentSpec::File`) ; `launch` déjà refusé
  (`M3uLaunch::None`). Sources traitées comme aujourd'hui (en place, chemins absolus) ; **aucun `write_playlist`** :
  `content` = `images[0]`, `images` = tous les disques ; pas de dossier temporaire si rien n'est extrait.
  Un seul disque : identique à `Playlist`.
- `Emulator::load_as` : après `load_game_from` réussi et avant `restore_sram`, dans la même chaîne d'erreur (le
  core est déchargé avant `prepared` en cas d'échec) : pour `images[1..]`, `add_image()` puis
  `replace_image(num, Some(path))` sur le `DiskControl` d'`emu-libretro`, sans `set_ejected` ; en cas d'échec de
  `replace_image`, `replace_image(num, None)` puis erreur. Pas d'interface disque ⇒ `RuntimeError::NoDiskControl`.
  **Ne pas** passer par `Disks::append` (il bascule le tiroir et ré-ajoute à `prepared.images`).
- `content_name` = radical du disque 1 (dérivé du chemin chargé, sans code nouveau).
