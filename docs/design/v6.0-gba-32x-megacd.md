# Version 6.0 — Game Boy Advance, 32X et Mega CD : contrat et découpage

Décisions : **ADR 0020** (statut proposé — décisions utilisateur du 2026-11-21 intégrées). Étude préalable :
`docs/essais-gba-32x-megacd.md`. Périmètre fixé par l'utilisateur le 2026-11-20 : **GBA + 32X + Mega CD**, rendu
logiciel. Suite décidée le même jour : **7.0 = PlayStation + 3DO (rendu logiciel)** ; Saturn, Dreamcast et rendu
matériel (OpenGL, DirectX **et Vulkan**) plus tard — la mention « PS1, Saturn, 3DO non prévus » des premières
versions de ce document est caduque.
Base réutilisée : 1.0 (cores, bibliothèque, jaquettes), 2.0 (`MediaSet`, interface disque, regroupement multi-disques,
options par jeu), 3.0 (`MediaRules` / `media_direct`, « Importer un BIOS… », `DatSource::Libretro`, et les **règles
communes du design 3.0 §3.5** : ordre d'évaluation des médias, **contrôle de firmware unique par variante**,
`game_saves` / `reset_core_game_files`, notices), 4.0 (`featured_options` par (core, système), `(Disc N)`, **règles
CD de la bibliothèque** : `cue_references`, masquage des pistes, images CD jamais hashées). Ce document ne donne que
le **delta** par rapport à la 5.0. Les signatures seront **posées dans le code par l'`architecte` au lancement de la
6.0** (tâche GX0), une fois la 5.0 intégrée ; aucune n'est posée aujourd'hui (le code fera alors foi).

Ce que la 6.0 pose (`DiscRegion`, `disc_serial`, tables de BIOS par région, Redump) est **générique** : la 7.0 le
réutilise pour la PlayStation (`scph5500` / `5501` / `5502`) et la 3DO sans le modifier.

## 1. Périmètre

| Dans la 6.0 | Plus tard / jamais |
|---|---|
| GBA avec **mgba** (gpsp, vbam en alternatives) ; 32X avec **picodrive** ; Mega CD avec **genesis_plus_gx** (picodrive en alternative) ; Linux / Windows / macOS x86_64 / Docker | **PlayStation et 3DO : version 7.0** (rendu logiciel) ; Saturn, Dreamcast : plus tard ; CD 32X (picodrive, non testé) ; MSU-MD |
| GBA : `.gba` (zip accepté) ; 32X : `.32x`, `.bin` à en-tête `SEGA 32X` (zip extrait comme en 1.0) | GBA e-Reader, câble link, capteur solaire autrement que par l'option du core |
| Mega CD : `.cue` (+ pistes), `.chd`, `.iso`, `.m3u` ; multi-CD par l'interface disque (2.0) | CD dans un zip (refusé avec message) ; `.ccd`, `.mds` (non lus par genesis_plus_gx) |
| BIOS Mega CD **requis**, contrôlés avant lancement, importés par l'utilisateur ; `gba_bios.bin` facultatif | Tout téléchargement de BIOS commercial (jamais) |
| Sauvegardes : `.srm` (GBA, 32X) ; RAM interne Mega CD **par jeu** (`.brm` du core) | Gestionnaire de la RAM de sauvegarde Mega CD (le BIOS en a un) |
| Identification : No-Intro (GBA, 32X), **Redump** (Mega CD : taille + CRC de la piste 01, puis numéro de série) | Lecture du contenu des CHD pour l'identification |
| Pad GBA (`PadStyle::Gba`, clavier **et** manette) ; pad MD 6 boutons pour 32X / Mega CD ; manette DS4 (ADR 0016, livrée en 2.1) | Vibration (GET_RUMBLE_INTERFACE) ; rendu matériel plus tard (OpenGL, DirectX et Vulkan, ce dernier validé par tests lavapipe) |
| Message lisible quand le core refuse un contenu (dernière erreur du core) | — |

## 2. Fonctionnement

### 2.1 Lancement

```text
Game (gba)    ─ choose_core ─► mgba            ─ prepare_launch (gba_bios.bin : info seulement) ─► ContentSpec::File(rom|zip)
Game (32x)    ─ choose_core ─► picodrive       ─ (aucun BIOS)                                    ─► ContentSpec::File(rom|zip)
Game (megacd) ─ choose_core ─► genesis_plus_gx ─ check_required(…, variante = région du jeu) ─┐   (contrôle unique, 3.0 §3.5.5)
     Missing / WrongHash ─► dialogue « BIOS Mega CD manquant : bios_CD_U.bin (Sega CD, USA) »
                            [Importer un BIOS…] [Lancer quand même] [Annuler]
     Ok / Unverified ─► 1 disque  : ContentSpec::File(cue|chd|iso|m3u)    (transmis en place)
                     ─► N disques : ContentSpec::Media { set, rules: MediaRules { Direct, media_direct = [cue, chd, iso] } }
                              ─► <jeu>.m3u généré dans un dossier temporaire privé (chemins absolus ; politique Direct,
                                 3.0 §3.5.1 — jamais dans <saves>/genesis_plus_gx/) ─► disks() (menu Disquettes / CD)
     zip ─► refus avant chargement : « Les CD ne se lisent pas dans un zip : décompressez-le ou convertissez-le en CHD. »
options : défauts cores.toml (genesis_plus_gx_system_bram = "per game") < défauts calculés < config < jeu ─► core_variables
```

`retro_load_game` refusé : `LibretroError::LoadGameFailed { path, core_error }` ⇒ l'UI affiche `core_error` (« Unable
to open CD BIOS: …/bios_CD_U.bin ») au lieu du conseil générique, qui ne s'affiche plus que si `core_error` est vide.

### 2.2 Région et BIOS du Mega CD

Région du jeu : champ `region` du DAT Redump si identifié, sinon étiquette du nom (`(Europe)` → E, `(USA)` → U,
`(Japan)` → J, `(World)` / inconnu → U, comme le core). BIOS voulu = celui de la région. Si le BIOS de la région
manque mais qu'un autre est présent, le dialogue le dit (« bios_CD_E.bin présent, mais ce jeu est USA ») sans
proposer de forcer la région (le core choisit son BIOS d'après le disque).

## 3. Interfaces entre crates (delta 5.0 → 6.0)

### 3.1 `emu-libretro`

```rust
pub enum LibretroError { …, LoadGameFailed { path: PathBuf, core_error: Option<String> } }   // remplace LoadGameFailed(PathBuf)
```

Règles : pendant `retro_load_game` seulement, la **dernière** ligne de niveau `RETRO_LOG_ERROR` reçue par
l'interface de log (ADR 0009) est mémorisée ; tronquée à 512 caractères, caractères de contrôle retirés, chemins
laissés tels quels (journal local). Commandes 62 `SET_AUDIO_BUFFER_STATUS_CALLBACK`, 63 `SET_MINIMUM_AUDIO_LATENCY`,
66 `GET_GAME_INFO_EXT` : réponse `false` explicite au niveau `debug`, sans « unhandled » (demandées par mgba /
picodrive, consultatives). 14 `SET_HW_RENDER` reste refusé (aucun core de la 6.0 ne le demande).

### 3.2 `emu-runtime`

Aucune API nouvelle. Vérifications seulement : `MediaRules` avec `Direct` + `media_direct = [cue, chd, iso]`
génère, **dans le dossier temporaire privé** de la politique `Direct`, un `.m3u` de chemins absolus sans rien copier ; audio à 65 536 Hz (mgba) rééchantillonné sans sous-alimentation
(déjà constaté) ; `reset_core_game_files` (3.0) applique les motifs `game_saves` de genesis_plus_gx.

### 3.3 `emu-assets`

**Aucune API nouvelle pour les BIOS** : `RequiredFirmware`, `FirmwareVariant::Region`, `check_required` et
`FirmwareCheck` (avec le `FirmwareState` existant et `others_present`) sont posés en 3.0 (design 3.0 §3.5.5). Il n'y
a **pas** d'énumération `RequirementState` (doublon supprimé) ni de `DiscRegion` dans `emu-assets` : la variante est
une clé de chaîne (`"europe"`, `"usa"`, `"japan"`) que l'UI tire de `Game::region` (`emu-library`, §3.4). La 6.0
ajoute des **données** et une URL :

```rust
// dat.rs
pub const DAT_REDUMP_BASE_URL: &str = "https://raw.githubusercontent.com/libretro/libretro-database/master/metadat/redump/";
```

Le code livré ne connaît que `metadat/no-intro/` et `metadat/tosec/` (`crates/emu-assets/src/dat.rs`) : sans cette
constante le DAT Redump n'est pas téléchargeable. Même hôte, mêmes règles (HTTPS, ETag, taille bornée, écriture
atomique) ; code réseau ⇒ revue GV1.

Rappel des règles du contrôle (3.0) : variante inconnue ⇒ `default` ; le fichier voulu est hashé (md5) et comparé à
`firmware.toml` ; présent sans hash connu ⇒ `Unverified` (pas de blocage) ; lecture bornée (`MAX_FIRMWARE_BYTES`).

Données (`cores.toml`) :

l'emporte (règle 3.0 : `Builtin` seulement en l'absence de table pour le système). BIOS HLE de mgba : aucun état
particulier (le `.info` déclare `gba_bios.bin` facultatif : contrôle 1.0, sans avertissement) ; statut de licence
des BIOS intégrés : ADR 0020 §2 (à vérifier par GV1).

### 3.4 `emu-library`

```rust
pub enum DatSource { NoIntro, Tosec, Libretro, Redump }     // Redump = metadat/redump/ ; systems.toml : dat = "redump"
pub struct SystemInfo { …, pub disc: bool }                  // systems.toml `disc = true` : règles CD propres au système
pub enum BinKind { MegaDrive, Sega32x, SegaCdTrack, Unknown }
pub fn probe_bin(path: &Path) -> io::Result<BinKind>;        // lit ≤ 0x200 octets
// cue_references : déjà posé en 4.0 (générique)
pub enum DiscRegion { Europe, Usa, Japan }                   // générique (Mega CD, puis PlayStation / 3DO en 7.0)
impl DiscRegion { pub fn key(self) -> &'static str }         // "europe" | "usa" | "japan" = clé de variante du contrôle de firmware
pub enum DiscFormat { SegaCd }                               // 7.0 : + PlayStation, ThreeDo (sondes ajoutées, signature inchangée)
pub fn disc_serial(path: &Path, format: DiscFormat) -> Result<Option<String>, LibraryError>;   // cue (piste 01) ou iso ; lecture bornée
pub struct Game { …, pub region: Option<DiscRegion> }        // DAT `region`, sinon étiquette du nom ; colonne game.region (schéma v6)
SCHEMA_VERSION = 6                                           // migration v5 → v6 : colonne game.region (sans perte)
```

Systèmes (`systems.toml`) — identifiants ScreenScraper / IGDB à revérifier par GB1 :

```toml
[[system]]
id = "gba"
name = "Game Boy Advance"
extensions = ["gba"]
database = "Nintendo - Game Boy Advance"
screenscraper = 12
igdb = 24

[[system]]
id = "32x"
name = "32X"

database = "Sega - 32X"
screenscraper = 19
igdb = 30

[[system]]
id = "megacd"
name = "Mega CD / Sega CD"

folder_extensions = ["cue", "chd", "iso"]   # hors de `megacd/` : seulement si l'en-tête ou Redump l'identifie
database = "Sega - Mega-CD - Sega CD"
dat = "redump"
disc = true
screenscraper = 20

```

Règles du scan :
- `.bin` : `probe_bin` — `SEGA 32X` à 0x100 ⇒ `32x` ; `SEGADISCSYSTEM` à 0 ou 0x10 ⇒ piste CD (jamais une ROM MD ;
  orpheline ⇒ ignorée + compteur « pistes sans .cue ») ; sinon règle 1.0 (Mega Drive).
- Masquage des pistes d'un `.cue`, des entrées d'un `.m3u` et absence de hash des images CD : **règles génériques de
  la 4.0**, inchangées. `disc = true` ajoute pour le système : le jeu porte le nom du `.cue` / `.chd` / `.iso` /
  `.m3u`, identification Redump ci-dessous, libellé « CD » dans l'UI. Regroupement `(Disc N)` / `(CD N)` (4.0).
- Attribution (design 3.0 §3.5.2) : `cue` / `chd` / `iso` sont aussi des extensions de `dos` (restreintes à `dos/`) et
  le seront de la PlayStation et de la 3DO en 7.0. Pour ne pas ranger d'office tout CD en Mega CD : `megacd` les
  déclare en `folder_extensions`, **et** un `.cue` / `.iso` hors dossier dont la piste 01 porte l'en-tête
  `SEGADISCSYSTEM` (`disc_serial` renvoie une série, ou correspondance Redump) est attribué à `megacd` ; sinon non
  classé. Un `.chd` hors dossier est non classé (contenu non lu).
- Zip dans `roms/megacd/` : listé comme « non pris en charge » (non lançable), avec le message du §2.1.
- Identification Redump : index `taille de la piste 01 → entrées` ; CRC32 calculé **seulement** si la taille figure
  dans l'index (premier fichier du `.cue`, ou `.iso` entier) ; sinon `disc_serial` (en-tête de type MD à 0x100 du
  secteur 0 : série à 0x180, à confirmer sur le DAT : forme `T-93175`) comparé au champ `serial` ; `.chd` : nom de
  fichier puis rien (lecture CHD reportée). Résultat mis en cache (taille + date) comme les hash 1.0.

### 3.5 `emu-ui` / `emu-app` (agent `ui`)

```rust
pub enum PadStyle { …, Gba }      // from_core_id("mgba") = Gba ; from_extension("gba") = Gba, ("32x") = MegaDrive
impl KeyMap { pub fn gba_default() -> Self }   // A=K, B=J, L=O, R=L, Start=Entrée, Select=Maj droite (= SNES sans X/Y), flèches + ZQSD
pub fn plan_disc_launch(game: &Game, core: &CoreId, prefs: &CorePreferences) -> Result<ContentSpec, LaunchRefusal>;
pub enum LaunchRefusal { ArchivedDisc, … }
```

- Contrôle de firmware unique de la 3.0 (`check_required`), ici avec `variant = "region"` : l'UI passe
  `Game::region.map(DiscRegion::key)` ; dialogue du §2.1 ; « Importer un BIOS… » ouvre l'import 3.0 présélectionné
  sur le nom voulu, puis relance le contrôle. Aucun code de contrôle propre au Mega CD.
- Erreur de chargement : `core_error` affiché tel quel (OSD + boîte d'erreur), conseil générique sinon.
- Menu **Disquettes / CD** : libellé « CD » pour un système `disc = true`.
- Réglages par jeu : `featured_options(core, système du jeu)` (4.0, données du §3.3) — section « Mega CD » pour un
  jeu `megacd` lancé avec genesis_plus_gx, **rien de tel pour un jeu Mega Drive, Master System ou Game Gear du même
  core** ; « GBA » (mgba) ; « 32X » (picodrive).
- Gestionnaire de cores : colonne « BIOS » du Mega CD = « requis » ; GBA = « facultatif ».
- CLI : `--check-bios` couvre les BIOS requis par système.
- `docs/bios-utilisateur.md` : sections « Mega CD » (requis) et « Game Boy Advance » (facultatif) déjà écrites
  (2026-11-21) ; PlayStation et 3DO y figurent pour la 7.0, la Saturn « plus tard ». GU2 vérifie seulement les noms.
- Manette : mapping `PadStyle::Gba` dans `crates/emu-ui/src/gamepad/mapping.rs` (tâche GU1 ; colonne GBA d'ADR 0016).

## 6. Découpage

Règle (1.0) : une seule instance d'agent par fichier ; un agent par crate ; chaque agent finit avec le workspace vert.
Préalable : **5.0 intégrée** (fichiers partagés : `cores.toml`, `systems.toml`, `scan.rs`, `db.rs`, `dat.rs`, `keyboard.rs`) ;
pour le mapping manette de GU1 : **2.1 livrée** (`gamepad/mapping.rs`).

### Critères de « terminé » (6.0)

- Définition générale de `CLAUDE.md` (fmt, clippy `-D warnings`, tests, aucun réseau réel hors `#[ignore]`, revue).
- Headless, sans BIOS ni ROM commerciale : `hello.gba` et `240pee_mb.gba` reconnus par empreinte ; Mega CD sans

## 7. Risques

| Risque | Atténuation |
|---|---|
| Aucune ROM 32X libre : régression du mode 32X invisible en CI | Essai utilisateur ; picodrive testé en MD (même binaire) ; option yatssd + marsdev (§9.3) |
| Aucun disque Mega CD testable sans BIOS commercial | Test négatif automatisé + `EMU_TEST_MEGACD_BIOS` local (BIOS de l'utilisateur) + essai utilisateur |
| Scan lent sur des dossiers de CD (Go) | CRC seulement si la taille de la piste 01 est au DAT ; cache par taille + date ; aucun hash de CHD |
| `.cue` hostile (chemins `..`, absolus, énorme) | Lecture bornée à 64 Kio ; références hors du dossier jamais suivies par le scan (le core lit le `.cue` lui-même, comme RetroArch) |
| Changement `per bios` → `per game` : l'utilisateur ne retrouve pas d'anciennes sauvegardes `scd_U.brm` | Aucun historique avant la 6.0 ; option par jeu documentée dans le guide |
| mgba sur le Mac Intel (ancien) trop lent | gpsp en alternative (gestionnaire de cores) ; `mgba_idle_optimization` |
| picodrive / genesis_plus_gx non commerciaux | Usage personnel (ADR 0001) ; jamais redistribués ; cités dans le README de release et l'écran Cores |
| Statut de licence des BIOS intégrés (HLE mgba, BIOS 32X picodrive) non sourcé | Règle « Builtin » (ADR 0005) : rien n'est extrait ni redistribué ; vérification confiée à GV1, notice ajustée ensuite |
| CD d'autres machines (DOS, plus tard PlayStation) rangés en Mega CD | `folder_extensions` + sonde d'en-tête `SEGADISCSYSTEM` ; sinon non classé |
| Série Mega CD mal localisée (offset) | GB1 vérifie sur des disques générés et sur le DAT ; repli sur taille + CRC et nom |

## 8. Suite : 7.0 (PlayStation, 3DO) et rendu matériel

Décisions de l'utilisateur (2026-11-20, `docs/questions-ouvertes.md`) :

- **7.0 = PlayStation + 3DO, rendu logiciel.** ADR et design dédiés au lancement de la 7.0. Réutilisés sans
  changement : CD de la 4.0 / 6.0 (`media_direct`, `.m3u`, masquage, Redump, `disc_serial` avec de nouvelles sondes),
  `DiscRegion`, contrôle de firmware par région (données : `scph5500.bin` JP, `scph5501.bin` US, `scph5502.bin` EU ;
  `panafz10.bin`), import de BIOS. Piste notée : pcsx_rearmed (logiciel, BIOS HLE, démarré dans l'étude) ; core 3DO
  à étudier.
- **Saturn, Dreamcast, rendu matériel : plus tard.** Quand le rendu matériel sera abordé : **OpenGL, DirectX
  (contexte libretro D3D11 sous Windows) et Vulkan**. Vulkan ne sera pas essayé par l'utilisateur : les **tests
  automatiques sous lavapipe valident les étapes** ; essai réel facultatif par un camarade (à lui rappeler).

Pistes techniques notées, non décidées (nouvelle ADR le moment venu) : contexte GL unique partagé avec egui (FBO créé
par `emu-runtime`, `get_current_framebuffer`, `get_proc_address` de glutin, `context_reset` après `retro_load_game`,
`context_destroy` avant `retro_deinit`, état GL restauré après `retro_run`) ; profil core 3.3 (4.1 sur macOS) ; tests
sous llvmpipe (GL) et lavapipe (Vulkan) avec un core factice qui dessine ; ni macOS Intel ni WSLg n'ont de pilote
Vulkan natif, ce qui rend ces tests logiciels indispensables.
