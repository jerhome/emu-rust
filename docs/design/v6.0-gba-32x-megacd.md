# Version 6.0 — Game Boy Advance, 32X et Mega CD : contrat et découpage

Décisions : **ADR 0020** (statut proposé). Étude préalable : `docs/essais-gba-32x-megacd.md`. Périmètre fixé par
l'utilisateur le 2026-11-20 : **GBA + 32X + Mega CD**, rendu logiciel ; **PS1, Saturn, 3DO non prévus**.
Base réutilisée : 1.0 (cores, bibliothèque, jaquettes), 2.0 (`MediaSet`, interface disque, regroupement multi-disques,
options par jeu), 3.0 (`MediaRules`, « Importer un BIOS… », `DatSource::Libretro`), 4.0 (`reset_core_game_files`,
`game_saves`, `featured_options`, `(Disc N)`). Ce document ne donne que le **delta** par rapport à la 5.0. Les
signatures seront **posées dans le code par l'`architecte` au lancement de la 6.0** (tâche GX0), une fois la 5.0
intégrée ; aucune n'est posée aujourd'hui (le code fera alors foi).

## 1. Périmètre

| Dans la 6.0 | Plus tard / jamais |
|---|---|
| GBA avec **mgba** (gpsp, vbam en alternatives) ; 32X avec **picodrive** ; Mega CD avec **genesis_plus_gx** (picodrive en alternative) ; Linux / Windows / macOS x86_64 / Docker | PS1, Saturn, 3DO (non prévus) ; CD 32X (picodrive, non testé) ; MSU-MD |
| GBA : `.gba` (zip accepté) ; 32X : `.32x`, `.bin` à en-tête `SEGA 32X` (zip extrait comme en 1.0) | GBA e-Reader, câble link, capteur solaire autrement que par l'option du core |
| Mega CD : `.cue` (+ pistes), `.chd`, `.iso`, `.m3u` ; multi-CD par l'interface disque (2.0) | CD dans un zip (refusé avec message) ; `.ccd`, `.mds` (non lus par genesis_plus_gx) |
| BIOS Mega CD **requis**, contrôlés avant lancement, importés par l'utilisateur ; `gba_bios.bin` facultatif | Tout téléchargement de BIOS commercial (jamais) |
| Sauvegardes : `.srm` (GBA, 32X) ; RAM interne Mega CD **par jeu** (`.brm` du core) | Gestionnaire de la RAM de sauvegarde Mega CD (le BIOS en a un) |
| Identification : No-Intro (GBA, 32X), **Redump** (Mega CD : taille + CRC de la piste 01, puis numéro de série) | Lecture du contenu des CHD pour l'identification |
| Pad GBA (`PadStyle::Gba`) ; pad MD 6 boutons pour 32X / Mega CD ; manette DS4 (ADR 0016) | Vibration (GET_RUMBLE_INTERFACE), rendu matériel, Vulkan |
| Message lisible quand le core refuse un contenu (dernière erreur du core) | — |

## 2. Fonctionnement

### 2.1 Lancement

```text
Game (gba)    ─ choose_core ─► mgba            ─ prepare_launch (gba_bios.bin : info seulement) ─► ContentSpec::File(rom|zip)
Game (32x)    ─ choose_core ─► picodrive       ─ (aucun BIOS)                                    ─► ContentSpec::File(rom|zip)
Game (megacd) ─ choose_core ─► genesis_plus_gx ─ check_required_firmware(région du jeu) ─┐
     Missing / WrongHash ─► dialogue « BIOS Mega CD manquant : bios_CD_U.bin (Sega CD, USA) »
                            [Importer un BIOS…] [Lancer quand même] [Annuler]
     Satisfied ─► 1 disque  : ContentSpec::File(cue|chd|iso|m3u)          (transmis en place)
               ─► N disques : ContentSpec::Media { set, rules: MediaRules { Direct, direct = [cue, chd, iso] } }
                              ─► <saves>/genesis_plus_gx/<jeu>.m3u (chemins absolus) ─► disks() (menu Disquettes / CD)
     zip ─► refus avant chargement : « Les CD ne se lisent pas dans un zip : décompressez-le ou convertissez-le en CHD. »
options : défauts cores.toml (genesis_plus_gx_system_bram = "per game") + options du jeu + config ─► core_variables
```

`retro_load_game` refusé : `LibretroError::LoadGameFailed { path, core_error }` ⇒ l'UI affiche `core_error` (« Unable
to open CD BIOS: …/bios_CD_U.bin ») au lieu du conseil générique, qui ne s'affiche plus que si `core_error` est vide.

### 2.2 Région et BIOS du Mega CD

Région du jeu : champ `region` du DAT Redump si identifié, sinon étiquette du nom (`(Europe)` → E, `(USA)` → U,
`(Japan)` → J, `(World)` / inconnu → U, comme le core). BIOS voulu = celui de la région. Si le BIOS de la région
manque mais qu'un autre est présent, le dialogue le dit (« bios_CD_E.bin présent, mais ce jeu est USA ») sans
proposer de forcer la région (le core choisit son BIOS d'après le disque).

## 3. Interfaces entre crates (delta 5.0 → 6.0)

### 3.1 `emu-libretro`

```rust
pub enum LibretroError { …, LoadGameFailed { path: PathBuf, core_error: Option<String> } }   // remplace LoadGameFailed(PathBuf)
```

Règles : pendant `retro_load_game` seulement, la **dernière** ligne de niveau `RETRO_LOG_ERROR` reçue par
l'interface de log (ADR 0009) est mémorisée ; tronquée à 512 caractères, caractères de contrôle retirés, chemins
laissés tels quels (journal local). Commandes 62 `SET_AUDIO_BUFFER_STATUS_CALLBACK`, 63 `SET_MINIMUM_AUDIO_LATENCY`,
66 `GET_GAME_INFO_EXT` : réponse `false` explicite au niveau `debug`, sans « unhandled » (demandées par mgba /
picodrive, consultatives). 14 `SET_HW_RENDER` reste refusé (aucun core de la 6.0 ne le demande).

### 3.2 `emu-runtime`

Aucune API nouvelle. Vérifications seulement : `MediaRules` avec `Direct` + `direct_extensions = [cue, chd, iso]`
génère un `.m3u` de chemins absolus sans rien copier ; audio à 65 536 Hz (mgba) rééchantillonné sans sous-alimentation
(déjà constaté) ; `reset_core_game_files` (4.0) applique les motifs `game_saves` de genesis_plus_gx.

### 3.3 `emu-assets`

```rust
// cores/select.rs
pub enum DiscRegion { Europe, Usa, Japan }
pub struct RequiredFirmware { pub system: String, pub by_region: Vec<(DiscRegion, String)>, pub default_region: DiscRegion }
impl CorePreferences {
    pub fn required_firmware(&self, core: &CoreId, system: &str) -> Option<&RequiredFirmware>;
}
// cores/firmware.rs
pub enum RequirementState {
    Satisfied { name: String },
    Missing { wanted: String, others_present: Vec<String> },
    WrongHash { name: String, md5: [u8; 16] },
}
pub fn check_required(system_dir: &Path, req: &RequiredFirmware, region: Option<DiscRegion>, known: &KnownFirmware)
    -> Result<RequirementState, FirmwareError>;
```

Règles : `region = None` ⇒ `default_region` ; le fichier voulu est hashé (md5) et comparé à `firmware.toml` ;
présent sans hash connu ⇒ `Satisfied` (règle 1.0 « non vérifiable » : pas de blocage). Lecture bornée
(`MAX_FIRMWARE_BYTES`, 3.0).

Données (`cores.toml`) :

```toml
[systems."Nintendo - Game Boy Advance"]
cores = ["mgba", "gpsp", "vbam"]                  # MPL-2.0, GPL-2.0, GPL-2.0

[systems."Sega - 32X"]
cores = ["picodrive"]                             # MAME (non commerciale)

[systems."Sega - Mega-CD - Sega CD"]
cores = ["genesis_plus_gx", "picodrive"]          # non commerciale, MAME (non commerciale)

[cores.genesis_plus_gx]                           # table existante : on ajoute
options = { genesis_plus_gx_system_bram = "per game" }   # sans effet hors Mega CD
game_saves = ["{game}.brm", "{game}_*_cart.brm"]
media_direct = ["cue", "chd", "iso"]
[cores.genesis_plus_gx.required_firmware."Sega - Mega-CD - Sega CD"]
europe = "bios_CD_E.bin"
usa = "bios_CD_U.bin"
japan = "bios_CD_J.bin"
default = "usa"

[cores.picodrive]
media_direct = ["cue", "chd", "iso"]
[cores.picodrive.required_firmware."Sega - Mega-CD - Sega CD"]   # mêmes noms que genesis_plus_gx
europe = "bios_CD_E.bin"
usa = "bios_CD_U.bin"
japan = "bios_CD_J.bin"

```

`firmware.toml` : `gba_bios.bin` et `bios_CD_{E,U,J}.bin` y sont déjà (md5 d'ADR 0020) ; rien à ajouter.

### 3.4 `emu-library`

```rust
pub enum DatSource { NoIntro, Tosec, Libretro, Redump }     // Redump = metadat/redump/ ; systems.toml : dat = "redump"
pub struct SystemInfo { …, pub disc: bool }                  // systems.toml `disc = true` : règles CD du scan
pub enum BinKind { MegaDrive, Sega32x, SegaCdTrack, Unknown }
pub fn probe_bin(path: &Path) -> io::Result<BinKind>;        // lit ≤ 0x200 octets
pub fn cue_references(cue: &Path) -> Result<Vec<PathBuf>, LibraryError>;   // FILE "…" ; ≤ 64 Kio
pub fn disc_serial(path: &Path) -> Result<Option<String>, LibraryError>;   // cue (piste 01) ou iso
pub struct Game { …, pub region: Option<String> }            // DAT `region`, sinon étiquette du nom
```

Systèmes (`systems.toml`) — identifiants ScreenScraper / IGDB à revérifier par GB1 :

```toml
[[system]]
id = "gba"
name = "Game Boy Advance"
extensions = ["gba"]
database = "Nintendo - Game Boy Advance"
screenscraper = 12
igdb = 24

[[system]]
id = "32x"
name = "32X"
extensions = ["32x"]                       # + .bin si probe_bin = Sega32x
database = "Sega - 32X"
screenscraper = 19
igdb = 30

[[system]]
id = "megacd"
name = "Mega CD / Sega CD"
extensions = ["cue", "chd", "iso", "m3u"]
database = "Sega - Mega-CD - Sega CD"
dat = "redump"
disc = true
screenscraper = 20
igdb = 78
```

Règles du scan :
- `.bin` : `probe_bin` — `SEGA 32X` à 0x100 ⇒ `32x` ; `SEGADISCSYSTEM` à 0 ou 0x10 ⇒ piste CD (jamais une ROM MD ;
  orpheline ⇒ ignorée + compteur « pistes sans .cue ») ; sinon règle 1.0 (Mega Drive).
- `disc = true` : chaque `.cue` est lu, ses fichiers référencés sont **masqués** ; références absolues ou avec `..`
  ignorées (le `.cue` reste listé, le core décidera) ; un `.m3u` masque ses entrées. Le jeu porte le nom du `.cue`
  / `.chd` / `.iso` / `.m3u`. Regroupement `(Disc N)` / `(CD N)` (4.0).
- Zip dans `roms/megacd/` : listé comme « non pris en charge » (non lançable), avec le message du §2.1.
- Identification Redump : index `taille de la piste 01 → entrées` ; CRC32 calculé **seulement** si la taille figure
  dans l'index (premier fichier du `.cue`, ou `.iso` entier) ; sinon `disc_serial` (en-tête de type MD à 0x100 du
  secteur 0 : série à 0x180, à confirmer sur le DAT : forme `T-93175`) comparé au champ `serial` ; `.chd` : nom de
  fichier puis rien (lecture CHD reportée). Résultat mis en cache (taille + date) comme les hash 1.0.

### 3.5 `emu-ui` / `emu-app` (agent `ui`)

```rust
pub enum PadStyle { …, Gba }      // from_core_id("mgba") = Gba ; from_extension("gba") = Gba, ("32x") = MegaDrive
impl KeyMap { pub fn gba_default() -> Self }   // A=K, B=J, L=O, R=L, Start=Entrée, Select=Maj droite (= SNES sans X/Y), flèches + ZQSD
pub fn plan_disc_launch(game: &Game, core: &CoreId, prefs: &CorePreferences) -> Result<ContentSpec, LaunchRefusal>;
pub enum LaunchRefusal { ArchivedDisc, … }
```

- Contrôle `check_required` avant tout lancement d'un système qui a un `required_firmware` ; dialogue du §2.1 ;
  « Importer un BIOS… » ouvre l'import 3.0 présélectionné sur le nom voulu, puis relance le contrôle.
- Erreur de chargement : `core_error` affiché tel quel (OSD + boîte d'erreur), conseil générique sinon.
- Menu **Disquettes / CD** : libellé « CD » pour un système `disc = true`.
- Réglages par jeu : section « Mega CD » (`featured_options` : `genesis_plus_gx_system_bram`,
  `genesis_plus_gx_cart_bram`, `genesis_plus_gx_cart_size`, `genesis_plus_gx_cdda_volume`) ; « GBA » (`mgba_use_bios`,
  `mgba_skip_bios`, `mgba_color_correction`, `mgba_interframe_blending`, `mgba_solar_sensor_level`) ; « 32X »
  (`picodrive_input1`, `picodrive_drc`, `picodrive_region`, `picodrive_aspect`).
- Gestionnaire de cores : colonne « BIOS » du Mega CD = « requis » ; GBA = « facultatif ».
- CLI : `--check-bios` couvre les BIOS requis par système.
- `docs/bios-utilisateur.md` : section « 6.0 » (GBA facultatif, Mega CD requis), la ligne « phase 7 » devient
  « non prévu » (PS1, Saturn, 3DO).

### Critères de « terminé » (6.0)

- Définition générale de `CLAUDE.md` (fmt, clippy `-D warnings`, tests, aucun réseau réel hors `#[ignore]`, revue).
- Headless, sans BIOS ni ROM commerciale : `hello.gba` et `240pee_mb.gba` reconnus par empreinte ; Mega CD sans
  BIOS ⇒ contrôle préalable `Missing` **et** message du core affiché ; scan d'un dossier CD généré : pistes masquées,
  multi-CD regroupé, zip non lançable.
- Aucun fichier de l'utilisateur modifié (hash des `.cue` / `.bin` / `.chd` avant / après une session).
- Un `config.toml` 5.0 est relu sans changement ; MD / SMS / GG avec genesis_plus_gx se comportent comme en 1.0
  (`per game` n'affecte que le CD).
- Essai utilisateur (GE1) : les jeux du tableau ci-dessus, au clavier et à la manette DS4 si la phase 6 est livrée.

## 7. Risques

| Risque | Atténuation |
|---|---|
| Aucune ROM 32X libre : régression du mode 32X invisible en CI | Essai utilisateur ; picodrive testé en MD (même binaire) ; option yatssd + marsdev (§9.3) |
| Aucun disque Mega CD testable sans BIOS commercial | Test négatif automatisé + `EMU_TEST_MEGACD_BIOS` local (BIOS de l'utilisateur) + essai utilisateur |
| Scan lent sur des dossiers de CD (Go) | CRC seulement si la taille de la piste 01 est au DAT ; cache par taille + date ; aucun hash de CHD |
| `.cue` hostile (chemins `..`, absolus, énorme) | Lecture bornée à 64 Kio ; références hors du dossier jamais suivies par le scan (le core lit le `.cue` lui-même, comme RetroArch) |
| Changement `per bios` → `per game` : l'utilisateur ne retrouve pas d'anciennes sauvegardes `scd_U.brm` | Aucun historique avant la 6.0 ; option par jeu documentée dans le guide |
| mgba sur le Mac Intel (ancien) trop lent | gpsp en alternative (gestionnaire de cores) ; `mgba_idle_optimization` |
| picodrive / genesis_plus_gx non commerciaux | Usage personnel (ADR 0001) ; jamais redistribués ; cités dans `THIRD-PARTY-DATA.txt` |
| Série Mega CD mal localisée (offset) | GB1 vérifie sur des disques générés et sur le DAT ; repli sur taille + CRC et nom |

## 8. Hors périmètre : rendu matériel (PS1, Saturn, 3DO)

Non prévus (décision du 2026-11-20). Si un jour demandés : nouvelle ADR. Pistes notées : pcsx_rearmed d'abord

## 9. Questions pour l'utilisateur (défaut appliqué sans attendre ; recommandation entre parenthèses)

1. **Cores** : mgba (GBA), picodrive (32X), genesis_plus_gx (Mega CD) par défaut ; gpsp / picodrive en alternatives
   dans le gestionnaire ? (*oui*.)
2. **RAM de sauvegarde Mega CD** : une par jeu (pratique, la RAM de la console est minuscule) ou une par région comme
   la vraie console ? (*par jeu*, réglable par jeu.)
3. **Test 32X** : se contenter de ton essai avec tes ROM, ou construire une démo libre (yatssd, MIT) dans l'image de
   build avec la toolchain marsdev (≈ 100 Mo de plus, à épingler) pour un test automatique ? (*ton essai seulement* ;
   la démo si une régression 32X apparaît.)
4. **Tes CD Mega CD** : plutôt en `.cue/.bin` ou en `.chd` ? As-tu des jeux à plusieurs CD ? Les CD en zip ne seront
   pas lus (décompresser ou convertir en CHD avec `chdman`). (*CHD conseillé* : un fichier par disque, plus petit.)
5. **BIOS Mega CD** : quelles régions possèdes-tu (E / U / J) ? Un jeu d'une autre région refusera de démarrer sans le
   BIOS correspondant. (*question d'information*.)

7. **Ordre de livraison** : tout en une pré-release, ou GBA + 32X d'abord puis Mega CD ? (*tout ensemble*, Mega CD
   en second seulement s'il bloque.)
