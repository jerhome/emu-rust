# Version 2.0 — Atari ST et infrastructure « ordinateur » : contrat et découpage

Décisions : **ADR 0015** (précise 0003, 0005, 0006, 0011, 0013, 0014). Étude préalable : `docs/essais-hatari.md`.
Manette (chantier parallèle) : ADR 0016, `docs/design/phase6-manette.md` (§8 ci-dessous).
Signatures **posées dans le code** (corps `todo!()`, le code fait foi en cas d'écart) :
`crates/emu-libretro/src/{keyboard,disk}.rs`, `crates/emu-runtime/src/{input,media}.rs`, `crates/emu-assets/src/bios.rs`.
Celles d'`emu-library`, `emu-ui` et `emu-app` sont données ici (§3.4, §4), à poser par leurs agents.

## 1. Périmètre

| Dans la 2.0 | Plus tard |
|---|---|
| Atari ST avec `hatari` (recommandé) et `hatarib` (alternative), Linux / Windows / macOS x86_64 / Docker | Amiga (3.0), DOS (4.0) : réutilisent tout |

## 2. Fonctionnement

### 2.1 Lancement d'un jeu ST depuis la bibliothèque

```text
Game (atarist, media = [d1, d2]) ─ choose_core ─► hatari ─ prepare_launch (BIOS) ─┐
   tos.img absent ─► dialogue « Installer EmuTOS (GPL-2.0, ~2 Mo, SourceForge) ? [langue ▾] » ─► job FreeBiosManager::install
   tos.img = EmuTOS ─► FirmwareState::Free (pas d'avertissement) ; TOS utilisateur ─► Ok / WrongHash comme en 1.0
options du jeu (game-options/hatari/<jeu>.toml) + défauts cores.toml + config ─► core_variables
Emulator::load_content(core, ContentSpec::Media { set: {name, images: [d1, d2], playlist}, policy: WorkingCopy })
   ─► Core::load ─► prepare_media (copies dans saves/hatari/<jeu>.disks/, <jeu>.m3u) ─► load_game(<jeu>.m3u)
   ─► (si last_disk) disks().insert(last_disk)
mode clavier initial = options du jeu, sinon « joystick » ; OSD « Ctrl droit : menu · Ctrl droit + J : clavier ST »
```

Entrée « Bureau Atari ST » (bibliothèque, système `atarist`) : `ContentSpec::NoGame`, mode *Clavier*.

### 2.2 Entrées, image par image (thread unique, ADR 0010)

```text
winit (KeyboardInput, MouseInput, CursorMoved, DeviceEvent::MouseMotion, MouseWheel)
  └─► emu-ui::computer::InputRouter ── touche hôte ? ─► HotkeyAction (menu, K, M, J, D, S, L…)
        │ mode Joystick + touche du KeyMap ─► KeyboardInput (1.0, pads)
        └─► ComputerKeyboard (état + file d'événements) ; ComputerMouse (deltas, boutons) ; VirtualKeyboard (egui)
InputBackend::poll(frame, &mut InputFrame)   // OU des pads, OU des touches, somme des deltas, concaténation des événements
Emulator::run_frame : 1) send_key_event pour chaque InputFrame::key_events (hors retro_run)
                      2) retro_run ; input_state(KEYBOARD, id) = keyboard.is_pressed ; (MOUSE, X/Y) = deltas de l'image
```

### 2.3 Touche hôte (ADR 0015 §4)

Machine à états dans `emu-ui` (pure, testée) : `Idle` → hôte enfoncé → `HostHeld { used: false }` ; autre touche
pendant `HostHeld` ⇒ action, `used = true`, la touche n'atteint pas le core (ni à l'appui ni au relâchement) ;
relâchement de l'hôte avec `used == false` ⇒ `HotkeyAction::Menu`. Perte de focus ⇒ `Idle` et `release_all`.
Pour les systèmes `console`, la touche hôte agit comme Ctrl (raccourcis Ctrl de la 1.0) et Échap reste le menu.

| Hôte + | Action (`HotkeyAction`) | Existant ? |
|---|---|---|
| (seul) | `Menu` | oui |
| S / L | `SaveState` / `LoadState` | oui |
| `,` / `.` | `PrevSlot` / `NextSlot` | oui |
| R / P / F / I | `Reset` / `Pause` / `ToggleFullscreen` / `ToggleStats` | oui |
| Espace (maintenu) | avance rapide | oui |
| K | `ToggleVirtualKeyboard` | **nouveau** |
| M | `ToggleMouseCapture` | **nouveau** |
| J | `ToggleKeyboardMode` | **nouveau** |
| D | `NextDisk` | **nouveau** |

Environnement : 12 (`SET_KEYBOARD_CALLBACK`, conserve le pointeur), 13 et 58 (copie des pointeurs de fonctions),
57 (`GET_DISK_CONTROL_INTERFACE_VERSION` → 1), `GET_INPUT_DEVICE_CAPABILITIES` (24) → joypad | souris | clavier,

Règles : `Emulator::load` = `load_content(…, ContentSpec::File(rom), …)` (comportement 1.0 inchangé, y compris zips).
`prepare_media` : copie seulement si la copie de travail est absente ; zip → entrées dont l'extension est acceptée par
le **binaire** (pas le `.info`), noms assainis par `fsname`, limites de `content.rs` ; `.m3u` généré écrit par
`write_atomic`, une entrée relative par ligne ; jamais d'écriture hors de `saves_core_dir/<jeu>.disks/` (ou du dossier
temporaire privé en `Direct`) ; un `.m3u` utilisateur en `WorkingCopy` est relu et ses images copiées (chemins
absolus ou relatifs au `.m3u`, `..` refusé). Souris : deltas remis à zéro après `retro_run`, constants pendant l'image.
`ScriptedInput` gagne `key(RetroKey, Range<u64>)` (état + événements d'appui / relâchement aux bornes) et
`mouse(dx, dy, buttons, Range<u64>)` (tests headless). `Disks::insert` : `set_ejected(true)` → `set_image_index` → `set_ejected(false)` ; erreurs du core
remontées telles quelles, état précédent restauré si possible.

## 7. Découpage

Règle (1.0) : une seule instance d'agent par fichier ; un agent par crate ; chaque agent finit avec le workspace vert.

| Tâche | Agent (modèle) | Fichiers | Dépend de |
|---|---|---|---|
| **F1** FFI clavier, disques, sans contenu | `libretro-ffi` (**opus** : `unsafe`, pointeurs de callbacks) | `crates/emu-libretro/src/{keyboard,disk,callbacks,core,sys,error}.rs` | contrat (fait) |
| **R1** Entrées et médias | `runtime-av` (**opus** : copies atomiques, zips non fiables) | `crates/emu-runtime/src/{input,media,emulator,content,error,lib}.rs` | F1 (exécution ; compile dès maintenant contre les stubs) |
| **A1** BIOS libre, cores ST | `library-assets` (**opus** : réseau, archives) | `crates/emu-assets/src/bios.rs`, `data/{free_bios,cores}.toml`, `src/cores/{select,firmware}.rs`, `src/dat.rs`, `Cargo.toml` | contrat (fait) |
| **B1** Bibliothèque ST | `library-assets` (sonnet ; 2e instance, autre crate) | `crates/emu-library/src/{systems,scan,db,lib}.rs`, `data/systems.toml` | — |
| **U1** Logique ordinateur (pure) | `ui` (sonnet) | `crates/emu-ui/src/computer/{keymap,host,input}.rs`, `config_computer.rs`, `game_options.rs`, `hotkeys.rs` (nouvelles actions), `Cargo.toml` (`sys-locale`) | contrat ; R1 pour les types réels (compile contre les stubs) |

| **P1** Plate-forme | `platform-build` (sonnet) | `scripts/fetch-test-assets.sh` (hatari, EmuTOS, Nova Defense, `mkst.py`), `docker/entrypoint.sh` (`game-options/`), README de release et `docker/README.md` (Atari ST, EmuTOS, touche hôte, souris sous noVNC), `about.toml` si `sys-locale` l'exige | — |

Vagues (≤ 3 agents en parallèle) :
1. **F1** ‖ **A1** ‖ **Q1** (puis **B1** et **P1** dès qu'une place se libère : ils ne bloquent personne) ;
2. **R1** ‖ **U1** ‖ B1/P1 restants ;
3. **U2** (seul sur `app.rs` / `config.rs`) ‖ **Q2** (parties FFI / runtime / BIOS) ;
4. Q2 (parties UI, réel) → **Q3** → **V1** → pré-release `v2.0.0-rc.1` → **E1**.

Un besoin hors périmètre (ex. U2 veut une méthode de `Disks`) repasse par l'`architecte`.

### Critères de « terminé » (2.0)

- Définition générale de `CLAUDE.md` (fmt, clippy `-D warnings`, tests, aucun réseau réel hors `#[ignore]`, revue).
- Headless : bureau EmuTOS et Nova Defense reconnus par empreinte ; clavier, souris et changement de disquette
  vérifiés sur le core réel (`#[ignore]`) et sur le core factice (toujours exécutés).
- Aucun fichier de l'utilisateur modifié (test : hash des disquettes avant / après une session qui écrit).
- `tos.img` utilisateur jamais écrasé sans `BackupAndReplace` (test).
- Un `config.toml` 1.0 est relu sans changement ni réécriture ; les consoles se comportent comme en 1.0.
- Essai utilisateur : jeu ST au clavier 60 % (mode joystick, bascule, Hôte + menu), bureau GEM à la souris capturée,
  jeu à deux disquettes, clavier virtuel pour F1–F10.
