# Version 1.0 — Gestionnaire de cores : contrat et découpage

Décisions : **ADR 0013** (précise 0005, 0006). Pile HTTP, `CancelToken`, `Progress` : **ADR 0014** /
`docs/design/v1.0-bibliotheque.md` §6.2 (conçu en parallèle). Jonction avec la bibliothèque : le **nom de base
libretro** du système (`emu_library::SystemInfo::database`) et `emu_assets::cores::choose_core`.
Signatures `emu-assets` **dans le code** (`crates/emu-assets/src/cores/**`, `jobs.rs`, corps `todo!()`) : le code fait
foi en cas d'écart. Celles d'`emu-ui` / `emu-app` sont données ici (§4), à poser par l'agent `ui`.

## 1. Périmètre

| Dans la 1.0 | Plus tard |
|---|---|
| Index nightly + `info.zip`, installation, mise à jour, suppression, retour arrière, épinglage | Canal `stable/<version>/` à hashes épinglés |
| Liste des cores installés (gérés + manuels), mises à jour disponibles (cache) | Vérification automatique au démarrage |
| Choix du core par système (`data/cores.toml` + `[cores.preferred]`) | Choix par jeu |
| État des BIOS (md5) pour chaque core | BIOS libres téléchargés (EmuTOS 2.0, AROS 3.0) |
| Écran egui « Cores », CLI `--list-cores`, `--install-core`, … | Reprise HTTP `Range` |
| Linux, Windows, macOS x86_64 (+ Docker = Linux) | aarch64 (pas de chemin buildbot retenu) |

## 2. Fonctionnement

### 2.1 Sources (ADR 0013 §1)

| Quoi | URL | Limite |
|---|---|---|
| Index | `<base>/nightly/<dir>/latest/.index-extended` | 1 Mio |
| Core | `<base>/nightly/<dir>/latest/<id>_libretro.<ext>.zip` | 128 Mio (zip), 256 Mio (extrait) |
| `.info` | `<base>/assets/frontend/info.zip` | 16 Mio ; 64 Kio par `.info`, 4096 entrées, 32 Mio au total |

`<dir>` : `linux/x86_64`, `windows/x86_64`, `apple/osx/x86_64` ; `<ext>` : `so`, `dll`, `dylib`. Ligne d'index :
`2026-11-16 e09352e9 gambatte_libretro.so.zip` (CRC32 **du `.so` extrait**). Lignes non conformes ignorées.
Client : `HttpClient` d'ADR 0014 construit avec `timeout = 600 s` (le défaut 60 s sert aux jaquettes), 3 tentatives
(réseau, délai, 5xx ; 1 s puis 2 s), annulation entre deux blocs. Pas de reprise `Range` : on recommence.

### 2.2 Installation / mise à jour (`CoreManager::install`)

1. Refus : core en usage (`InUse`), opération en cours sur ce core (`Busy`), pas de catalogue (`NoCatalog`), absent
   de l'index (`NotAvailable`).
2. Téléchargement en mémoire → `extract_core(zip, "<id>_libretro.<ext>", ExtractLimits::CORE)` → CRC32 comparé à
   l'index (`CrcMismatch`) → SHA-256.
3. `<cores>/.<fichier>.tmp-<pid>` (`create_new`), `sync_all` ; ancien fichier renommé en `.prev` (écrase l'ancien
   `.prev`) ; temporaire renommé au nom final ; fsync du dossier (Unix) ; `manifest.toml` écrit atomiquement
   (entrée courante + `previous`).
4. Échec ou annulation à n'importe quelle étape ⇒ installation précédente intacte, aucun temporaire restant.
5. `open()` répare : supprime les `.*.tmp-*`, restaure `<fichier>` depuis `.prev` s'il manque (coupure entre les
   deux renommages). Un fichier dont le SHA-256 ne correspond pas au manifeste ⇒ `Tampered` au chargement.

Manifeste (`version = 1`) :

```toml
version = 1
index_fetched_unix = 1763590000
[cores.gambatte]
file = "gambatte_libretro.so"
url = "https://buildbot.libretro.com/nightly/linux/x86_64/latest/gambatte_libretro.so.zip"
date = "2026-11-16"
crc32 = "e09352e9"
sha256 = "…"            # 64 hex
size = 4802872
installed_unix = 1763590000
pinned = false
[cores.gambatte.previous]  # mêmes champs (sans pinned) pour le .prev
```

Manifeste illisible ⇒ `CoreError::Manifest` journalisé, cores listés en `Manual` (jamais considérés comme vérifiés),
fichier non réécrit avant une action de l'utilisateur (même règle que `config.toml`, ADR 0011).

### 2.3 Lancement d'un jeu (dans `emu-ui`)

```text
système (bibliothèque) ─ database ─► choose_core(Some(db), Some(ext), installés, infos, prefs)
   Installed(id) ─► set_in_use(Some(id)) ─► verified_path(id) ─► firmware_status(id) ─► Emulator::load
   Install(id)   ─► dialogue « Installer <nom> (licence) ? » ─► écran Cores, job install ─► relance
   Unknown       ─► message « aucun core connu pour ce système »
retour à la bibliothèque ─► Emulator détruit ─► set_in_use(None)
```

BIOS : requis (`optional == false`) absent ou hash faux ⇒ dialogue « lancer quand même / annuler » listant les
fichiers et le dossier `system/` ; optionnel à hash faux ⇒ message OSD ; jamais de téléchargement. `--core <chemin>`
(0.1) contourne le gestionnaire (aucune vérification).

### 2.4 Choix des cores (ADR 0013 §7)

`crates/emu-assets/data/cores.toml` (posé) : Mega Drive / Master System / Game Gear → genesis_plus_gx, picodrive ;
SNES → snes9x, bsnes, mesen-s ; Game Boy / Color → **gambatte**, sameboy, mgba ; NES → **mesen**, nestopia, fceumm.
Présents pour les 3 plates-formes sur le buildbot au 2026-11-19 (vérifié). « Installer les cores recommandés » =
premier core de chaque système (4 cores : genesis_plus_gx, snes9x, gambatte, mesen).
Surcharge : `[cores.preferred]` dans `config.toml`, clé = id de système de la bibliothèque (`gb = "sameboy"`),
convertie en nom de base par `emu-ui`.

## 3. API `emu-assets` (posée dans le code)

```rust
// cores/id.rs, platform.rs
pub struct CoreId;  new(&str) -> Option<Self> /* [A-Za-z0-9_-]{1,64} */, from_library_file(name, ext), as_str()
pub enum Platform { LinuxX86_64, WindowsX86_64, MacosX86_64 }
    current() -> Option<Self>; buildbot_dir(); library_extension(); dir_name(); core_file_name(&CoreId) -> String
// cores/index.rs, info.rs
pub struct BuildDate { year, month, day }  parse(&str), Display, Ord
pub struct RemoteCore { id, file_name, date: BuildDate, crc32: u32 }
pub fn parse_index_extended(text: &str, platform: Platform) -> Vec<RemoteCore>;      // jamais d'échec
pub struct CoreInfo { id, display_name, core_name, version, license, extensions, databases, firmware, description }
pub struct FirmwareSpec { path /* relatif validé */, description, optional: bool, md5: Option<[u8; 16]> }
pub fn parse_info(id: CoreId, text: &str) -> Result<CoreInfo, InfoError>;            // seule la taille échoue
// cores/archive.rs
pub struct ExtractLimits { max_entry_size, max_total_size, max_entries }   // ::CORE, ::INFO_BUNDLE
pub fn extract_core(zip: &[u8], expected: &str, ExtractLimits) -> Result<Vec<u8>, ArchiveError>;
pub fn read_info_bundle(zip: &[u8], ExtractLimits) -> Result<Vec<(CoreId, String)>, ArchiveError>;
// cores/manager.rs — Send + Sync, partagé par Arc ; méthodes &self, mutex interne jamais tenu pendant un téléchargement
pub struct CoreDirs { cores, system: PathBuf }  under(data_root, Platform)
pub struct BuildbotSource; official(), custom(&str) -> Result<_, AssetError>, is_official(), index_url, core_url, info_bundle_url
pub enum Origin { Buildbot { url, date, crc32, sha256, size, installed_unix, pinned }, Manual }
pub struct InstalledCore { id, path, origin, has_previous }
pub struct RemoteCatalog { fetched_unix, cores: BTreeMap<CoreId, RemoteCore> }
pub struct CoreUpdate { id, installed: BuildDate, available: BuildDate, pinned }
impl CoreManager {
    open(CoreDirs, Platform, BuildbotSource, HttpClient) -> Result<Self, CoreError>;   // sans réseau, répare
    installed() -> Vec<InstalledCore>; info(&CoreId) -> Option<CoreInfo>; infos() -> BTreeMap<..>; catalog();
    refresh(progress, &CancelToken) -> Result<RemoteCatalog, CoreError>;               // réseau
    updates() -> Vec<CoreUpdate>;
    install(&CoreId, progress, &CancelToken) -> Result<InstalledCore, CoreError>;      // réseau ; = mise à jour
    remove(&CoreId); rollback(&CoreId); set_pinned(&CoreId, bool); set_in_use(Option<CoreId>);
    verified_path(&CoreId) -> Result<PathBuf, CoreError>; firmware_status(&CoreId) -> Vec<FirmwareStatus>;
}
// CoreError : UnsupportedPlatform, NotAvailable, NotInstalled, InUse, Busy, NoPrevious, Tampered, CrcMismatch,
//             NoCatalog, Asset(AssetError), Archive(ArchiveError), Io { path, source }, Manifest(String)
// cores/firmware.rs, select.rs
pub enum FirmwareState { Ok, Missing, WrongHash { md5 }, Unverified, Unreadable(String) }
pub fn check_firmware(system_dir: &Path, &CoreInfo, &KnownFirmware) -> Vec<FirmwareStatus>;
pub struct CorePreferences; builtin(), with_overrides(&BTreeMap<String /*database*/, String>), for_system(&str), systems()
pub enum CoreChoice { Installed(CoreId), Install(CoreId), Unknown }
pub fn choose_core(system: Option<&str>, extension: Option<&str>, installed: &[CoreId],
                   infos: &BTreeMap<CoreId, CoreInfo>, prefs: &CorePreferences) -> CoreChoice;
// jobs.rs — aussi utilisé par la file de jaquettes (ADR 0014)
pub type Notify = Arc<dyn Fn() + Send + Sync>;
pub enum JobEvent<T> { Progress(Progress), Done(T) }
impl<T: Send + 'static> Job<T> { spawn(name, Notify, FnOnce(&mut dyn FnMut(Progress), &CancelToken) -> T);
                                  poll(&mut self) -> Vec<JobEvent<T>>; cancel(&self) }  // Drop ⇒ cancel
```

**Ajouts à `http.rs` (tâche A1, qui implémente aussi la pile HTTP d'ADR 0014)** :
`HttpClient::get_with_progress(&self, url, max_bytes, progress: &mut dyn FnMut(Progress), cancel: &CancelToken)
-> Result<Vec<u8>, AssetError>` (200 seulement, sinon `AssetError::Http`) ; variante `AssetError::Cancelled` ;
`HttpConfig::same_host_redirects: bool` (défaut `true` : redirections suivies seulement vers le même schéma + hôte,
3 au plus). Dépendances ajoutées par A1 pour les cores : `zip` (workspace), `crc32fast`, `sha2`, `md-5`, `serde`,
`toml` (tous MIT/Apache) ; dev : `wiremock`, `tokio`, `tempfile`.

## 4. `emu-ui` / `emu-app` (signatures cibles, agent `ui`)

```rust
// config.rs
pub struct DataDirs { …, pub cores: PathBuf /* <data>/cores */ }
pub struct Config { …, pub cores: CoresConfig }
pub struct CoresConfig { pub buildbot_url: Option<String>, pub preferred: BTreeMap<String /*id système*/, String>,

pub enum LibraryScreen { Home, Settings, Cores }          // --screen cores (capture, sans réseau)
// src/cores_ui/{mod,rows,launch}.rs (pub(crate))
pub(crate) struct CoresUi { manager: Option<Arc<CoreManager>>, prefs: CorePreferences,
    refresh: Option<Job<Result<RemoteCatalog, CoreError>>>,
    installs: BTreeMap<CoreId, Job<Result<InstalledCore, CoreError>>>, errors: BTreeMap<CoreId, String>, … }
impl CoresUi { pub fn show(&mut self, ui: &mut egui::Ui); pub fn request_install(&mut self, id: CoreId); }
pub(crate) fn rows(installed: &[InstalledCore], catalog: Option<&RemoteCatalog>, infos: &BTreeMap<CoreId, CoreInfo>,
                   prefs: &CorePreferences, filter: RowFilter, in_use: Option<&CoreId>) -> Vec<CoreRow>; // pur, testé
pub(crate) enum LaunchCheck { Ready { path: PathBuf, warnings: Vec<FirmwareStatus> }, NeedsInstall(CoreId),
                              FirmwareMissing { path: PathBuf, missing: Vec<FirmwareStatus> }, Failed(CoreError) }
pub(crate) fn prepare_launch(manager: &CoreManager, id: &CoreId) -> LaunchCheck;  // set_in_use + verified_path + BIOS
```

**Écran « Cores »** (depuis la bibliothèque : bouton de la barre du haut ; depuis le dialogue `Install`) :
- en-tête : source (avertissement orange permanent si non officielle), date de dernière vérification, boutons
  « Vérifier les mises à jour », « Tout mettre à jour (n) », « Installer les cores recommandés » ;
- filtre « Systèmes de la 1.0 » (cores de `cores.toml`, défaut) / « Tous » (catalogue, recherche par nom) ;
- lignes : nom (`display_name`), systèmes, licence, version installée (date / « manuel » / —), disponible, actions
  Installer / Mettre à jour / Supprimer (confirmation) / Version précédente / Épingler ; barre de progression et
  « Annuler » pendant un job ; dernière erreur en rouge sur la ligne ; actions grisées pour le core en usage
  (« en cours d'utilisation ») ;
- détail (Entrée) : description, extensions, BIOS (fichier, description, optionnel, état) et chemin de `system/` ;
- clavier : flèches / Tab / Entrée / Échap (retour), pas de raccourci destructif sans confirmation ;
- `Job` + `Notify` = `ctx.request_repaint()` ; `poll()` une fois par image ; aucune attente sur le thread UI
  (seuls `installed()`, `verified_path()` — SHA-256 d'un fichier de quelques Mio — et `firmware_status()` y tournent).

**CLI** (`emu-app`, sans fenêtre, progression sur stderr, code 0 / 1, usage 2) :

```text
emu-rust [--data-dir D] --list-cores                  installés (+ mises à jour d'après le cache)
emu-rust [--data-dir D] --refresh-cores               index + info.zip
emu-rust [--data-dir D] --install-core ID|recommended  répétable ; rafraîchit d'abord si pas de catalogue ou > 1 h
emu-rust [--data-dir D] --update-cores                tous les cores non épinglés
emu-rust [--data-dir D] --remove-core ID
emu-rust [--data-dir D] --check-bios [ID]             état des BIOS (tous les cores installés sans ID)
emu-rust --core ID|CHEMIN --rom R …                   ID (CoreId valide, sans séparateur ni point) ⇒ core géré,
                                                      verified_path ; sinon chemin comme en 0.1
```

Docker : `docker compose run --rm <service> emu-rust --install-core recommended` (cores dans `/data/cores/linux-x86_64`).

## 6. Découpage

Coordonné avec `docs/design/v1.0-bibliotheque.md` §7 (L1, L2, U3, U4, Q1, Q2, V1, E1). Règle : une seule instance
d'agent écrit dans un fichier donné ; dans `emu-assets`, **A1 ajoute toutes les dépendances** (HTTP + cores), ensuite
A2 (`src/cores/**`) et L2 (`src/{covers,dat,image,secret}.rs`) ont des fichiers disjoints et L2 seul touche
`Cargo.toml` pendant cette vague.

| Tâche | Agent (modèle) | Fichiers | Dépend de |
|---|---|---|---|
| **A1** HTTP, jobs, archives | `library-assets` (**opus** : réseau, TLS, archives non fiables) | `crates/emu-assets/src/{http,error,jobs}.rs` (pile d'ADR 0014 + ajouts §3), `src/cores/archive.rs`, `Cargo.toml` (toutes les dépendances), tests unitaires | — |
| **A2** Gestionnaire | `library-assets` (**opus** : atomicité, réparation, concurrence) | `crates/emu-assets/src/cores/{id,platform,index,info,select,firmware,manager}.rs`, `data/firmware.toml` (md5 des BIOS des systèmes 1.0 depuis `libretro-database/dat/System.dat`, source en commentaire), tests unitaires | A1 |
| **U5** Config et CLI cores | `ui` (sonnet) | `crates/emu-ui/src/config.rs` (`CoresConfig`, `DataDirs::cores`), `crates/emu-ui/Cargo.toml` (`emu-assets`), `crates/emu-app/src/{cli,main}.rs` (commandes §4, `--core ID`) | U3 (mêmes fichiers : à la suite, même instance possible) ; A2 pour l'exécution réelle |
| **U6** Écran Cores et lancement | `ui` (sonnet) | `crates/emu-ui/src/cores_ui/**`, `LibraryScreen::Cores` | U5 ; **avant U4** (U4 appelle `request_install` / `prepare_launch`) |
| **P2** Plate-forme | `platform-build` (sonnet) | `docker/entrypoint.sh` (`/data/cores`), image runtime (`ca-certificates`, partagé avec L2), `README.txt` de release et `docker/README.md` (cores via l'UI / `--install-core recommended`, plus de liens manuels), `about.toml` si une licence nouvelle apparaît | — |
| **Q3** Tests cores | `qa-systems` (sonnet) | `crates/emu-assets/tests/{cores_archive,cores_manager}.rs`, `tests/support/faulty_http.rs`, `crates/emu-ui/tests/cores_launch.rs`, fixture `tests/data/cores/` (racine de capture), échantillon d'index | A1 (archives), A2 (gestionnaire), U6 (bout en bout) |
| **Q2** Vérification complète (commune) | `qa-systems` (sonnet) | + `--screen cores`, CLI `--list-cores` sur la fixture, `--ignored` réels si réseau | U4, U6, Q3 |
| **V1** Revue (commune) | `reviewer` (**opus**) | + `http.rs` (redirections, limites, annulation), `cores/archive.rs`, `manager.rs` (renommages, réparation, `set_in_use`, chemins issus du réseau via `CoreId`), `firmware.rs` (chemins des `.info`), licences `sha2` / `md-5` / `crc32fast` | Q2 |
| **E1** Essai réel (commun) | **utilisateur** | sur les 4 plates-formes : « Installer les cores recommandés », lancer un jeu par système, mettre à jour, revenir en arrière ; macOS : `.dylib` téléchargé chargé par l'app signée ad hoc (Gatekeeper) ; Windows : mise à jour refusée pendant une partie | V1 |

Vagues : 1. **A1** ‖ L1 ‖ U3 ‖ **P2** ; 2. **A2** ‖ L2 ‖ **U5** ; 3. **U6** ‖ **Q3** (archives, gestionnaire) ;
4. U4 ‖ **Q3** (bout en bout) ; 5. Q2 → V1 → E1. Chaque agent finit avec le workspace vert ; un besoin hors périmètre
(ex. U6 veut une méthode de `CoreManager`) repasse par l'`architecte`.
