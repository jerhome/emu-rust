# Version 2.1 — Mega CD « express » : contrat et découpage

Date : 2026-11-21. Demande de l'utilisateur : essayer **Dune (Mega CD)** dès le 21/11, avec ses BIOS, sur son Mac
Intel. Le Mega CD était prévu en 6.0 (ADR 0020, `docs/design/v6.0-gba-32x-megacd.md`, étude
`docs/essais-gba-32x-megacd.md` §4 bis). Ce document en **avance un sous-ensemble strict** dans la 2.1
(branche `wip-2.1`, tag visé `v2.1.0-rc.1`), avec les **mécanismes de la 2.0 seulement**, selon les contraintes de
l'harmonie (`docs/design/integration-largeur.md` §8, worktree `emu-rust-wt30`). La 6.0 **complète** ce socle (Redump,
région en base, contrôle unique par région, multi-CD, import de BIOS) sans le casser : §8.

Règle de lecture : tout ce qui n'est pas écrit ici reste celui de la 2.0. Aucune signature n'est posée dans le code
par ce document (tâche MX0, §6).

(`v1.7.4 b9c2316`), sous Xvfb, dossier système vide, disques **factices générés** (aucune donnée commerciale).

## 2. Fonctionnement

### 2.1 Lancement

```text
Game (megacd, path = .cue|.chd|.iso)
  ─ plan_launch (1.0) ─► genesis_plus_gx (ou NeedsInstall : dialogue 1.0)
  ─ megacd::region_of(path)            sonde d'en-tête ; .chd ou illisible : étiquette du nom ; sinon inconnue
  ─ megacd::bios_verdict(région, firmware_status du core)
       Ready      ─► ContentSpec::File(path)   (en place ; chemin 1.0 inchangé)
       Different  ─► dialogue : « bios_CD_E.bin présent mais différent de la référence » [Lancer quand même] [Annuler]
       Missing    ─► dialogue « BIOS Mega CD manquant » [Réessayer] [Copier le chemin] [Lancer quand même] [Annuler]
  options : défauts du core < cores.toml (genesis_plus_gx_system_bram = "per game") < config < jeu   (ordre 2.0)
  échec de retro_load_game d'un jeu megacd ─► message Mega CD (BIOS, dossier, nom), pas le conseil générique
```

### 2.2 Région

Ordre : (1) **sonde** — en-tête `SEGADISCSYSTEM` trouvé ⇒ région de l'octet 0x20B (C2) ; (2) sinon (`.chd`, fichier
illisible, en-tête absent) **étiquette du nom de fichier** : `(Europe)`, `(France)`, `(Germany)`, `(Spain)`,
`(Italy)`, `(UK)`, `(Australia)` ⇒ Europe ; `(USA)`, `(Brazil)` ⇒ USA ; `(Japan)`, `(Korea)`, `(Asia)` ⇒ Japon ;
première étiquette reconnue d'une liste `(Japan, USA)` ; (3) sinon **inconnue**. Rien n'est stocké en base : la
sonde est refaite à chaque lancement (une lecture de moins de 4 Kio).

### 2.3 Contrôle du BIOS (décision)

Contrainte d'harmonie : ni `check_required`, ni `FirmwareCheck`, ni `required_firmware` sur `wip-2.1` (noms posés
sur `wip-3.0` par X0). Le contrôle express est donc une **fonction pure d'`emu-ui`** qui relit le résultat du
contrôle 1.0 (`CoreManager::firmware_status`, qui hashe déjà les fichiers du `.info` contre `firmware.toml`) :

- région connue ⇒ **un** fichier voulu (`bios_CD_E.bin`, `bios_CD_U.bin`, `bios_CD_J.bin`) ; son état 1.0 décide :
  `Ok` / `Unverified` / `Free` ⇒ `Ready` ; `WrongHash` ⇒ `Different` (il existe plusieurs révisions du BIOS ;
  `System.dat` n'en référence qu'une par nom : on prévient, on ne bloque pas) ; `Missing` / `Unreadable` ⇒ `Missing` ;
- région inconnue ⇒ `Ready` dès qu'**un** des trois est présent (le core choisira), `Missing` (les trois noms) sinon ;
- le fichier voulu absent du `.info` installé (ne devrait pas arriver) ⇒ présence simple dans `system/` ;
- `others_present` : BIOS d'autres régions présents (« bios_CD_U.bin est présent, mais ce disque est Europe »).

Les noms `bios_CD_*` sont **retirés** de l'avertissement OSD « BIOS facultatifs absents » pour un jeu `megacd`
(traités par le dialogue) ; pour un jeu Mega Drive, comportement 1.0 inchangé. `firmware.toml` : rien à ajouter
(les trois md5 y sont depuis la 1.0, source `System.dat`).

### 2.4 Import du BIOS (minimum retenu)

Pas de bouton d'import en 2.1. Le dialogue donne : le **nom exact** attendu, la région du disque, le **chemin
absolu** du dossier `system/` (texte sélectionnable + bouton « Copier le chemin », presse-papiers d'egui, aucune
dépendance), le rappel « emu-rust ne télécharge jamais de BIOS commercial », et « Réessayer » qui refait le contrôle
sans fermer le dialogue. Le guide (§7) dit la même chose. Variantes non retenues : §9 q.1.

Texte de référence (à adapter par MU1, chaînes nettoyées par `text::clean`) :

```text
BIOS Mega CD manquant : bios_CD_E.bin (Mega CD, Europe)
« Dune » est un disque Europe. Copiez votre BIOS Mega CD dans le dossier
  /Users/<vous>/Library/Application Support/emu-rust/system
sous le nom exact bios_CD_E.bin (majuscules et minuscules comprises), puis choisissez « Réessayer ».
bios_CD_U.bin est présent, mais ce disque est Europe.          (seulement si un autre BIOS est là)
emu-rust ne télécharge jamais de BIOS commercial.
```

### 2.5 Sauvegardes

- `[cores.genesis_plus_gx] options = { genesis_plus_gx_system_bram = "per game" }` : RAM interne dans
  `<data>/saves/genesis_plus_gx/<nom du .cue sans extension>.brm`, écrite **par le core** à la fermeture du jeu
  (`retro_unload_game`). Sans effet sur Mega Drive / Master System / Game Gear. Cartouche RAM : défaut du core
  (`cart.brm` partagée, comme une vraie cartouche ; Dune utilise la RAM interne).
- Collisions : deux jeux de noms différents ont deux fichiers. Deux **homonymes** (`Dune.cue` dans deux dossiers)
  partagent `Dune.brm` tant que l'identité de jeu (I1) n'est pas livrée ; ensuite le dossier de sauvegarde du
  second devient `<saves>/genesis_plus_gx/Dune (2)/`. Limite connue de la rc.1 si I1 n'y est pas : à dire dans le
  guide (les dumps Redump portent la région dans le nom, le cas est rare).
- La RAM n'est écrite qu'à une **fermeture propre** : tâche MR0 (audit sans modification) vérifie tous les chemins
  de sortie (retour bibliothèque, fermeture de fenêtre, ⌘Q, touche hôte + Quitter, erreur). Le guide conseille en
  plus un état sauvegardé avant de quitter lors du premier essai.
- États : mécanisme 2.0 (taille lue à chaque sauvegarde) ; à constater par l'utilisateur (§7).

Nouveau fichier `crates/emu-library/src/disc.rs` (noms de la 6.0 et de la 4.0, repris tels quels) :

```rust
/// Region of a disc: BIOS choice. Generic (Mega CD now; other disc systems later).
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum DiscRegion { Europe, Usa, Japan }
impl DiscRegion { pub fn key(self) -> &'static str }            // "europe" | "usa" | "japan" (clé de variante 6.0)

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum DiscFormat { SegaCd }

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct DiscInfo { pub format: DiscFormat, pub region: Option<DiscRegion> }

/// Files named by the `FILE` lines of a `.cue`, resolved in the cue's folder, in order, without duplicates.
pub fn cue_references(cue: &Path) -> Result<Vec<PathBuf>, LibraryError>;      // signature du design 4.0 §3.4

/// Header probe of a `.cue` (its first data track), a `.iso` or a raw `.bin` track. `Ok(None)`: not a known disc
/// (or a `.chd`, never read). Reads at most 64 KiB of the cue and 0x220 bytes of the track.
pub fn disc_info(path: &Path) -> Result<Option<DiscInfo>, LibraryError>;

/// Region tag of a file name (`Dune (Europe)` ⇒ Europe). Fallback when the header cannot be read.
pub fn region_from_name(stem: &str) -> Option<DiscRegion>;

/// Extensions of disc images handed to cores in place (never hashed, never copied).
pub const DISC_EXTENSIONS: &[&str] = &["cue", "chd", "iso"];                  // nom du design 4.0
```

Réexportés par `lib.rs`. La 6.0 ajoute `disc_serial(path, format)` et `probe_bin` **à côté** (rien à renommer).

Règles de `cue_references` (entrée non fiable) : fichier régulier, **≤ 64 Kio**, UTF-8 avec repli Latin-1 (les
`.cue` anciens ne sont pas toujours en UTF-8), BOM ignoré ; lignes `FILE "nom" TYPE` et `FILE nom TYPE` (nom sans
guillemets = tout jusqu'au dernier mot), **tout type** (`BINARY`, `WAVE`, `MP3`, `OGG`, `MOTOROLA`…) ; au plus 99
références ; un nom **absolu**, contenant `..`, `/` ou `\`, ou un préfixe de lecteur est **ignoré** (jamais suivi
hors du dossier du `.cue`) ; aucune vérification d'existence (l'appelant compare aux fichiers vus). Erreur
(`LibraryError`) seulement si le `.cue` est illisible ou trop gros.

Règles de `disc_info` :
- `.iso` : `SEGADISCSYSTEM` aux octets 0..14 ⇒ décalage 0 ; `.bin` : essai à 0 puis à 0x10 (secteur brut 2352) ;
  `.cue` : premier fichier référencé (premier `FILE`), mêmes essais ; `.chd` et toute autre extension ⇒ `Ok(None)` ;
- région = octet `décalage + 0x20B` : `0x64` ⇒ `Europe`, `0xA1` ⇒ `Japan`, autre ⇒ `Usa` (C2 : même règle que le
  core) ; fichier plus court que `décalage + 0x20C` ⇒ `region: None` ;
- fichier régulier seulement (`open_regular` : jamais un FIFO), lecture bornée, aucun suivi de lien de dossier.

`crates/emu-library/src/scan.rs` — **ajouts localisés** (trois points d'appel, la logique vit dans `disc.rs` ; B3
réécrit l'attribution dans ce fichier, cf. §8) :

1. `resolve_media`, avant le regroupement : pour chaque `.cue` vu, les fichiers de `cue_references` présents dans
   `found` (comparaison par `norm_key`, donc insensible à la casse sous macOS / Windows) sont **masqués** (retirés
   de `found` et de `seen`, comme les entrées d'un `.m3u`) — `.bin`, `.iso` et toute extension du catalogue. Un
   `.cue` illisible : erreur au rapport, le `.cue` reste listé (le core décidera).
2. `analyze_file` :
   - extension dans `DISC_EXTENSIONS` ⇒ **aucun hash** (`hashes: None`, `size` = taille du fichier) ; système
     `megacd` (seul candidat). Exception : un `.cue` ou une `.iso` **hors d'un dossier `megacd`** dont
     `disc_info` répond `Ok(None)` n'est **pas listé** (`Failure::Empty`-like : ignoré sans erreur — ce n'est pas un
     disque Sega, C3) ; sous un dossier `megacd`, toujours listé. `.chd` : listé partout (contenu non lu) ;
   - `.bin` non masqué dont `disc_info` répond `SegaCd` ⇒ **pas** une ROM Mega Drive : non listé, message au
     rapport « piste de CD sans fichier .cue : ignorée » (pas de nouveau champ dans `ScanReport`).
3. `analyze_zip` : une archive dont une entrée a une extension de `DISC_EXTENSIONS` ⇒ non listée, message « Les CD
   ne se lisent pas dans un zip : décompressez-le ou convertissez-le en CHD. » (texte de la 6.0).

Inchangés : `systems.rs` (aucune clé nouvelle), `db.rs` (schéma v3, `SCHEMA_VERSION = 3`), `media.rs`, `hash.rs`.
Un jeu `megacd` a `crc32 = sha1 = None`, `identification = Unknown` (ou `Name`, §3.4), `media` vide. La détection
« inchangé » se fait sur la taille et la date du `.cue` / `.chd` / `.iso` (comportement 1.0).

- Définition de `CLAUDE.md` (fmt, clippy, tests, aucun réseau réel hors `#[ignore]`, revue).

  intacts (SHA-256).
- Mega Drive, Master System, Game Gear et Atari ST se comportent comme en 2.0 (tests existants verts, sans retouche
  autre que les listes de systèmes).
- `library.sqlite` reste en v3 ; un `config.toml` 2.0 est relu sans changement.

## 7. Guide de l'essai sur Mac (à recopier dans `docs/guide-essai-2.1.md`)

Préparation :
1. Installer `v2.1.0-rc.1` (`.app`), l'ouvrir une fois, vérifier que le core **genesis_plus_gx** est installé
   (écran Cores).
2. Copier le BIOS dans `~/Library/Application Support/emu-rust/system/` (Finder : Aller → Aller au dossier…), sous
   le nom **exact** `bios_CD_E.bin` (disque européen), `bios_CD_U.bin` (USA) ou `bios_CD_J.bin` (Japon). Dans le
   doute, copier les trois.
3. Mettre le jeu dans `<dossier des ROMs>/megacd/Dune (Europe)/` : le `.cue` **et tous ses fichiers** de pistes
   (`.bin`, `.wav`…) ensemble, noms inchangés ; ou un `.chd`. Pas de zip.
4. Bibliothèque → Analyser.

À vérifier (noter OK / KO) :

| # | Point | Attendu |
|---|---|---|
| 1 | Bibliothèque | **un seul** « Dune » dans « Mega CD / Sega CD » ; aucune piste listée ; aucun faux jeu Mega Drive ; analyse rapide |
| 2 | Sans le BIOS (le retirer une fois) | dialogue « BIOS Mega CD manquant : bios_CD_E.bin », avec le dossier ; « Réessayer » après l'avoir remis ⇒ le jeu démarre |
| 3 | Démarrage | logo du BIOS, puis le jeu ; image stable, vitesse correcte |
| 4 | **Musique et voix du CD** | présentes dès l'introduction ; pas de craquement ; pas de silence après un changement de scène |
| 5 | Touches | exactement celles de la Mega Drive (même profil `genesis_plus_gx`, réglages conservés) ; manette DS4 si branchée |
| 6 | Sauvegarde du jeu | sauvegarder dans Dune, **quitter par le menu** (retour bibliothèque), relancer ⇒ la partie est là ; fichier `~/Library/Application Support/emu-rust/saves/genesis_plus_gx/Dune (Europe).brm` présent |
| 7 | Même essai en quittant par ⌘Q, puis par la fermeture de la fenêtre | partie toujours là |
| 8 | État sauvegardé / chargé en cours de jeu | reprise au même endroit, musique comprise |
| 9 | Un jeu Mega Drive ensuite | inchangé (sauvegarde `.srm`, touches) |
| 10 | Format `.chd` (si disponible) | même résultat ; si le nom n'a pas d'étiquette de région, le BIOS présent suffit |
| 11 | Fichiers du jeu | dates de modification du `.cue` et des pistes inchangées |

Si le jeu refuse de démarrer : relever le message affiché et les lignes `Unable to open CD BIOS` du journal. Limites
connues à annoncer : pas de jeu à plusieurs CD ; pas d'import de BIOS par bouton (3.0) ; pas d'identification
automatique (jaquette trouvée seulement si le fichier porte le nom Redump) ; deux `.cue` de même nom partagent leur
sauvegarde (tant que l'identité de jeu n'est pas livrée).

## 9. Questions pour l'utilisateur (défaut appliqué sans attendre)

1. **Dépôt du BIOS** : dialogue avec le chemin du dossier `system/`, « Copier le chemin » et « Réessayer »
   (*défaut*). Variantes écartées pour la rc.1 : reconnaître par md5 un BIOS déposé sous un autre nom et proposer de
   le renommer (30 à 45 min de plus, à faire si le temps le permet) ; bouton « Ouvrir le dossier » et « Importer un
   BIOS… » (3.0).
2. **Jeux à plusieurs CD** : hors rc.1 (*défaut* ; Dune tient sur un CD). Si un jeu à plusieurs CD est voulu avant
   la 6.0 : `.m3u` reconnu seulement sous `megacd/` (contrainte d'harmonie), en 2.1.x.
3. **Format de tes disques** : `.cue` + pistes ou `.chd` ? Les deux sont pris ; avec un `.chd` sans étiquette de
   région dans le nom, le contrôle se contente d'« un BIOS présent » (*information*).
4. **RAM cartouche** (`cart.brm`) : partagée entre les jeux, comme une vraie cartouche (*défaut*, décision 6.0
   inchangée) ou une par jeu ?

## 10. Risques

| Risque | Atténuation |
|---|---|
| Aucun démarrage réel testable sans BIOS (conteneur, CI) | Accord sonde ↔ core prouvé sur disques générés et sur 240p ; test local `EMU_TEST_MEGACD_BIOS` ; essai utilisateur guidé (§7) |
| RAM `.brm` écrite seulement à la fermeture propre : perte si l'application est tuée ou plante | Audit MR0 ; points 6 et 7 du guide ; conseil « état sauvegardé » ; correction dans `emu-runtime` seulement après accord de l'harmonie |
| Son CD dégradé sur le Mac (lecture de pistes, rééchantillonnage) | Rien de nouveau dans le chemin audio (44,1 kHz, comme la Mega Drive) ; point 4 du guide ; option `genesis_plus_gx_cdda_volume` |
| BIOS de l'utilisateur d'une autre révision que `System.dat` (md5 différent) | `Different` : avertit, ne bloque pas |
| BIOS mal nommé (casse, autre nom) | Message avec le nom exact ; variante md5 de la q.1 si le temps le permet |
| `.cue` hostile ou exotique (chemins, encodage, taille) | Bornes et refus du §3.2 ; revue MV1 ; un `.cue` illisible reste lançable (le core le lit lui-même) |
| Régression du scan 2.0 (`.bin` Mega Drive, Atari ST) | Tests de non-régression nommés au §5 ; la sonde `.bin` ne lit que 0x220 octets |
| Conflit `scan.rs` avec B3 à la fusion | Logique dans `disc.rs`, trois points d'appel ; tests `megacd_scan.rs` rejoués après M1 / M2 |
| Nightly du core qui change la règle de région | Test réel « accord sonde ↔ core » : il casse et le dit ; repli : région inconnue ⇒ « un BIOS présent » |
| Homonymes partageant `<jeu>.brm` | Identité de jeu (I1) ; limite annoncée |
| Disque (95 %) et `target/` partagé en A | `cargo test -p <crate>` pendant les tâches ; `rm -rf target/debug/incremental` avant MQ2 ; 240p : n'extraire que le nécessaire (≈ 110 Mio pour les trois régions) |
