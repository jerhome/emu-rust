# 7.2 — Manette USB simple type SNES : conception et découpage

Décisions : `docs/adr/0016-manette.md`, **amendement du 2026-11-23** (statut : accepté le 2026-11-23, défauts du §questions validés par l'utilisateur). Demande de l'utilisateur
du 2026-11-23 (`docs/questions-ouvertes.md`). Pas de nouveau crate, `emu-runtime` reste tel quel : tout se passe dans
`crates/emu-ui/src/gamepad/` (module de l'ADR 0016) et dans l'écran Réglages → Manettes (`library/pad_settings.rs`).

## 1. Constat

- Aujourd'hui `GilrsSource` jette une manette en `MappingSource::None` (`warn!`, aucun événement) et ne garde que
  les boutons et axes **nommés** de gilrs (`Button::Unknown`, `Axis::Unknown` → `None`).
- Les pads SNES USB génériques posent deux problèmes : (a) absents de la base SDL embarquée sur une plateforme ;
  (b) **présents mais mal mappés** : une même puce (DragonRise 0079:0011 notamment) équipe des pads dont les boutons
  sont câblés dans un ordre différent, et la base n'a qu'une ligne par GUID. Beaucoup rapportent la croix en **axes**
  (X/Y à -1 / 0 / +1), d'autres en **hat**, rarement en boutons.
- **Non vérifié ici** : les sources de gilrs 0.11 / gilrs-core 0.6 ne sont pas dans le registre local et rien ne doit
  être téléchargé. Points qui restent à contrôler (tâche Q1) : présence de 0079:0011, 0810:e501, 081f:e401,
  12bd:d015 dans `SDL_GameControllerDB` embarquée par plateforme ; ce que remonte un pad non mappé (attendu :
  `ButtonPressed(Button::Unknown, Code)` / `AxisChanged(Axis::Unknown, v, Code)`, avec `Code::into_u32()`
  stable pour un modèle et une plateforme donnés) ; traitement du hat sur macOS (IOKit) et Windows (WGI). La
  conception ci-dessous ne dépend d'**aucun** de ces points : elle marche que la base connaisse le pad ou non.

## 2. Décision de conception (résumé, détail dans l'ADR)

1. **Mode brut** : une manette non mappée, ou dont le modèle (GUID) a un mapping appris, est lue en **mode brut** :
   la source remonte des entrées natives opaques (`RawInput::Button(code)` / `RawInput::Axis(code)`), sans les noms
   de gilrs. Un mapping appris **remplace** donc la base SDL pour ce modèle (corrige le cas « mal mappé »).
2. **Apprentissage dans l'UI** : on demande une touche à la fois, avec la possibilité de la passer ; le résultat
   est un `LearnedMap` (`PadButton` positionnel → `RawBinding`) **converti en événements normalisés** avant le reste du
   pipeline. `PadMap` par `PadStyle`, ports, raccourcis et navigation des menus ne changent pas.
3. **Mémorisé par GUID** dans `[input.gamepad.devices."<guid>"]` (table déjà existante, champs nouveaux tous
   facultatifs : rétrocompatible).
4. **Format SDL_GameControllerDB écarté** : gilrs ne donne pas les indices SDL (`b0`, `a1`, `h0.1`) mais des `Code`
   natifs ; écrire une ligne SDL obligerait à reproduire sa numérotation interne, et `Gilrs::set_mapping` (croix
   sur axes ?) n'est pas vérifiable ici. Notre couche est indépendante du backend (le repli SDL3 de l'ADR 0016 §2
   la garde telle quelle) et entièrement testable avec `ScriptedPadSource`.

## 3. Interfaces publiques (toutes dans `emu-ui`, aucune hors du crate ; aucun `unsafe`)

`gamepad/source.rs` (modifié) :

```rust
/// Native input of a pad read without gilrs' names. Codes are opaque, stable for one model on one platform.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum RawInput { Button(u32), Axis(u32) }

pub enum PadEventKind {
    /// `raw = true`: this pad's inputs arrive as `Raw` (unmapped model, or a learned map overrides the database).
    Connected { name: String, guid: String, raw: bool },
    Disconnected,
    Button { button: PadButton, pressed: bool },
    Axis { axis: PadAxis, value: f32 },
    /// Buttons: 0.0 / 1.0; axes and hats: [-1, 1].
    Raw { input: RawInput, value: f32 },
}

pub trait GamepadSource {
    fn poll_events(&mut self, out: &mut Vec<PadEvent>);
    /// Models (GUIDs) to read raw even when the database maps them. Default: ignored (scripted sources).
    fn set_raw_guids(&mut self, _guids: &[String]) {}
}
```

Contrat changé : une manette `MappingSource::None` n'est **plus ignorée** ; elle est annoncée `Connected { raw: true }`.

Correspondance des invites (positionnelle, comme l'ADR 0016) : SNES : B → `South`, A → `East`, Y → `West`,
X → `North`, L/R → `L1`/`R1`, Select, Start, croix (4 directions → `DPad*`) ; NES : B, A, Select, Start, croix ;
Mega Drive 3 boutons : A → `West`, B → `South`, C → `East`, Start, croix ; 6 boutons : + X → `L1`, Y → `North`,
Z → `R1`, Mode → `Select` (cohérent avec la colonne Mega Drive de l'ADR 0016). Ordre : croix d'abord (repérer
axes / hat), puis boutons. Les sticks analogiques ne sont pas appris en 7.2 : axes non liés ignorés.

`gamepad/input.rs` (ajouts à `GamepadInput`) :

```rust
pub enum PadStatus { Mapped, Learned, Unrecognized }
pub struct PadInfo { pub id: PadId, pub name: String, pub guid: String, pub port: Option<usize>, pub status: PadStatus }

pub enum GamepadNotice {
    Connected { name: String, port: usize },
    Disconnected { port: usize },
    /// Once per connection: unmapped model without a learned map; it holds no port.
    Unrecognized { id: PadId, name: String, guid: String },
}

impl<S: GamepadSource> GamepadInput<S> {
    pub fn set_learned_maps(&mut self, maps: BTreeMap<String, LearnedMap>); // also calls source.set_raw_guids
    pub fn pads(&self) -> Vec<PadInfo>;
    /// Learning screen: raw inputs of `pad` go to `take_raw` only (no game, hotkey, navigation).
    pub fn set_raw_capture(&mut self, pad: Option<PadId>);
    pub fn take_raw(&mut self) -> Vec<(RawInput, f32)>;
}
```

Règles : un pad `raw` sans mapping appris ne prend **pas** de port (il ne vole pas le port 0 à la DS4) ; dès qu'un
mapping est enregistré, il est attaché comme une manette ordinaire (port libre suivant). Un pad à la fois en
`raw_capture`. `set_raw_guids` sur un pad déjà branché : la source le réannonce (`Disconnected` puis
`Connected { raw }`) pour basculer proprement.

`GamepadSettings` : bouton de raccourcis **par manette** : `GamepadDeviceConfig::hotkey_button` sinon, pour un pad
appris sans `Mode`, **Select** (Select + Start = menu, Select + R = sauver, comme le repli « Share » existant) ;
sinon la valeur globale.

## 4. Écran d'apprentissage (Réglages → Manettes)

- Liste des manettes branchées (`pads()`) : nom, port, état « reconnue / apprise / non reconnue ». Boutons
  « Configurer » (toutes, y compris reconnues mais mal mappées) et « Oublier » (manettes apprises).
- Configurer : choix de la forme (SNES par défaut, NES, Mega Drive 3 / 6), puis une invite par touche
  (« Appuyez sur A (bouton de droite) »), image textuelle de la manette, « Passer », « Retour », « Annuler »
  (Échap au clavier). Une entrée déjà utilisée est refusée avec un message. Fin : résumé, « Enregistrer ».
- Pilotage au clavier et à la souris (la manette en cours d'apprentissage ne navigue pas).
- Branchement d'un pad non reconnu : notification « Manette non reconnue : <nom> — Réglages → Manettes →
  Configurer » (question 1). Débranchement pendant l'apprentissage : session annulée, message.
- La 7.3 restylera cet écran et l'intégrera à l'assistant de premier lancement : garder la logique dans
  `LearnSession`, la vue mince.

## 6. Tests headless (sans manette, `ScriptedPadSource`)

- Pad façon DragonRise : `Connected { raw: true }`, croix sur deux axes (-1 / 0 / +1, repos à ±0,004), apprentissage
  complet SNES, puis D-pad et boutons RetroPad corrects sur le core factice (empreinte d'image).
- Croix en hat (axes -1 / 0 / 1) et croix en boutons ; NES (touches passées) ; Mega Drive 6 boutons → colonne
  Mega Drive de l'ADR ; doublon refusé ; retour arrière ; déconnexion en cours d'apprentissage.
- Pad brut non appris : aucune entrée au core, pas de port, une seule notice `Unrecognized` par connexion.
- DS4 mappée + pad SNES appris + clavier : ports 0 / 1, OU avec le clavier, raccourcis PS sur la DS4 et Select
  sur le SNES.
- Pad mappé par la base mais appris : `set_raw_guids` → réannonce et mapping appris prioritaire.
- Hotplug : rebrancher un pad appris le rattache sans réapprentissage.
- Config : aller-retour TOML, config 7.1 relue sans changement, tokens invalides ignorés.
- `Translator` de `gilrs_source.rs` : tests existants adaptés (non mappé → `Connected { raw: true }` + `Raw`).

## 7. Guide d'essai utilisateur (macOS, puis Windows)

1. Brancher la manette SNES, lancer l'app. Noter la notification (reconnue ou « non reconnue »).
2. Réglages → Manettes : relever le nom affiché. Si non reconnue, ou si les boutons sont faux dans un jeu :
   « Configurer », forme SNES, suivre les invites (croix d'abord), « Enregistrer ».
3. Jeu SNES (Doctor Mario) : croix, A/B/X/Y, L/R, Start, Select. Puis un jeu NES et un jeu Mega Drive.
4. Select maintenu + Start : menu ; Select + R / Select + L : sauver / charger l'état. Select seul marche en jeu.
5. Débrancher / rebrancher en jeu : pas de plantage, la manette reprend sans réapprentissage ; relancer l'app : idem.
6. Clavier en même temps (et la DS4 si disponible : DS4 = joueur 1 si branchée d'abord).
7. En cas d'échec : joindre le journal (`RUST_LOG=emu_ui=debug`) de la séance d'apprentissage.
