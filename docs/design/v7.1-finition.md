# 7.1 — finition : icône, terminal caché, avertissement firmware (points 2, 3, 5)

Le point 4 (rangement `roms/`) est reporté. Aucune ADR : rien ne change le graphe ni les contraintes.

## Point 2 — icône

- **Source** : `assets/icon.svg`, dessiné à la main (carré arrondi sombre, couleurs du thème egui, un pictogramme simple
  de type manette/« play » ; pas de texte). Licence : celle du repo.
- **Dérivés commités** (pas d'outil requis en CI, reproductibles par `scripts/make-icons.sh`, qui utilise `resvg` +
  `iconutil` ou `png2icns`/`icnsutil`, lancé à la main si le SVG change) : `assets/icon-{16,32,48,64,128,256,512,1024}.png`,
  `assets/icon.ico` (PNG 16-256), `assets/icon.icns`. Les binaires sont petits (< 300 Ko au total).
- **Fenêtre** : le jeu et les fenêtres d'`emu-ui` passent par `winit::WindowAttributes` (pas eframe) : `with_window_icon(Some(Icon::from_rgba(..)))`
  avec `assets/icon-256.png`, embarqué par `include_bytes!` et décodé par le crate `png` (déjà présent ? sinon `png`, MIT/Apache,
  léger ; à défaut stocker un `icon-256.rgba` brut). Un helper unique `emu_ui::window_icon() -> Option<winit::window::Icon>`
  appliqué aux 3 sites (`app.rs:2352`, `library/host.rs:362`, `cores_ui/capture.rs:108`). macOS ignore l'icône de fenêtre (c'est celle du bundle).
- **Windows** : `.ico` embarqué dans l'exe via `winresource` (build-dep de `emu-app`, `build.rs` sous `cfg(windows)`, MIT).
- **macOS** : `assets/icon.icns` copié dans `emu-rust.app/Contents/Resources/`, `CFBundleIconFile` = `icon` dans `packaging/macos/Info.plist`.
- **Linux** : `icon-256.png`/`.svg` ajoutés à l'archive + un `emu-rust.desktop` (`Icon=emu-rust`) ; dans Docker, rien.

## Point 3 — terminal caché, journal dans l'UI

Contrainte `unsafe` interdit : pas d'`AllocConsole`. Décision la plus simple et robuste :

- **Windows** : `emu-app/src/main.rs` : `#![cfg_attr(all(windows, not(feature = "console")), windows_subsystem = "windows")]`.
  Deux exécutables livrés par `package-windows` (ou ZIP existant) : `emu-rust.exe` (sans console, par défaut) et
  `emu-rust-console.exe` (même code, `--features console`, via 2e `[[bin]]` sur le même `main.rs`). Le CLI (`cores …`) est à utiliser avec la version console.
- **Réglage** `[app] show_terminal = false` (nouvelle table `AppConfig` dans `emu-ui::config`, non écrite si défaut) :
  à l'ouverture, si `true` sous Windows et `emu-rust-console.exe` est à côté, `emu-app` se relance dessus
  (`std::process::Command`, une seule fois : variable d'env `EMU_RELAUNCHED=1`) puis quitte. Sous macOS/Linux, `true` active la couche stderr
  du log ; `false` ne l'active que si stderr est un terminal (`IsTerminal`) : lancer depuis un terminal garde le comportement actuel.
  Libellé UI : « Afficher le terminal (après redémarrage) ».
- **Journal dans l'UI** : `emu-ui` expose `LogBuffer` (anneau de 500 lignes, `Arc<Mutex<VecDeque<LogLine>>>`) et un
  `tracing_subscriber::Layer` (`LogBuffer::layer()`), que `emu-app::init_tracing` empile avec la couche stderr conditionnelle
  et une couche **fichier** `<racine>/logs/emu-rust.log` (rotation simple : renommer en `.1` au-delà de 1 Mo, mode 600).
  UI : volet « Journal » (Réglages), niveaux warn/error en surbrillance, bouton « Copier ». Les erreurs importantes
  (core introuvable, BIOS manquant, échec de téléchargement) déjà en `warn!/error!` y apparaissent ; un toast pour `error!`.
- API publique : `emu_ui::LogBuffer { new(cap), layer(), snapshot() -> Vec<LogLine> }`, `LogLine { level, target, message }`,
  `Options.log: Option<LogBuffer>` (ou paramètre de `run`), `AppConfig { show_terminal: bool }`.

## Point 5 — cores améliorés par un fichier d'origine

- **Données** : `emu-assets::cores::info::FirmwareSpec` (parse des `.info`, avec champ « optionnel ») et `data/free_bios.toml`
  couvrent déjà le cas ; ajouter dans `emu-assets` une table embarquée `data/firmware_hints.toml` : `core_id → { system,
  nom lisible, fichiers attendus, obligatoire/amélioration, texte court }` (PS1 `scph*`, 3DO `panafz10`, Amiga Kickstart, GBA `gba_bios.bin`,
  Mega CD `bios_CD_*`…). Aucun hash ni URL de téléchargement.
- **API** (`emu-assets`) : `pub fn firmware_advice(core_id: &str, system_dir: &Path) -> Option<FirmwareAdvice>` ;
  `FirmwareAdvice { core_id, files: Vec<AdviceFile{name, required, present}>, note: String }` — pur, sans réseau.
- **UI** : bandeau jaune sur la fiche du jeu / avant lancement si `present == false` : « Ce core fonctionne mieux (ou exige)
  avec le fichier X, que vous devez fournir vous-même ; emu-rust ne le télécharge pas. » + bouton « Importer… » qui
  réutilise `emu-ui::bios_import` (ADR 0017 §3). Jamais bloquant si `required == false`. Le texte rappelle la licence.

## Découpage

| Agent | Tâche | Fichiers |
|---|---|---|
| `library-assets` | `firmware_hints.toml` + `firmware_advice` + tests | `crates/emu-assets/{data,src}` |
| `ui` (A) | `AppConfig`, `LogBuffer`+Layer, volet Journal, réglage terminal, `window_icon()` | `crates/emu-ui` |
| `ui` (B, après A et `library-assets`) | bandeau firmware ; `emu-app` : init_tracing (fichier + stderr conditionnel), relance console, `windows_subsystem`, 2e bin, `build.rs` winresource | `crates/emu-ui`, `crates/emu-app` |
| `platform-build` | `assets/icon.svg` + dérivés + `scripts/make-icons.sh`, Info.plist, `package-macos.sh`, `.desktop`, ZIP Windows 2 exe, release.yml | `assets/`, `scripts/`, `packaging/`, `.github/` |
| `qa-systems` | vérification complète ; test `LogBuffer` ; capture Xvfb du volet Journal et du bandeau | `crates/*/tests` |
| `reviewer` | relance de processus (Windows), fichier de log (perms, pas de secrets loggés) | lecture seule |

Ordre : `library-assets`, `ui` A et `platform-build` en parallèle (l'icône PNG doit exister avant `ui` A pour `include_bytes!` :
`platform-build` livre d'abord `assets/icon-256.png`, ou `ui` A utilise un PNG provisoire) → `ui` B → `qa-systems` → `reviewer`.

## Points ouverts

- Dessin exact de l'icône (à valider visuellement par l'utilisateur après la 1re version).
- Relance console sous Windows : alternative plus simple = ne livrer que la version console en option ; à confirmer à l'essai sur Windows.
- Pas de test possible ici sur macOS/Windows : le `.icns` et la relance se valident chez l'utilisateur.
