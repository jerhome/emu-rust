## Faits relevés (reviewer, 2026-11-27) et choix techniques

`sevenz-rust2` 0.27.0 (2026-11-26), Apache-2.0, sans code C ; dépendances retenues : `lzma-rust2` (Apache-2.0),
`ppmd-rust` (CC0-1.0 OR MIT-0, sans `unsafe`), `flate2` + `zlib-rs` (déjà présents), `crc32fast`. MSRV 1.93,
compatible. Avis : **go sous conditions**. Choix techniques tranchés (réversibles) :

- `default-features = false, features = ["ppmd", "deflate"]` : chiffrement exclu ; version épinglée (`=0.27.0`),
  montée de version seulement par un lot dédié.
- `read_with_memory_limit` avec la borne de dictionnaire de 64 Mo (design §2).
- Test : une archive chiffrée est refusée avec un message clair (sans la feature `aes256`).
- `lzma-rust2` active de l'`unsafe` (assembleur dans le décodeur) qu'on ne peut pas couper : fuzz minimal du
  listing et de la décompression (archives corrompues générées, courte campagne par `qa-systems`), relecture
  `reviewer` de la dépendance.

## Écarts à reporter dans la conception (pour to-spec)

- Design §9.4 : minimum de `archive_cache_mb` = **1000** (décision du 2026-11-26), pas 500.
- Design §4 et §9.3, ADR 0027 : le CD archivé passe en 8.1.1 (T1-4).
- Recalage sur la 8.0 : catalogue dynamique (`Catalog`, instantané au départ du scan et du plan de rangement),
  marque de scan en base (schéma v8, sans migration de plus pour la 8.1), `ARCHIVE_EXTENSIONS` contient déjà `7z`
  (design 8.0 §0.1), systèmes personnalisés (T1-2), ADR 0023 amendée (journal v2 : un `.7z` reste une unité
  « fichier seul »).
- Numérotation : ADR 0027 et le design parlent encore de « 7.7 ».
