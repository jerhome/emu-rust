# ADR 0021 — Version 7.0 : PlayStation et 3DO (rendu logiciel)

Statut : **accepté** (2026-11-21, architecte ; feu vert de l'utilisateur pour la 7.0 donné le 2026-11-21). Les choix
laissés à l'utilisateur ont un défaut appliqué sans attendre (`docs/design/v7.0-ps1-3do.md` §9, lignes en fin de
`docs/questions-ouvertes.md`). Le numéro 0021, « abandonné » dans les documents de la 6.0 tant que la 7.0 était
gelée, est repris ici. Précise ADR 0005 (BIOS commerciaux jamais téléchargés ; règle « Builtin »), 0011
(sauvegardes), 0013 (choix des cores), 0014 (DAT), 0016 (manette) ; réutilise ADR 0020 (CD, région, Redump, contrôle
de firmware par région) et ADR 0022 (rechargement d'un core). Conception : `docs/design/v7.0-ps1-3do.md`.
**Graphe des crates inchangé.** Rendu matériel (`SET_HW_RENDER`) toujours refusé : hors périmètre.

## Contexte

Décisions de l'utilisateur (2026-11-20 / 21) : 7.0 = PlayStation + 3DO en rendu logiciel ; PlayStation =
**pcsx_rearmed par défaut, swanstation et beetle_psx sélectionnables facilement** ; 3DO = opera ; BIOS fournis par
l'utilisateur et vérifiés par hash, jamais téléchargés ; jeux d'essai : GTA (PS1), Road Rash (3DO).

Faits vérifiés le 2026-11-21 (réseau : `.info` de libretro-core-info, `.index-extended` du buildbot, dépôts des
cores, `metadat/redump/` de libretro-database ; **exécution** des quatre cores nightly `linux/x86_64` dans un
mini-hôte C hors dépôt, dossier système **vide**, contenus libres seulement) :

## Décision

1. **Cores.** `Sony - PlayStation` : `pcsx_rearmed` (défaut), `swanstation`, `mednafen_psx`, dans cet ordre, choisis
   par le sélecteur « Core utilisé par système » de la 3.0 (`[cores.preferred]`). `The 3DO Company - 3DO` : `opera`.
   `mednafen_psx_hw`, `duckstation` et `pcsx1` ne sont pas proposés. swanstation est livré **en rendu logiciel
   seulement** : défaut frontend `swanstation_GPU_Renderer = "Software"` (ni mise à l'échelle interne ni PGXP).
2. **BIOS : jamais téléchargés, jamais bloquants.** Les quatre cores démarrent avec un remplaçant intégré (HLE,
   OpenBIOS, Opera Boot : règle « Builtin » d'ADR 0005, rien n'est extrait ni redistribué par emu-rust). Le BIOS de
   l'utilisateur reste **préféré** dès qu'il est présent, et vérifié par md5 :
   - PlayStation : table `required_firmware` par région (`japan` → `scph5500.bin`, `usa` → `scph5501.bin`,
     `europe` → `scph5502.bin`) pour les trois cores, avec `fallback = "core"` ⇒ état `CoreFallback` : lancement et
     **avertissement une fois par jeu** (« BIOS d'origine absent : BIOS de remplacement du core, compatibilité
     réduite — Importer un BIOS… »). Mauvais md5 ⇒ dialogue non bloquant, comme en 6.0.
   - 3DO : `opera_bios = "panafz10.bin"` par défaut frontend, `fallback = { opera_bios = opera-boot-internal }` si
     le fichier manque (mécanisme AROS de la 3.0), même avertissement unique.
   La feuille de route disait « requis » : ils deviennent **recommandés**. `firmware.toml` gagne les sections
   PlayStation et 3DO (md5 ci-dessus, tailles de `System.dat`).
3. **`FirmwareFallback` devient une énumération** (`emu-assets`) : `Option { option, value }` (TOML inchangé) ou
   `Core` (`fallback = "core"` : le core se replie seul, aucune option à poser). Seule évolution du contrôle de
   firmware unique ; `check_required`, `FirmwareState` et `firmware_gate` sont inchangés.
4. **CD.** `DiscFormat` gagne `Psx` et `Opera` ; `disc_info`, `disc_serial`, `probe_bin` les reconnaissent par des
   lectures bornées. Région PlayStation : secteur de licence, sinon préfixe de la série (`SLES` / `SLUS` / `SLPS`…),
   sinon DAT, sinon nom ; 3DO : sans verrou de région (nom ou DAT, pour l'affichage). Identification : PlayStation
   par **série** (jamais de CRC d'une piste de plusieurs centaines de Mo), 3DO par taille + CRC de la piste 01
   (borne portée à 800 Mio pour ce format, seulement si la taille figure au DAT). Contenu des `.chd` et des `.pbp`
   toujours non lu (nom seulement).
5. **Systèmes** `psx` et `3do` (`disc = true`, `dat = "redump"`), `cue` / `chd` / `iso` en `folder_extensions`
   (règle 3.0 §3.5.2, sondes d'en-tête avant « non classé ») ; `pbp` propre à `psx`. Un `.chd` hors dossier dont le
   nom figure dans **plusieurs** DAT Redump reste non classé. Une piste `.bin` PlayStation ou 3DO sans `.cue` est
   un jeu (les cores la lisent), à la différence du Mega CD. `.exe` (PS-EXE) hors bibliothèque (CLI seulement).
6. **Multi-CD.** PlayStation : mécanisme 6.0 inchangé (`(Disc N)`, `.m3u` généré de chemins absolus, interface
   disque, menu « CD »). 3DO : opera n'a ni interface disque ni `.m3u` ⇒ `group_discs = false` sur le système : un
   jeu par disque.
7. **Sauvegardes.** Carte mémoire 1 = `SAVE_RAM` ⇒ `.srm` **par jeu** écrit par le frontend (identité de jeu 2.1,
   commun aux disques d'un même jeu) ; emplacement 2 désactivé par défaut frontend (réglable). Les trois cores
   PlayStation déclarent `save_family = "psx-memcard"` : au premier lancement d'un jeu avec un core sans `.srm`, la
   carte d'un autre core de la famille est **copiée** (jamais écrasée, jamais fusionnée). 3DO : NVRAM par jeu écrite
   par le core ; `game_saves` accepte un **sous-dossier fixe** (`opera/per_game/{game}.*.srm`).
8. **Manette.** Nouvelle surface sûre dans `emu-libretro` : types de périphériques déclarés par le core
   (`SET_CONTROLLER_INFO`) et `set_controller_device(port, id)`, limité aux identifiants déclarés. `cores.toml`
   `pad_devices` donne, par core, l'identifiant de chaque mode (`digital`, `dualshock`). Mode par défaut
   **numérique** (le stick gauche vaut la croix, comme pour les autres consoles : GTA est numérique) ; **DualShock
   analogique** réglable globalement et par jeu, appliqué à chaud. Nouveaux `PadStyle::PlayStation` et
   `PadStyle::ThreeDo` (clavier et manette). Vibration : hors 7.0 (`GET_RUMBLE_INTERFACE` refusé sans bruit).
9. **Schéma : aucune migration.** `game.region`, `dat_entry.serial` / `region` (v6) suffisent.
10. **Rechargement (ADR 0022).** Les quatre cores passent « deux chargements successifs » ; ils rejoignent le test
    générique. Aucune clé nouvelle.

## Conséquences

- La 7.0 se teste **sans aucun BIOS commercial**, démarrage compris pour la PlayStation (premier système CD dans ce
  cas) ; pour la 3DO le démarrage d'un jeu reste à l'essai de l'utilisateur (aucun disque libre).
- `unsafe` nouveau dans `emu-libretro` (lecture du tableau `retro_controller_info`) ⇒ revue `reviewer`.
- Aucun code réseau nouveau : les DAT Redump passent par `DAT_REDUMP_BASE_URL` (6.0), les cores par le buildbot.
- La valeur de `FirmwareFallback` change de forme : les `match` d'`emu-ui` (`fallback_option`) sont adaptés par la
  tâche de contrat (PX0).
- Notices à ajouter (README de release, écran Cores) : opera (non commercial), swanstation (GPLv3), OpenBIOS, Opera
  Boot (GPL-2.0), HLE de pcsx_rearmed ; rien d'embarqué de plus dans les paquets.
- Limites assumées : swanstation sans rendu matériel ; `.chd` / `.pbp` identifiés par leur nom ; 3DO à plusieurs CD
  non regroupés ; pas de vibration ; cartes mémoire copiées, non partagées, entre cores.
- Si Opera Boot ou un BIOS de remplacement casse un jeu, l'utilisateur importe son BIOS : aucun changement de code.
